# NationalTeam业务契约版本与兼容规则

对应ARCH-206（另一计划P1-06），实现于 `EtfBusinessProtocol`、`EtfRequest`、`EtfQueryPage`、`EvidenceChunk`。适用范围为可信第一方ETF/股票/预警插件，不把插件业务DTO放入公共Worker宿主契约。

## 独立版本

| 边界 | 当前版本 | 所有者与拒绝规则 |
| --- | --- | --- |
| 插件加载契约 | `hostContract: 2.0` | 桌面/后台清单验证器；不兼容包不加载 |
| Host IPC | `WorkerProtocol.Version=2` | 身份、帧、请求ID、命令与权限；不匹配返回ProtocolMismatch |
| 插件业务 | `ContractVersion=1` | NationalTeam Core维护请求/分页/导出DTO和编解码器；未知版本明确拒绝 |
| 市场数据库 | `PRAGMA user_version=2` | Jobs仓储负责；仅新库0或已知2允许打开，其他版本拒绝；不随业务DTO升级 |

数值相同不表示可以相互替代。本次不修改市场Schema或任何已提交事实。

## 兼容窗口

- 现有业务格式定义为V1。**缺失ContractVersion永远只表示历史V1**；显式null、非整数或未知值不接受。将来升级当前版本时不能把缺失版本重解释成新版。
- 同一V1内新增可选字段允许忽略；改变已有字段意义、必填字段或操作语义应另立版本与适配器。根和嵌套对象的重复属性拒绝，避免版本/操作覆盖。
- Operation是必填非空字符串，最长64字符；请求最多4096个UTF-8字节、JSON深度32。不是4096个中文字符。宿主还保留自身帧和查询额度。
- 新桌面读取已发布旧服务时，旧分页/导出响应缺版本按V1处理；V1状态查询保留字符串响应。分页Items内部业务数据仍使用该页声明的契约，不重新发明第二份版本。
- 旧桌面请求新服务时，缺版本按V1处理；新增响应版本字段可被旧客户端忽略。新桌面写入持久命令携带V1；已有队列里的无版本命令仍按V1恢复。
- 旧服务自身没有未知业务版本拒绝能力，因此本兼容承诺只覆盖V1客户端。未来新版客户端不得对旧服务静默改发V1或将无版本响应当作新版。未知版本不能通过自动降级重试绕过。
- 包内Core/Jobs/UI程序集必须配套构建发布。线协议兼容不代表允许混用新旧DLL；保持完整包哈希和既有升级Journal。

## 错误与副作用

查询在执行用例前解析请求。无法解析、重复字段、超限或未知版本返回插件业务错误对象：`ContractError`与`SupportedContractVersion`，Host IPC仍可用；桌面先检查该错误及版本，不能把它反序列化为空列表冒充成功。

写任务在执行业务前同样解析，契约错误返回`Rejected`，检查点为`contract=<错误码>`。未知operation继续由现有读白名单和写Job/operation匹配拒绝。预期拒绝不发起网络，不调用业务写入口。宿主仍可记录命令受理及拒绝审计，此审计不属于金融事实写入。

分页/导出响应缺少必填项、版本不支持或重复属性时，桌面清晰报告契约失败；不返回已累积半页结果。响应额外可选字段保持同版本兼容。

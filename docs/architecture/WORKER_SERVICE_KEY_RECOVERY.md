# ServiceKey 跨机器灾备：安全审查与分阶段实施

2026-10-23；基线 main `cbb3d8ba`（已合并 PR #16）。P0-02 / ARCH-005 **保持 Open**。

## 反方审查

`ServiceKey.Open` 使用机器 DPAPI 并核对运行账户 SID；`StorageSecurity` 另行限制 ACL、
所有者与链接。LocalService 账户 SID 和 NT SERVICE/CRSBackgroundService 服务 SID 是两个
不同约束。管理员读取旧密钥时移除 SID 检查、增加通用 LocalService ACE 或复制 DPAPI 密文，
都不能构成跨机恢复。错误凭据/密钥损坏/身份变化必须关闭访问，禁止生成替代密钥。

PR #16 证明原机停机快照与活动文件一致，未证明跨机可解密。无认证哈希清单不是可信来源：
攻击者可同时替换清单和密钥包。清单摘要必须进入 AEAD 认证；恢复凭据独立于备份保管。
本方案不能防御已控制 Worker/管理员的攻击者；同进程插件仍在可信计算基内。

## 阶段 1：内部封装组件（已合并 PR #17）

`ServiceKeyRecoveryEnvelope` 仅在内存封装/解封，不读取 ServiceKey、文件或 SCM，不提供
IPC/CLI/安装入口，不授予恢复权限。现有 SID、ACL、启动路径保持原行为。
组件为 internal，仅向既有测试程序集开放；这不是 OS 权限边界。

- 凭据须为独立 CSPRNG 生成的 32 字节随机秘密，**不是口令**。长度不能证明熵；生成、
  确认、交付和保管由后续授权流程负责，不允许将用户输入的 32 字节口令直接代入。
- HKDF-SHA256：独立 Worker recovery 域及每包随机盐，派生 AES-256-GCM KEK；每包新 nonce。
  不复用个人税务保险库恢复槽、机器 DPAPI 熵或插件密钥。
- 固定 152 字节：magic 8、LE uint32 版本 1、.NET Guid 默认字节序 16、清单 SHA256 32、
  盐 32、nonce 12、密文 32、tag 16。前 104 字节全部是 AAD。
  尾随字节、截断、未知版本和不符长度在 KDF 前拒绝；没有可控迭代次数或不定长字段。
- 包 ID 和清单摘要绑定调用者持有的预期上下文；即使预期上下文也被改成伪造值，仍需通过
  GCM 认证。组件不解析清单，也不证明清单代表完整兼容的数据集。
- 解密返回可释放 RecoveredKey，临时明文/KEK 在成功和异常时清零。调用者必须释放返回值、
  清零输入秘密与 Copy 副本。托管运行时不承诺所有瞬态副本或转储彻底擦除。
- 认证错误使用固定消息。秘密不得进入 argv、环境变量、日志、配置、明文临时文件或 CI artifact。

Windows 合成测试覆盖正确往返、随机化、逐字节篡改、伪造匹配上下文、所有截断长度、
尾随/超大输入、错误凭据/长度/ID/摘要与释放语义。额外用测试自建 GUID 目录验证既有
ServiceKey 的 SID 错配、损坏 DPAPI、坏 JSON、数据库缺钥拒绝且原文件不改写。
它们不证明真实跨机器恢复，生产恢复保持未接入。

## 阶段 2：源机显式授权导出（2a 内部组件，2b 生产接入未实现）

2a 新增内部一次性导出会话和 OpenExisting 只读入口，覆盖身份/快照/期限绑定、确认、审计故障、
并发重放及失败清理，见[安全审查与验证](../validation/WORKER_RECOVERY_EXPORT_AUTHORIZATION_20261023.md)。
没有生产 IPC/CLI 接线；持久重放索引、全局容量、实际凭据交付、排空/租约及完整加密打包仍属 2b。

由现有认证管道确认的管理员发起专用操作，在服务身份内读取原密钥，不能绕过 SID。
授权绑定一次性 request ID、包 ID、操作类型、期限与恢复点；拒绝重放、非管理员、普通
Query、后台自动导出和未确认导出。成功必须有审计落盘；失败/断连结果未知不能自动重发。

停止接收工作、有界排空、独占维护/数据租约；先解决运行中 Worker owner.lock 的维护交接，
再固定快照，逐文件核验，形成有界清单。覆盖全部库/WAL/SHM、原件/审核、配置、Schema、
程序/插件发行指纹及包 ID；不能复制仍在写入的树。恢复凭据安全一次性交付并显式确认保管，
与备份分别存放。输出不得向通用 LocalService/Users 放宽 ACL。
业务备份还需经评审的认证加密与有界打包协议；本组件只加密主密钥，不加密业务文件。

## 阶段 3：目标机只读暂存（后续独立 PR，未实现）

显式授权恢复到全新受限目录；非空、越界、ADS、重复路径、链接和过大输入拒绝。
认证封装与清单，核验文件集合/哈希、受信发行和全部 Schema/插件兼容。由目标实际服务
身份按本机 DPAPI 重封装，写入实际账户 SID；保留服务 SID ACL 检查，不能伪填 SID。
持独占租约只读打开全部 SQLCipher 库，核验完整性、跨库引用和原件；任何错误只保留受限
故障暂存及不含秘密的状态，不覆盖活动密钥/数据，不启动调度，不回退为新库。

## 阶段 4：显式激活与干净机器验收（后续独立 PR，未实现）

独立持久事务关联授权、恢复点、目标发行及只读验证结果；全部通过且显式确认后才切换启动。
阶段持久化前后强杀、磁盘满、错误凭据、缺文件、未知 Schema、非空目标和 ACL/SID 漂移
均需负例。以两台不同 DPAPI 状态的干净 Windows 和真实 LocalService/服务 SID，恢复
合成多库、原件及审核事实，确认事实一致后再验调度。单机往返和 CI 绿灯不能关闭此阶段。

## 后续优先级评估

先推进 P0 授权与恢复事务，继续阻断生产灾备就绪声明。PluginRunner 下一步独立 PR：
合成插件 Job Object 监督器、PID/握手绑定、有界取消/进程树强杀、结果未知不重放，然后
迁移 Heartbeat。stdio 原型不能生产替换；独立身份、ACL 和网络负例通过前不宣称安全沙箱。

国家队先建不访问交易所的规模基准：1k/10k/50k 合成原件，控制引用分布、冷/热文件缓存、
并发查询与后台巡检，测 Overview/History/Coverage 的 P50/P95/P99、取消时延、内存和哈希 I/O。
延续 PR #15 的业务引用范围核验与全量后台巡检：引用原件损坏仍拒绝，孤立抓取不阻断无关查询。
缺失不能用零或陈旧回退。先保存测量，再决定索引、分页或有界快照，不预设绕过 SHA256。
合成规模证明趋势和拒绝语义；真实大样本验收仍需另行授权的只读数据与可复核测量。

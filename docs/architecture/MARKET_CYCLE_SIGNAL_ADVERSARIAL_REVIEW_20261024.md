# 市场周期研究方案反方审查（2026-10-24）

- 审查对象：docs/implementation/MARKET_CYCLE_SIGNAL_DESIGN.md 初稿
- 审查立场：以最可能导致错误投资结论、回测失真、证据误归因和维护困难的角度审查
- 结论：方向可行，但初稿不应直接进入正式信号接线。先修订以下规则，再实现纯领域原型。

## 审查发现

### R1｜P0：点时回放不能只依赖当前“最新”修订

**风险：** 如果数据库只提供每个交易日当前最终值，回测会把后来更正的数据当作当时已知值。只过滤交易日期无法防止未来数据泄漏。

**整改：** 每个来源修订必须保留首次发现、实际获取、来源发布时间（若可得）、原件哈希和审核状态。每个历史评估时点只允许使用当时可见的修订。若同一日期在截止时点有多个可见修订且不能唯一确定有效版本，必须返回数据不足/冲突，不得按当前时间或数据库顺序随意选一条。后续更正不得回写旧回测快照。

### R2｜P1：简单累加条件会把相关指标重复计权

**风险：** “接近阶段高点”“上涨动量”“站上均线比例下降”可能描述同一趋势或同一市场广度变化。若每条条件都加一分，同一类信息可重复触发风险升高，产生伪精确。

**整改：** 以相对独立的证据族计分：
- 顶部候选：价格位置族、市场广度族、量价/流动性族，每族最多计 1 分。
- 底部候选：阶段回撤族、市场广度压力族、恐慌量价族，每族最多计 1 分。
- 底部后的修复确认独立展示，不加到底部候选分数中，也不自动称为“底部确认”。
- 输出条件族及触发理由，不输出未经校准的概率。

### R3｜P1：市场总成交额和指数价格属于不同数据粒度

**风险：** 若把全市场成交额复制进每只指数行情记录，再跨指数汇总，可能重复计权或误把市场成交额解释为某个指数的成交额。

**整改：** 逻辑上分离指数价格事实与市场广度/市场成交事实。第一阶段可使用一个不可变研究快照承载所需字段，但来源、原件 ID、统计范围和粒度必须独立记录；后续持久化必须使用独立事实表/引用，不允许按指数行数累加市场总成交额。

### R4｜P0：历史市场广度存在存活偏差

**风险：** 使用当前仍上市证券计算历史涨跌家数、均线比例或创新高/创新低，会漏掉退市、被吸收合并或历史期间不存在的证券，夸大历史市场质量。

**整改：** 历史广度必须绑定当时有效的证券宇宙快照、上市/退市区间、证券类别和排除规则。无法重建历史证券宇宙时，相关历史日期只能标记探索性数据，不得用于严格样本外验证或宣称模型已通过回测。

### R5｜P1：候选阈值缺少固定的实验协议

**风险：** “显著回撤”“极弱广度”“显著放量”等描述若不落实为有版本的参数，研究人员可能在看过结果后反复调参，形成隐性过拟合。

**整改：** 参数集中放入版本化规则对象。每次回测冻结规则、输入范围、样本切分和标签定义；先报告固定候选参数，再另行报告敏感性分析，不允许将调参区间当作样本外结果。

### R6｜P1：数据可用性不等于来源稳定、可持续或可合法再利用

**风险：** 交易所页面当前可访问，不保证接口稳定、历史可下载、字段含义长期不变或允许所有用途。

**整改：** 每种来源先独立完成请求/字段/单位/日期/分页/缺失/修订/访问频率与使用条款核验。没有经过黄金样本验证的来源不进入正式数据就绪判定。禁止以绕过 403/429、改变身份或未授权镜像来保持采集。

### R7｜P1：直接持仓和 ETF 间接暴露的可识别范围有限

**风险：** 即使某机构持有 ETF，也不一定拥有对应 ETF 的全部成分股暴露；指数权重、基金实际组合、现金、衍生品、证券借贷和披露时点会造成误差。若机构 ETF 持有证据缺失，不能根据 ETF 总份额推算机构持仓。

**整改：** 将“已披露直接持股”“已确认 ETF 持有”“基于指数权重的间接暴露估算”“仅 ETF 覆盖方向”分开呈现。间接暴露只能作为带误差说明的估算，不能冒充基金实际持仓；缺少具名 ETF 持有证据时不生成机构穿透暴露。

### R8｜P1：顶部和底部应采用不同标签与指标，不可镜像反转

**风险：** 价格在阶段高位与深度回撤是不同状态；顶部风险信号不触发，不代表底部机会；超卖也不代表熊市结束。

**整改：** 顶部风险和底部候选分别评分、分别回测。底部修复确认单独定义，必须有后续价格与广度证据。界面不得将“底部候选”显示成“底部确认”。

### R9｜P1：覆盖率、模型可计算性、预测有效性和正式发布必须是不同门槛

**风险：** 250 日价格完整只能说明有足够历史窗口，不能证明广度和成交额完整；单元测试通过也不能证明官方来源数据可靠；回测结果好也不等于生产作业已经部署。

**整改：** 分别记录来源验收、输入完整性、研究计算可复现、点时回测、正式发行/通知授权。任何关键输入缺失时状态为 InsufficientData，不可用其他指标的分数抵消。

### R10｜P2：信号解除和通知去重需要状态机

**风险：** 每次计算都发送相同告警会形成通知疲劳；短期跨阈值会重复打开/关闭事件。简单的“条件不再满足”也不能证明风险消失。

**整改：** 后续阶段设计独立事件状态机：新事件、升级、持续、条件解除、数据质量阻断、恢复。用规则版本、评估日、条件族与输入指纹去重；解除说明只代表当前规则不再触发。

### R11｜P1：同一根放量下跌可能同时触发顶部与底部强信号

**风险：** 如果顶部量价族只要求成交额放大且收益不为正，极端放量下跌会同时满足顶部量价与底部恐慌条件。再叠加同一市场广度恶化，模型可能在同一天同时给出顶部风险升高和底部候选，且用户难以理解这两个方向相反的标签。

**整改：** 将顶部量价族限定为成交额放大、当日不涨但跌幅尚未达到底部恐慌阈值；底部恐慌族单独使用放量且跌幅达到阈值的条件。仍允许顶部与底部状态因不同证据族而在特殊行情下并存，但必须由独立条件触发、展示理由并在历史回测中验证，不能由同一个量价事实重复加分。

### R12｜P1：证据族分数不能取代市场区域门槛

**风险：** 若顶部只按广度与量价计分，深跌区也可能被误标为“顶部风险升高”；若底部只按广度和放量下跌计分，指数尚未出现显著回撤时也可能被标为“底部候选”。

**整改：** 顶部“风险升高”必须处于 250 日高位附近并至少有一个独立佐证；底部“候选”必须先满足至少 20% 的阶段回撤，再由其他证据族佐证。缺少区域门槛时，分数可以保留为观察信息，但等级不能升级。增加深回撤非高位和浅回撤放量下跌的反例测试。


### R13｜P0：不同来源的事实不能共用一个证据哈希和时间轴

**风险：** 指数收盘、两市成交额/量、市场广度通常来自不同接口或不同计算过程。若把它们放在同一条记录并共用一个原件哈希、修订 ID 和发布时间，就无法证明每个字段来自哪份原件，也无法单独处理某一路数据的更正、延迟或待审状态。

**整改：** 第一阶段领域输入拆分为指数价格、市场成交额/量、市场广度三个独立事实流；每个事实流单独携带来源时间戳、修订 ID、SHA-256 和审核状态。周期计算只在三个流各自通过时间点与完整性门槛后组合结果；持久化层不得因多个指数引用同一市场成交额而重复累计。



### R14｜P0：官方网页公开展示不等于获准自动采集与持久化

**风险：** 上交所历史数据产品页面明确列出按年订阅的历史数据服务；交易所网页可查看某个统计数字，不代表允许无许可批量下载、长期保存、回填或再分发。若直接把公开网页视为免费 API，可能违反数据使用条件，也会让生产系统依赖未获授权的接口。

**整改：** 每个来源分别审核自动采集、本地持久化、历史回填、再分发四类用途；保存实际条款/合同证据哈希、审核人、审核时间、策略版本。未获人工批准时，来源门禁默认拒绝。参见 MARKET_CYCLE_DATA_SOURCE_FEASIBILITY_20261025.md。

### R15｜P0：现有交易所页面端点不是已确认的稳定 API 合同

**风险：** 现有成交统计适配器使用网页内部 JSON 端点并对产品代码、字段和单位作硬编码。真实页面当前可解析，不代表字段、分页、历史覆盖和响应语义受版本控制；合成测试也不能证明真实响应口径正确。

**整改：** 在新增生产适配器前，取得官方字段/单位说明或明确来源合同；保存人工确认的真实原件及 SHA-256，核对日期、统计范围、字段、单位、空数据、错误页、分页和修订。没有真实黄金样本时只能标记契约未验收，不允许进入正式数据就绪状态。

### R16｜P0：当前证券主表不能充当历史全市场证券宇宙

**风险：** 当前 security_master 和 ETF 观察名单只服务于应用配置，缺少退市、吸收合并、上市生效日及历史证券类别。直接用它计算历史广度会产生严重存活偏差，并可能把缺失证券从分母中静默移除。

**整改：** 建立独立的按交易日版本化证券宇宙快照，保留历史退市证券、纳入/排除原因、定义版本与快照哈希；市场广度必须引用同日已审核快照。证券级历史行情或证券宇宙任一项无法还原时，相关日期不能用于严格回测。

### R17｜P0：历史最终值不能反推出过去的首次可见时间

**风险：** 今天下载到的十年历史日线只说明今天可以取得这些数据，不能证明每个值在十年前的哪个时点已公开，也不能恢复供应商后来修订前的旧值。将当前最终历史数据填入 FirstSeenAt=交易日会制造未来数据泄漏。

**整改：** 区分 PointInTimeVerified、HistoricalFinalOnly 和 Unverified。历史最终值可用于探索性统计，但不能作为严格点时样本外证据；从获批采集上线起归档每次原始响应、首次发现/获取时间、来源发布时间、修订和解析器版本。

### R18｜P1：现有交易日历是限定年份的审核实现，不是无限期通用日历

**风险：** 当前 ReviewedExchangeCalendar 固定登记 2025、2026 年的公告并验证预期文本；若未来年份未登记，或发生临时休市/交易安排变更，系统不能仅靠周末规则推断真实交易日。

**整改：** 每年登记并复核交易所官方公告和原件哈希；未知年份、公告解析变化、交易所日历冲突或临时安排未核验时停止计算。不要自动沿用上一年的假期规则。

### R19｜P1：来源使用权限尚未形成可执行门禁

**风险：** 只把许可要求写在 Markdown 中，不能阻止未来开发者直接调用 HTTP 或执行历史回填。

**整改：** 在 Core/Application 增加无默认批准的 MarketCycleSourceAdmission；自动采集必须同时具备自动采集与持久化权限，历史回填必须另有回填与持久化权限，再分发必须单独批准。审批证据无效、未生效或过期时失败关闭。该门禁仍需在未来具体适配器和作业注册入口强制调用。



### R20｜P1：输入验证门禁不等于审批身份认证或审批记录防篡改

**风险：** MarketCycleSourceAdmission 检查审批对象字段、用途位、有效期和条款原件哈希，但它本身不证明 Reviewer 身份，也不阻止调用方直接构造 Status=Approved 的对象。若未来作业把任意 JSON/用户可写配置直接映射成审批对象，门禁可能被伪造审批绕过。

**整改与当前状态（2026-10-25）：** 已新增 MarketCycleSourceApprovalRegistry，复用插件现有 SQLCipher 加密 market.db；审批记录绑定 SourceId、来源基址、DatasetId、用途权限、条款原件 SHA-256、审核人/时间、策略版本及有效期。写入采用宿主注入的 IMarketCycleApprovalWriteAuthority，命令 ID/nonce 去重，追加式 HMAC 链、完整链核验和撤销状态；缺少授权器时写入失败关闭，准入时必须与注册表当前完整记录逐字段匹配，不能通过修改 JSON 的 ApprovedUses 或 URI 提权。 新增 RequireTarget 将每次请求的实际 SourceId、DatasetId、HTTPS 主机/端口及路径边界绑定到获批基址，避免只验证审批对象却请求其他 URL。

**尚未关闭的风险：** 当前 Worker/桌面组合根尚未实现并注入绑定真实管理员会话的生产授权器，因此生产审批写入仍关闭；测试授权器仅供离线测试，绝不能部署。事件 HMAC 链与独立 MAC 的链头锚点可检测记录篡改、内部删行、重排及未同步更新锚点的尾部截断；但链与锚点仍存于同一 market.db，攻击者若恢复一份协调一致的旧快照，仍无法从库内证明发生回滚。防全库回滚仍需独立于 market.db 的受保护单调序号/最新链头。上述两项完成前，不注册真实市场周期采集/回填作业。


## 修订后设计的准入条件

以上 R1、R2、R3、R4、R5、R8、R9、R11、R12、R13、R14、R15、R16、R17、R18、R19、R20 已写入设计文档或 P2 接入设计，并作为后续实现约束。R6、R7、R10 仍属于来源、持仓穿透和通知接线阶段的强制验收条件；来源门禁与 SQLCipher 审批注册表已进入代码；生产管理员授权和独立回滚锚点仍未完成，未来具体适配器和作业仍必须强制调用注册表准入检查。
## 第一阶段实现边界

第一阶段仅实现可确定重算的领域评估与合成测试：
- 交易日历和 250 个有效收盘点的完整性门槛；
- 前 20 个交易日成交额均值（不包含当日）；
- 5 日收益、滚动高点和回撤；
- 顶部与底部候选的证据族评分；
- 5 日后的广度改善与收益修复标记；
- 基于来源发布时间（如可得）、首次发现时间、实际获取时间及修订 ID 的点时过滤；
- 数据缺失/待审/冲突时失败关闭。

本阶段不实现联网采集、数据库迁移、Worker Job、正式 UI、自动通知或正式发布审批。必须在代码与 PR 说明中保持这一边界。
## 2026-10-25 补充反方审查

新增P0反例：默认知识时间、早于评估日的截止、早于交易日的取得、缺日历证据身份、广度定义混接及未转义字段拼接指纹。以上进入领域输入契约v2的失败边界；同一时刻的UTC/北京时间表示须得到一致身份。正式登记不可能早于其绑定原件的首次取得，不能把来源抓取前的“发现”当成已拥有金融事实。

修正及验证入口见[设计续记](../implementation/MARKET_CYCLE_SIGNAL_DESIGN.md)。这些防止错误开放研究状态，仍不关闭真实指数/广度数据、模型标签、时间样本外、行业估值及持仓方向门槛。

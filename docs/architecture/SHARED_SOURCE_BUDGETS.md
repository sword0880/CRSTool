# 宿主共享来源预算（ARCH-209）

状态：源码实施与隔离验证阶段，未部署到已安装服务；长期负载及真实来源恢复仍待验收。

Worker组合根唯一创建`SourceBudgetRegistry`，所有`WorkerPluginContext`绑定同一实例与宿主确认的插件ID。可选BCL能力`IBackgroundSourceContext`提供租约、旧状态合并和解析失败反馈，不交出宿主密钥、存储对象或HTTP客户端。插件仍负责已审核URL、响应体上限、原件和业务解析。

## 预算与公平性

宿主固定映射SSE四个公开域名、SZSE两个公开域名及已审核发行人域名至三个预算。未知域名拒绝，插件不能自选来源别名绕过额度。具体发行人路径仍由Jobs的原有白名单限制，预算许可不等于URL许可。

每来源最多一个在途逻辑HTTP调用，请求开始间隔至少3秒，租约覆盖头部及正文读取；两个交易所独立推进。等待队列跨插件FIFO，上限32项，每插件最多8个未释放请求（含其在途项）；超额立即返回`SourceQueueFull`。排队取消移除自身，既有顺序不变。当前策略不实行权重或抢占，长请求仍受网关20秒总期限约束。

403/429至少六小时冷却；超时、连接故障、服务端5xx及内容契约失败从5分钟指数退避，基数上限六小时并加0～20%正向抖动，Retry-After可进一步延长。排队请求在获得资格后重新读取冷却；已有失败不会被排队重试绕过。冷却到期成功清除失败计数，迟到成功不能清除仍有效的其他失败反馈。调用方取消不计来源故障。

网关原有系统代理连接失败后同URL一次直连保留在同一租约内；403/429不重试直连、不换域。预算约束是一次逻辑调用的开始间隔，不能当成底层连接尝试次数统计。

## 持久化与升级

根数据目录新增SQLCipher`source-budgets.db`，版本1，使用服务主密钥的独立HKDF域派生，`synchronous=FULL`。进程仍由既有数据根独占租约保证唯一Worker，注册表内部统一互斥，不支持多个独立Worker共享一个预算库。

Jobs保留原`source-policy.db`作为旧宿主兼容与保守限制。网关创建时（会话Start，早于Worker启动调度）将全部三个来源的旧Next/Blocked/Failures合并到宿主，之后每次申请再次合并；只取更晚期限和更高失败数，不能以空新库消除旧拒绝。新旧策略都成功允许后才访问网络。已有冷却不自动删除，也没有绕过或清空命令。

已初始化的库缺少状态表、非法/越界失败计数、损坏日期、未知库版本、预算读写失败均拒绝访问来源；启动会读取校验三个来源的持久状态，不能先声明健康再发现损坏。运行期读写失败锁定存储故障，不能在短暂恢复后继续放行，须重启并核验。请求间隔必须在HTTP前写入；失败状态写入失败仍上抛。宿主停机先终止调度和插件，再释放注册表。现有整树备份、权限检查覆盖新增库，未新增单库回滚操作；正式升级/断电恢复仍需专项验收。

## 可观测与兼容

`GetHealth.Health.Sources`附加来源名、Ready/RateWait/Cooldown、在途/等待数量、下次允许/冷却时间、失败次数及进程内延迟/拒绝计数。队列和计数重启归零，期限和失败数持久化。不包含URL、响应、凭据或插件输入。现有IPC版本2不变，字段可选，旧客户端可忽略；来源冷却不表示整个Worker不健康。来源存储失败时，健康查询保留`Code=Ok`和`Health.State=StorageFault`供运维读取，`Sources=null`明确表示来源快照不可用；其他执行/插件查询失败关闭，不把未知来源状态返回成Ready。

正式组合根始终注入预算；无预算的`WorkerPluginContext`失败关闭。旧宿主不实现可选能力时仍按插件原策略运行，不能声称该运行环境具备跨插件限流。可信第一方同进程插件需主动调用端口，本实现不是OS网络沙箱。

验证入口：`CRS.Tests.WorkerEtf --source-budget`。覆盖不同宿主插件上下文与真实网关的共享拒绝、域名归并、独立市场、FIFO、取消、32项容量、单插件限制、Retry-After、重启/恢复、旧冷却预合并、存储写入故障锁定和真实3秒间隔。网络由固定响应代替，未访问官网。长时间持续超载、真实服务部署/源站恢复、断电/磁盘满和历史发行升级仍开放；不能将ARCH-209整项标Closed。

## 存储提供方边界

SourceBudgetRegistry仅接收ISourceBudgetStore；Program创建SqliteSourceBudgetStore并移交生命周期。注册表不接触目录、密钥、连接或SQL。具体适配器保持原Schema和持久提交顺序，运行期SQLite故障转为IOException并保持故障锁定。替换实现仍须满足原子持久Save与损坏拒绝语义；当前只支持单Worker写入，多实例数据库部署需额外原子预留设计。详见[数据库抽象与替换边界](DATABASE_PORTABILITY.md)。

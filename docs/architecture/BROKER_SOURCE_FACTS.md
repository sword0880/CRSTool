# 券商不可变来源事实（ARCH-208）

本轮先收敛IBKR来源读取；税务和绩效继续拥有各自投影、计算与验收，不把Tax/FIFO结果作为Performance输入。

## 来源所有权

Application定义`BrokerSourceDocument`及`BrokerSourceRecord`：券商、原件SHA256、批次ID、来源读取版本、不可变属性/子记录/叶文本和原件内位置。使用ImmutableArray和ImmutableSortedDictionary，不持有可变XML节点；未知区段、字段和叶文本保留，完整原件继续按SHA256留存。该模型不替代原始XML的完整归档，不因当前投影不支持而丢弃原件。

Infrastructure的`IbkrSourceReader`是Activity Flex正文唯一结构读取入口，版本`IBKR.SourceFacts.v1`。继续使用既有安全XML读取器（禁DTD/外部实体、原件25MiB上限），归一元素命名空间并冻结；转换期响应取消，增加64层深度、2048字符位置及250000节点上限，超限整份拒绝，不返回半份事实。

位置格式为原件根及按原始子节点顺序定位的路径，结合原件SHA256唯一定位；不是跨版本经济交易ID。属性保留原值，数字/日期的既有校验仍由共享字段工具和各投影完成，不把未知金额补成零。

## 调用路径

1. `FrozenInput`冻结原件字节与SHA256。
2. `IbkrSourceReader`生成不可变来源文档。
3. `IbkrXmlParser`保留现有公共入口，内部消费来源记录，继续执行既有成交、现金、持仓/LOT、去重、账户/期间及对账规则。
4. 证券流水同步绩效时，把**同一个来源文档实例**随原冻结输入传给Vault/PerformanceFiles，不再重新解析XML。
5. 独立绩效导入也调用同一来源读取器，再由`IbkrPerformanceAdapter`投影；它核对原件SHA256、券商和读取版本后才消费快照。
6. 账号遮蔽/主动展示读取加密原件时也调用同一入口。不同业务请求可重新读取，不做跨会话明文全局缓存。

富途继续使用既有`BrokerActivityFacts.Freeze`规范事实投影路径；本轮仅让通用内部同步回调携带可选来源事实，富途传null，不改其解析或税务规则。

## 兼容与未关闭事项

来源读取首轮未改税务、FIFO、汇率规则、既有税务来源记录、绩效历史JSON、数据库Schema、服务身份或插件契约。后续绩效版本归档见下节，金额数据模型和历史原记录仍不回写。绩效事件ID、来源行标签和金额映射保留原值；新来源路径不反写历史结果。内部同步委托增加来源文档参数，Infrastructure及调用方须配套构建。

此层是原始来源事实，不等于已完成所有交易分类/公司行动的统一规范账本。各投影对未知事件、缺币种/估值、复杂转仓的既有保守门槛继续保留，源记录被保留不表示已经支持其金融语义。

绩效新导入及新运行已持久保存实际读取/投影版本，兼容旧设置和旧历史；详见下节。IBKR税务新历史的显式解析版本已接入（见下节）；完整类型化投资事实、跨版本投影差异及独立签认Tax/Performance真实黄金样本仍为ARCH-208未关闭事项，不能将本项标为Closed。

## 后续：绩效解析版本持久化与旧记录兼容

新增不可变`BrokerImportProvenance` V1：原件SHA256、批次ID、券商、实际来源读取版本、绩效投影版本、单份导入事实摘要。IBKR复用实际共享快照的读取版本，独立导入也只读取一次；Futu记录`FutuAnnualActivity.v1`，不把税务/FIFO输出作为绩效输入。投影版本为`IBKR.Performance.v1`及`FUTU.Performance.v1`，未来映射有语义变化须独立评审并更新版本。

来源版本与原件在同一SQLCipher事务写入`performance_settings`，以原件hash索引；读入时核对对应`performance_documents.data`的有序事实摘要。原件写入成功而版本写失败时，整个导入回滚。旧原件重复导入不会据当前解析器补填过去的未知版本，也不覆盖旧事实。

绩效设置JSON明确写Version=2，读取接受原Version=1且默认来源版本未知；不改变原三张表、金融`PerformanceData.Version=1`或保险库主Schema。新版设置/历史含新增字段，旧程序严格解码不能读取；不承诺向旧二进制降级。回退应保留新库并使用既有完整备份/恢复流程，不能删除版本字段或改回Version=1冒充旧资料。

新计算只从有效来源冻结版本记录，重放沿用原运行的不可变版本集合。新非空版本集合进入结果指纹，修改或剥除会校验失败；旧历史缺字段使用原版指纹载荷，不重签旧结果。运行清单列出逐原件依据；混有未记录版本的来源时标为PartiallyRecorded，全部缺失则Unrecorded。普通报告版本依据与加密`evidence.json`也携带对应记录；原件数据、来源修订和历史随加密备份恢复。

本次保存的是来源/投影的审计依据，未建立完整规范投资账本，未对未知公司行动或转仓补金融语义，税务新历史的版本审计另见下节，旧记录不迁移或补造版本。已有IBKR/FUTU金融冻结JSON、税务规则及独立金额验收顺序不变。验证入口为`--broker-provenance`，也包含在`--performance-only`，证据见整改续记。

## 后续：IBKR税务历史版本审计

TaxImportProvenance V1保存券商、原件SHA256、批次ID、实际来源读取版本与税务投影版本。新IBKR年度及期初报告均从实际BrokerSourceDocument记录IBKR.SourceFacts.v1和IBKR.Tax.v1；同内容只记录一份依据。来源/投影版本变化须随映射独立评审，不由运行时程序集版本猜测。

版本依据从ImportData复制到CalculationResult的可选冻结集合，与结果正文在现有仓储操作中原子保存，不新增表、连接或提供方类型。载入/封存/冻结核验格式、券商、原件/批次绑定及重复/数量上限。新非空集合进入既有整份结果封存摘要，修改或剥除均拒绝；不是来源真实性认证或数字签名。

版本审计独立于规范金融输入JSON；现有CanonicalInput/InputReferences版本、输入摘要和金额投影不变。重放从历史结果带回原版本集合，不使用当前读取器版本，也不为旧记录补造。年度汇总合并已有版本依据，未记录的来源继续未知；底稿新增“解析版本”表，按原件展示实际版本或“未记录”。

旧记录缺字段保持null，序列化不新增该字段，从而保留旧封存载荷；这是读兼容，不承诺旧二进制可读取新记录。旧二进制忽略新字段后封存校验可能失败，回退仍须保留新库和完整备份，不得剥除字段或重签旧结果。富途税务版本已接入（见下节），旧记录仍未知；绩效Futu版本继续沿用既有归档。

专项入口 `CRS.Tests.Infrastructure --tax-provenance`。旧构建解析对照仅允许新增版本审计字段，仍对其余所有字段逐一比对，新增字段另外核验实际版本；不重写金融冻结期望值。旧形态兼容检查是缺字段的兼容夹具，不冒称独立旧版本真实金额签认。完整类型化事实、跨版本投影差异和独立真实Golden仍开放。

# CRS 税务规则适用性与验证规范（TAX_RULE_VALIDATION）

> **状态：新增的验证规范，非税务合规验收通过证明；未要求修改现有税额引擎。**
>
> 版本：1.0（2026-10-10）｜维护主体：产品/税务规则负责人｜适用：.NET 10 WPF 本地境外证券所得**辅助测算**。
>
> **单一事实原则：** 当前实现以 `TAX_ENGINE_SPEC.md`、`CAPITAL_GAIN_FIFO_SPEC.md`、`FOREIGN_CREDIT_REVIEW.md` 和实际源码为准。本文件只规范规则来源、验证和上线门槛；对法律适用的判断必须经独立复核，不得凭本文把辅助结果升级为申报结论。

## 1. 目的与适用范围

针对个人投资者从 IBKR / 富途报表中取得的交易、股息、利息及境外预扣税记录，建立“**代码事实 → 法规条文 → 适用条件 → 计算样本 → 独立复核 → 发布资格**”的证据链。

- **产品边界：** 本地整理和辅助计算，不代替中国个人所得税申报、税务居民身份判定、税务代理或主管税务机关认定。
- **当前支持输入：** IBKR Activity Flex XML；富途当前已验证的交易/收入 XLSX 及文本 PDF 布局；规范化交易与期初 LOT；参见券商导入指南。
- **当前不支持/尚待验收：** 完整证券转让税额抵免、协定资格自动判定、法定外币折算闭环、跨年抵免结转、复杂公司行动/转仓/衍生品及真实全年法定口径验收。此清单不意味着所有场景都已被穷举。
- **税务适用前提：** 本规范以**中国税收居民个人**取得相关境外所得的场景为验证对象；具体税收居民身份、所得来源地、资产分类及适用年度均须确认。CRS 自动交换信息与个人所得税义务不是同一个法律判断。

## 2. 证据等级与发布状态

| 代码 | 证据/状态 | 定义 | 是否可支持“可直接申报” |
| --- | --- | --- | --- |
| `IMPLEMENTED` | 代码事实 | 已在源码中存在的公式、数据接口或保护门槛 | 否 |
| `SOURCE_CHECKED` | 条文来源已核对 | 找到官方条文及具体条款，**未完成个案适用** | 否 |
| `TESTED_SYNTHETIC` | 合成样本通过 | 测试验证计算一致性，不等于法规正确性 | 否 |
| `TESTED_REAL` | 真实样本对账通过 | 独立人工基准验证真实券商文件和处理流程 | 单独仍不够 |
| `REVIEW_PENDING` | 适用性待签认 | 存在税务解释/所得来源/汇率/抵免资格问题 | **否，阻断完整预计补税** |
| `APPROVED_SCOPED` | 指定场景签认 | 签认人、依据、范围、限制、日期均记录 | 只在明确范围内供辅助核对，不表示机关核准 |
| `OUT_OF_SCOPE` | 不支持 | 禁止自动套用，保持未知值/人工处理 | 否 |

**硬性规则：** `Summary.SupplementTax` 为既有公式计算值，不是最终税务认定；当完整性、对账、口径或证据门槛未满足时，`CalculationResult.EstimatedTopUpCny` 必须保持 `null`，并在页面和导出清晰说明原因。禁止用 0 代替未知额；不允许人工备注直接解除成本或法规问题。参见 `TAX_ENGINE_SPEC.md`、`KNOWN_ISSUES.md` 的 AR-06/07。

## 4. 税务规则核验矩阵（核心工作台）

> 下表“现有实现”依据项目上传的 2026-10-10 文档，不代表逐行源码核查。“发布动作”属于新需求。`TAX-xx` 为**文档拟定规则 ID**，不是现有代码中的已实现常量。

| 规则 ID | 范围及当前代码事实 | 法规锚点 | 关键待核实/反证场景 | 目前结论及动作 |
| --- | --- | --- | --- | --- |
| `TAX-01` | 税收居民与年度：当前用户选年度 | `LAW-PIT`、`LAW-OVERSEAS-2020-03` | 居民/非居民、境外非公历税年、跨年收入确认 | `REVIEW_PENDING`；年度和适用身份显式确认，未确认禁止申报用途声明 |
| `TAX-02` | 所得来源国家：已可人工分配股息/利息 | 公告第 1 条 | 发行主体所在地、支付主体、券商与上市地不同；特别来源规则 | `REVIEW_PENDING`；不得通过账户/市场/交易币种自动认定来源国 |
| `TAX-03` | 所得分类：股息、利息、证券财产转让 | 公告第 2 条、个税法第 3/6 条 | 其他收入、基金分配、REIT、期权/衍生品、返还资本 | 支持已确认分类；不能识别时 `OUT_OF_SCOPE` 并显示问题 |
| `TAX-04` | 买入成本：`FIFO_TOTAL_COST_V3`、`CostBasisMode`、费用守恒 | 个税法第 6 条、实施条例第 16/17 条 | **税法是否认可项目的 FIFO 配对口径**；股票拆并、换股、转仓、赠股等原值 | **算法正确 ≠ 法规认可；不得自动把 FIFO 标为法定成本**；待书面适用性复核 |
| `TAX-05` | 出售手续费：`Match.Gain = Revenue − SellFee − Cost`，买入费用不重复扣 | 实施条例第 16/17 条 | 费用性质、交易税、异币种费用、退佣、费用字段缺失 | 先验证费用可扣项目及跨币种折算；缺失时不能填 0 |
| `TAX-06` | 财产转让损益：当前合计 `Match.GainCny`，正值 ×20% | 个税法第 3/6 条及公告第 2 条 | **不同卖出交易的盈亏如何认定及能否相互抵减**；年度/同类/跨类冲抵 | `REVIEW_PENDING`；不能把年度净收益算法视为当然适法 |
| `TAX-07` | 股息/利息：原币金额以项目汇率转 RMB，合计 ×20% | 个税法第 3/6 条、公告第 2 条 | 毛额与净额、退税、股息再投、混合分配与特殊豁免 | 审定金额定义和所得分类后再确认适用性 |
| `TAX-08` | 汇率：2026 用截至 10-08 报价日平均值；2021–25 旧值未复核 | 公告第 12 条、实施条例第 32 条 | 申报/预缴状态、上一月末/上年末汇率、非交易日报价 | 当前仅 `TEMPORARY_ESTIMATE`；法定折算验证前完整预计补税不可发布 |
| `TAX-09` | 抵免按国家分类、凭证关联，部分限额辅助测算 | 公告第 3/4/6 条 | 逐国限额、分类所得抵免、错误征收、退税/补偿、超限五年结转 | `REVIEW_PENDING`；保持 `TAX_CREDIT_REVIEW` 和未知补税门槛 |
| `TAX-10` | 税款凭证仅检查存在、摘要和关联 | 公告第 10 条 | 证明文件真实性/所载税款与实际缴纳一致、协定资格、原件要求 | 结构化记录不能代替税务机关认可；凭证待人工验证 |
| `TAX-11` | 多账户年度归并：同年度、同纳税人确认后统一辅助计算 | 公告第 2/3 条 | 混合纳税主体、跨国、跨券商同一事件重复、年度不一致 | 保留账户隔离与相同纳税人门槛；真实跨券商样本验收 |
| `TAX-12` | 申报用途与报表：现有 Excel 为辅助底稿 | 公告第 7 条及 `FORM-OVERSEAS-B` | B 表及抵免明细表字段覆盖、证明义务、税局受理差异 | **不得称“可直接申报表/税务机关核准税额”**；先做逐字段映射及人工签认 |
| `TAX-13` | 股票转让税制特殊规则：当前算法对正的证券收益采用辅助 20% 口径 | 实施条例第 7 条、个税法第 3/6 条及适用的特别规定 | A 股、港股、美股、跨境互联互通、ETF、场外交易的法律适用可能不同；不能仅凭券商/上市市场或账户地区归类 | `REVIEW_PENDING`；对各交易市场和所得类型逐类核验税收优惠、免征或特别规则的适用年度与条件，不得统一作法定 20% 结论 |

**特别禁止的默认假设：** `FIFO = 税法指定计价方法`、`年平均汇率 = 法定汇率`、`券商所在国 = 所得来源国`、`券商预扣税 = 必然可抵免税`、`一次成功导入 = 全年数据完整`、`20% × 全年净收益 = 已确认申报税额`、`不同交易市场/证券类型适用同一转让税制`。

## 5. 规则模型与版本治理（建议契约，尚未实现）

每个将影响税额的规则应有结构化元数据，至少记录：

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `RuleId` / `RuleRevision` | 是 | 本文件规则 ID 与内部修订号；与 TaxEngine `PolicyVersion` 分开 |
| `EffectiveTaxYears` | 是 | 实际适用年度或范围；未知时标 `Pending` |
| `TaxResidentScope` / `IncomeCategory` | 是 | 纳税人/所得分类适用条件 |
| `LegalSourceRefs` | 是 | 官方条文 URL、条款号、抓取/核对日 |
| `ImplementationRefs` | 是 | 实际代码文件/方法、测试用例及 `PolicyVersion` |
| `ValidationStatus` | 是 | 使用第 2 节枚举，不得默认为 `APPROVED_SCOPED` |
| `Reviewer` / `ReviewedAt` / `EvidenceIds` | 签认时是 | 独立复核身份、日期、证据与适用限制 |
| `KnownExclusions` | 是 | 特殊证券事件、资金流水缺口、汇率不适用等 |

**规则变更流程：** 增加规则版本和有效年度 → 补入法规来源及反例 → 增补独立测试样本 → 审核不同证券/账户情形 → 税务适用签认 → 与源代码和 `TAX_ENGINE_SPEC.md` 同步 → 生成带版本标识的新计算。不得静默重写既有冻结历史。

**更正法规理解时：** 旧任务保留原计算规则/版本及历史提示；新计算使用新版本并生成新的运行 ID，不能覆盖旧结果。若发现涉及重大计算风险，公开版应提供受影响版本列表与必要警示。

## 8. 放行与阻断标准

**内部辅助测算可运行**：保留当前范围限制、未知值、问题代码及原币底稿；可展示部分计算公式，但不向用户承诺法定适用性。

**某一具体场景可完成“适用性验证”**：条文已核实 + 明确居民/所得/来源/税年条件 + 独立真实样本对账 + 负责人签认，记录审定范围与反例。只对已签认范围解除对应规则问题。

**公开版发布阻断条件**：税务法定折算、成本口径、抵免适用性等与用户可见金额实质有关且未签认时，不得将 `EstimatedTopUpCny`、Excel 或宣传语标注为“已核定应补税”“申报可直接采用”。可以作为**明确限制范围的辅助测算版**发布的前提是业务与合规负责人确认风险提示、阻断门槛、真实样本和发布条款符合预期；总体发布批准仍由 `RELEASE_ACCEPTANCE.md` 管理。

**任务入口：** `KNOWN_ISSUES.md` 的 AR-06、AR-07、AR-12。新增规则/样例/审计材料写入本文件或受版本管理的非敏感验收记录；不要重复建立第二套待办清单。

**文档责任边界：** `TAX_ENGINE_SPEC.md` 描述当前实现；本文定义**如何核验税务适用性**；`CALCULATION_EVIDENCE_SPEC.md` 说明**如何固定某次计算使用的输入/规则/输出**；`RELEASE_PLAN.md` 规定**何时可以公开发布**。三者不能互相替代。

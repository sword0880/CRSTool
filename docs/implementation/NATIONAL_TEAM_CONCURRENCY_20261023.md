# NationalTeam 分组并发整改

2026-10-23。按用户确认，将不同来源下载改成有限并行，数据库操作保持短段串行，预警使用一致事实，每次执行独立保存进度与取消状态。

## 默认运行规则

Worker 全局并发为 8 时，NationalTeam 总并发为 4：

| 执行组 | 最大并发 | 任务 |
| --- | --- | --- |
| collection | 2 | 份额、成交、日历、披露、报告检索、原文下载审核、完整性巡检 |
| evaluation | 1 | 预警评价与通知提交 |
| management | 1 | 配置、审核、观察池及预警管理 |

同一 JobKey 仍由 Quartz 禁止重入。组内保持等待顺序；采集额度用完时，宿主可越过该组等待项，分派预警和管理任务。等待任务释放 Quartz 名额，保留有界等待、自动合并、持久命令、取消和回调排空保护。

全局额度和单插件最多占全局一半的限制仍有效。如果管理员调小全局额度，插件和组额度也受限，不能保证三个组始终同时执行。未声明可选分组契约的旧插件维持原策略。

## 执行、来源和存储边界

- NationalTeamBackgroundSession 通过 AsyncLocal 绑定每次执行独立的进度对象，隔离回调、日期和 HTTP 开始计数；退出恢复前一上下文。取消令牌仍由宿主按执行创建。
- 份额区间缓存只用于同一份额 Job；Quartz 不重入，应用层 syncGate 继续保护直接调用。查询快照和导出缓存仍受独立查询门槛保护。
- HTTP 网关由总锁改为 SSE、SZSE、已审核发行人三个来源门槛。同交易所域名共用额度，不同来源独立推进；SQLite 来源策略连接只在短互斥区内使用，网络等待不持有该锁。
- 宿主共享预算、至少三秒请求间隔、403/429 冷却、Retry-After、响应大小、白名单、正文期限及代理失败规则保留。迟到成功不清除仍有效的并行失败反馈。
- 份额按市场并行，SZSE 内各证券保持顺序；成交统计按日期固定日历快照，再并行下载两市场，串行汇总、提交结果。某市场失败仍保留另一市场事实和缺口，不补零。
- EtfWorkspace 保留单一数据库访问门槛、事务、修订检查和命令幂等。下载期间不占数据库门槛，管理操作无需等待整批下载。
- 完整性巡检先捕获来源 ID/哈希快照，在数据库门槛外核验文件，再核对当前来源哈希，以短事务提交同一快照结果。同类巡检单独串行，避免旧核验晚提交覆盖新结果；新增或已变更来源不冒充已核验，取消或不完整结果不部分提交。
- 预警评价在一个串行仓储操作内读取已提交事实并生成事件，其他任务不能在读取输入与生成事件之间改写市场库。必要的证据核验保留，不以提高响应速度跳过证据门槛。预警无需排在整个补采批次之后。
- 相同原件并行落盘采用原子移动；另一执行先保存时，只在重新核对目标哈希正确后接受去重。

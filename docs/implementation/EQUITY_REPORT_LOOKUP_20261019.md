# 持股候选的官方报告检索

## 目的与范围

29条正式持股候选仍待核验，图表缺少的不是绘图控件，而是与股东数据相符的报告期和原文。本轮提供官方报告目录检索，减少手工查找PDF链接；不自动批准股东数值或推断报告截止日。

## 来源核对

- 上交所公司页官方脚本 `https://www.sse.com.cn/xhtml/home/2021public/querySearch/search_stocksDepositoryReceipts_2021.js` 的 `company.announcementUrl` 指向 `security/stock/queryCompanyBulletinNew.do`，参数含证券代码、关键词、日期及分页。
- 实际公开样本 `artifacts/equity-disclosures-20261019/announcements.json`：600153，2026-08-01至2026-10-19，关键词“报告”。一个公告组含摘要及全文两个附件，分页total=1。全文链接为 `https://static.sse.com.cn/disclosure/listedinfo/announcement/c/new/2026-08-29/600153_20260829_U7BY.pdf`。
- 正常空样本 `empty.json`：2026-10-18至2026-10-19，同股票，total=0、pageCount=0、result=[]。不能把它误报为缺尾页。
- 本机curl/Schannel握手失败；保留证书验证的Python标准TLS客户端取得上述研究样本。生产程序仍使用现有C# OfficialHttpGateway，不引入Python运行时、不跳过证书验证或来源退避。

## 业务与展示

- “披露证据 / 核验”新增官方定期报告目录。“查找官方报告”提交Worker持久手动命令，查询最近400天，受理后立即返回；源码限流或失败由后台按原股票和固定日期区间重试。
- 在同一客户端重复点击尚待执行的同股票检索沿用原请求ID；受理情况不明时也保留原ID。只有完成的请求才允许下次新检索。
- “刷新报告目录”只读缓存；关闭桌面后已受理的后台任务继续。目录存在只代表取得JSON检索证据，不代表PDF已下载或股东表已核验。
- 仅支持已核对的沪市公告接口；深市请求明确拒绝。手动检索不能启用为无参数定时任务。
- 按公告组校验分页。所有页数量、证券代码、请求区间、公告ID和PDF日期路径必须匹配；跨页重复或截断时整次目录不提交。完整报告与摘要区分，过滤摘要后保存官方定期报告线索。
- 对完整返回内容存原始哈希，目录证据损坏时State=Critical，不能自动填入表单。只有恢复原字节哈希才解除异常。
- 选中目录记录可打开官方PDF。“填入所选报告”只填链接与目录公告日，重置原文确认和可比性；待审核候选报告截止日清空，须人工核对PDF。已核验披露禁止改用不同原文。
- 原有逐账户主体、股类、单位、总股本分母、公司行为及股数核验继续生效。不会因找到目录而产生任何持仓或增减持结论。

## 存储与兼容

- Worker市场库增加`equity_report_search`、`equity_report_index`，保留历次检索与原始来源证据；读目录去重相同PDF链接。
- 业务命令与目录在同一事务提交。进程中断后重放已提交命令，先查提交记录，不重新联网或重复写库。
- WPF仍只负责交互和展示；网络、解析、分页验证和数据库均在后台实现。本轮需要配套升级后台及桌面包，不能仅同步新UI到旧服务。

## 待验证

构建、回归、真实样本解析、后台真实管道及实际安装验收结果将在完成后追加。PDF表格自动提取、深市适配、个股行情与退出评分仍未完成。

## 使用方式

打开“设置 → 数据管理 → 运行资料清理”，选择日志保留天数及历史副本保留份数，点击“扫描可清理资料”。默认不选旧升级副本；勾选“同时清理更早的已完成升级副本”后需要重新扫描。预览优先列出将清理的项，各项可展开查看相对路径与原因，未知大小显示“未统计”。

“按预览清理”单独执行，不随“保存设置”触发。需要管理员权限和支持新命令的配套后台；旧后台明确报告不支持，界面不会自行删除后台文件。旧副本清理后，无法再依靠它回退到对应的历史版本。

预览有效15分钟，更改选项或新扫描会使旧预览失效。受理后保留操作编号；断线或停止等待不等于取消后台清理，应点击“查询清理结果”。中断、未知结果及未完整记录的删除数量均不显示为完成；重新扫描会核对剩余项。

## 所有权与执行边界

- `CRS.Common/Maintenance` 只定义固定选项、预览项与结果合同，不接受客户端文件路径。
- `CRS.Application/Abstractions/IDataCleanupGateway` 定义设置端口。桌面 `WorkerDataCleanupGateway` 负责IPC及用户主动操作期间的状态查询；WPF只展示结果。
- `CRS.Worker.Service/Maintenance/WorkerDataCleanup*` 由后台资料所有者执行用途判断、摘要核验、维护互斥、删除和审计，不解密当前库或密钥。
- 新命令为 `BeginDataCleanupPreview`、`GetDataCleanupStatus`、`ExecuteDataCleanup`。全部再次验证实际Windows调用者的管理员身份；执行走管理员控制管道。记录按SID隔离，拒绝路径、重复字段和未知字段。
- 扫描与删除使用独立单操作通道，不占Quartz业务并发，也不长时间持有Runtime全局门闩。状态通过短请求返回。

执行前先落盘清理范围，获取与升级相同的 `maintenance.lock`，核对当前维护记录未变化，再核验所保留的历史副本。旧快照验证完整文件集合和摘要后，先移到本功能专用弃用容器，再逐文件清理；清单最后删除，空目录使用非递归删除。未知文件、链接、摘要变化、维护冲突、占用或取消会保留剩余现场并报告未完成。活动数据和归档维护记录不进入删除集合。

扫描逐层拒绝链接并限制枚举数量，利用枚举元数据避免每个文件重复查询全部祖先路径；移动和删除前仍重新检查完整目标。重启发现在途记录时，计数标记为未完整记录，避免把未持久化计数误报为零。

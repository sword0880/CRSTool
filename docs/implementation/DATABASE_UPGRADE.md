# 加密数据库升级与执行程序归档

2026-10-13。业务数据库结构为 `user_version=2`；只接受已验证的 SQLCipher 库。旧明文 SQLite 仍只识别头部并拒绝，不读取业务表、不转换、不覆盖原件或 WAL／SHM。

## 升级和恢复

新建保险库直接建立版本 2。已存在的加密版本 1 在获得业务访问资格后检查实际列、类型、主键和外键关系；版本数字与实际结构不符、未知版本或高于当前版本时拒绝，不自动修补、降级或重建。用户已关闭手机验证时，仍须有效本机受保护密钥才能获得业务资格；恢复流程则已通过主密码或恢复密钥证明身份。

版本 1 升级前在保险库目录生成 `schema-v1-<随机标识>.crsbak`，复用手动备份的 `CRS.Backup.v2` 分块格式；旧 v1 加密备份仍可恢复。在线备份 API 生成独立 SQLCipher 快照，核验数据库完整性，再认证加密封装、完整回读实际容器、持久刷新并提交；不复制正在写入的主库文件。备份失败时不执行业务结构修改。

升级持有同一数据库事务，增加程序归档结构、旧任务归档标记及版本号，完整性检查通过后才提交；提交前异常会回滚结构和版本。旧计算 JSON、金额、来源和人工复核不改写，也不给旧结果补造原执行程序。升级成功或提交前失败时，已完成的升级前备份保留，程序不自动删除这些恢复资料。相同版本再次进入不重复升级或生成备份。

升级前备份可通过现有保险库“恢复备份”功能恢复到新的空目录，凭证是备份生成时的主密码或独立数据库恢复密钥，不需要原 Windows 用户的 DPAPI 文件。当前程序会把恢复的版本 1 副本再升级为版本 2；需要使用旧程序时，只能用兼容该备份及认证格式的旧版本恢复副本，不能手动改版本数字降级原库。应用不在原目录自动替换用户数据库。

新分块备份支持最大 2 GiB 数据库／3 GiB 容器；旧加密 JSON 恢复保留 128 MiB／256 MiB 上限。界面有容量预警，新任务提交前有容量门槛，详见 [分块备份与容量保护](BACKUP_CAPACITY.md)。备份或磁盘写入失败仍会阻止升级；可先解决空间或容量问题再重试。逻辑故障回滚不代替真实断电、磁盘满、网络或特殊文件系统的实机验收。

## 程序文件归档

新保存任务将 Application、Domain、Infrastructure 的实际程序集文件存入 SQLCipher BLOB，单文件最多 16 MiB。文件 SHA256 必须匹配运行封存；相同摘要去重，每个运行保存三个角色与摘要的关系。计算记录、归档正文及关系在同一事务提交，缺失、内容不匹配或损坏时不保存半成品任务。归档随完整数据库备份恢复，不生成库外 DLL 副本。

读取新任务同时核验运行证据、归档标记、三个角色关系、文件大小及正文 SHA256。缺失或损坏拒绝使用该记录。迁移的旧记录标记为无文件归档，保留已有冻结结果与封存，不宣称它们拥有无法取得的历史文件。归档仅存储和校验，绝不动态加载、执行或自动复算旧程序集；跨构建复算仍遵循原有拒绝门槛。

这是程序文件与运行摘要的一致性证据，不是数字签名或供应链认证，也不证明映像在加载之前未被替换。没有归档桌面 EXE、Security、运行时、全部第三方依赖或 PDB，不能宣称完整执行环境保全或任意跨版本重现。

## 验收

`SchemaUpgradeChecks` 使用隔离加密库构造真实版本 1 业务表，验证备份失败与 DDL／版本写入后故障回滚、旧 JSON 和复核保留、升级备份确实包含版本 1、重复进入不重复备份、未知结构与高版本拒绝、程序文件去重、损坏／缺失拒绝及保存事务回滚。升级前备份和带程序文件的新备份均通过既有恢复通道核验。

不同新建保险库的随机 DEK 不同，即使主密码相同也不能串库，拒绝串库不改写原文件。恢复副本仍属于原保险库身份，不等同独立新建保险库。真实不同 Windows 用户及不同电脑的恢复仍待人工演练。

专项入口：`dotnet run --project tests/CRS.Tests.Infrastructure -c Release -- --schema-upgrade-only`。整体产物为 `artifacts/schema-protection-acceptance`，仍保持 `ReleaseApproved=false`。

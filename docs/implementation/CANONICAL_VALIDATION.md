# 规范化快照读取校验

2026-10-13 更新：带账户期间依据时使用完整快照 `CRS.CanonicalInput.v3`／引用 `CRS.InputReferences.v2`，新增 `accountPeriods` 并与冻结声明核对；不带依据时继续生成完整 v2／引用 v1，不自动升级旧版本。期间核对与重放边界见 [账户活动期间](../guides/ACCOUNT_PERIODS.md)。2026-10-11 的结构与上限验收记录如下。

## 已实现

`CanonicalInputReader` 统一处理新快照保存前校验、历史复算、历史交易明细、原件要求查询及原件摘要校验。先检查 UTF-8 大小和 SHA256，再读取 JSON；重新计算一个损坏快照的摘要不能绕过结构检查。

| 项目 | 当前限制或要求 |
| --- | --- |
| 输入大小 | 最多 64 MiB（64 × 1024 × 1024 字节）；不是按字符数估算 |
| JSON 层级 | 最多 32 层 |
| 任意数组 | 最多 200,000 项 |
| 全部数组合计 | 最多 500,000 项，包括嵌套数组 |
| 单个字符串 | 最多 32,768 个 .NET 字符单元 |
| 属性名称 | 最多 128 个字符；任意层级重复字段含大小写差异都拒绝 |
| 文件引用 | 1—36 份活动来源及可选期初来源；唯一文件名、无目录路径、64 位十六进制 SHA256 |
| 顶层结构 | 必须完整提供当前版本字段；完整快照集合必须是数组，不能用 null 或缺省值代替 |
| 明细记录 | 非可选构造参数必须提供；证券 Key 和 LOT 成本／数量等字段显式检查，未知 DTO 字段拒绝 |
| 归属 | 快照券商、恢复模式、期初／范围确认及纳税人范围必须与冻结结果一致 |

明确可空的金额、日期与期初／结转字段保留 null 语义，不补零。数组内的 null 记录拒绝。既有合法空明细集合仍可读取。

新快照不符合上述契约时计算抛出中文错误，不保存为无法读取的历史任务。选择完整快照后超限不会偷偷降为引用模式；用户可调整输入或明确取消完整快照保存后重新计算。

标记为可重放的历史任务不能把空白快照当成正常空交易。明细读取失败时，页面清除旧交易并显示中文原因；冻结税务／FIFO 汇总及图表继续展示，冻结底稿导出仍受原有业务门槛控制。旧版本、不完整或损坏快照不被自动修补或冒充可复算。

## 自动验证

`CanonicalInputChecks` 验证有效完整／引用快照，以及 22 类损坏和超限输入在复算、历史明细及原件要求查询三个入口统一拒绝。包括缺失／null 集合、null 记录、缺失交易数量、未知字段、证券 Key 缺字段、确认／券商不一致、非法文件名或摘要、空来源、超长字符串、过多数组项、缺 LOT 成本、重复／大小写冲突字段、损坏 JSON、非对象根、深层嵌套及超大内容。

WPF 的 `CanonicalViewChecks` 验证损坏明细清除旧交易、显示原因并保留冻结汇总和导出资格。验收产物在 `artifacts/canonical-validation-acceptance`；合成样本不等于真实业务签认。

最终 Release 构建零警告、零错误；六组回归、架构检查和桌面冒烟均通过，原有 68 个综合场景通过。验收脚本使用已有 Release 文件，报告 Build 字段为 skipped_existing_release_binaries；真实样本与公开发布审查仍未关闭，ReleaseApproved=false。

## 剩余边界

后续已接入三个计算程序集摘要、持久载荷摘要及 `CRS.EvidenceCanonical.v1` 固定编码，结果冻结和限制见 [冻结结果与运行证据](FROZEN_EVIDENCE.md)。完整目标封套、执行二进制归档及严格兼容迁移仍开放。摘要不构成来源真实性认证，也不能阻止掌握全部数据者重新制作快照。

64 MiB 是输入 JSON 的读取上限，不是进程总内存承诺。数据库结果外层 JSON、执行审计 JSON 及序列化过程的全链路资源配额仍需后续完善；不能把这项输入检查宣称为所有持久化数据均有相同上限。结果集合后续已经冻结，AR-10 的旧格式迁移验收仍开放。

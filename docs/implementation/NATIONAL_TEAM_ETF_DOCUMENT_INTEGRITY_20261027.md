# ETF披露原件的统一核验与通知冻结

日期：2026-10-27。状态：源码接线及本地隔离回归通过，正式存储迁移尚未执行。此前持有人候选已有来源/Q15门槛，但部分已审核持仓、可比性、历史回算和通知领取仍可能仅凭文件哈希继承旧确认。本轮补这一缺口，配置池报告发现仍须继续推进。

## 同一证据合同

`AlertStore.DocumentHealth`统一检查证券、URL、原始/保存摘要、来源provider及版本、未解除Q15、登记首见及实际文件。具名持仓的首见还必须等于原件登记时刻，不能把负载中的较早时间当作已知时点。

可比性、已登记持仓、NAV研究、候选读取、人工再确认及历史冻结回算均使用这个门槛。失败保留历史行和数值，但撤去当前`OriginalConfirmed`；未知不填零、不删除历史，也不自动把隔离恢复写成新批准。原始字节恢复但Q15仍Open时仍不放行。

来源记录按128条引用分组、有界参数化读取；同次调用对相同哈希只读一次。总引用和分组匹配行均有限额，未知/歧义来源拒绝继承。核验结果不跨查询缓存，也不在查询中写入恢复或审核状态。逐基金读取不扫无关原件。

## 历史与通知

历史回算继续使用原事件的成员、原口径和原具名披露，只重新核验其原件，不用今天的新披露替代旧输入。当前证据不足时保留Unknown及原事件，不能据此宣告风险解除。

金融通知领取前核验它实际冻结的披露原件；失败写为门槛阻断，显示“原件待重新核验，禁止外发”，不领取租约、不联系提供商。原有M0正式门槛、订阅、结果未知禁止重试及投递审计保持有效。已阻断通知不会因读查询恢复原件而自动重发；需后续合法的新评价/通知条件。

发现解除/撤销通知过去未保存当次输入，因此新增`nt_alert_notification_input`，与事件、变更、Outbox同事务。它独立于原来只保存触发窗口的历史回算，避免把解除窗口当成原触发窗口参与旧回算。普通通知核对本版本冻结输入，历史更正核对其全部原触发快照。旧待发记录缺少可验证的通知冻结输入时保留阻断，不倒造旧证据。

该表以`alert-notification-proof`功能迁移记录管理；未知版本、有登记却缺表、无登记却残留表均拒绝启动，不能自动补成空金融证据。国家队继续普通SQLite，不改变收入/报税加密。此新增持久表尚未在正式Worker执行迁移。

## 页面

历史持仓表增加“原件当前通过核验”和“持有关系已核验”只读列，不能只显示份额而隐藏确认失效。相同配置值的刷新也显式重读原件列表，不依赖ComboBox清空/重选等控件副作用。刷新会清理旧草稿和确认，迟到候选仍不能覆盖当前原件。

## 验证入口与剩余范围

`CRS.Tests.NationalTeamWatch --etf-document-boundaries`使用普通SQLite、合成PDF、正式仓储和独立只读会话；覆盖Q15、来源串件/版本/解析失败、首见绑定、历史回算、领取前门槛、只读无写、无关文件锁、取消、迁移缺损以及跨128引用的批量核验。默认回归和CI包含该专项，远端CI是否实际执行另验。

预警回归额外检查通知冻结证据同事务回滚，以及解除通知冻结实际正常窗口后仍受M0门槛约束。界面专项同时用无控件ViewModel及真实WPF绑定验证同值刷新，不把后台校验通过当作展示已更新。

# 行业相对估值观察雷达：实现与反方审查（2026-10-26）

> 目标：从 CRSTool 已核验的国证行业公布 PE 中，**筛出值得进一步研究的历史低位行业**，不是输出“已被低估”“合理价值”“买入价”或国家队交易方向。以本次 PR 代码和实际 CI 为准，本文不能替代运行验收。

## 1. 当前 main 事实与这次增量

截至本次开发基线 `522fa68ab38db86532e2e745dbd5f11d50660dc3`，项目已有：

- 正式后台的国证 008200、深沪京一级行业 C01～C11 公布滚动加权/中位 PE；原件、哈希、修订审核、交易日历及查询；真实样本已存 261 个交易日（2025-09-19～2026-10-23），不是五年历史。
- 正式行业页面可以比较 11 条公布 PE 走势、单口径加权历史区间分位；另有尚未接真实价格、PB、盈利来源的 `SectorResearch` 领域/UI 原型。
- 已有 `OpportunityState=NotEvaluatedMissingCoveragePbFundamentals`、`TimingProof=NotProven`，必须保留。

本次改动**不新建数据源、不采集额外联网资料、不改变 Worker 调度、不开通任何自动交易**。

- `IndustryPeResearch` 分别计算加权和中位滚动 PE 的前置历史位置与有效正值样本量：只认审核后的已登记资料，排除当日；每一口径前置正值样本≥252，且覆盖已核验的前置交易日≥80%；零、负值、未知、交易日历未核验时不计算。
- `IndustryPePosition` 在两个分位及样本均有效时，才提供五种**研究标签**：双口径历史低位（两者均≤20%）、明显分歧（一个≤20%、另一个≥60%）、仅单口径低位、不满足双口径低位、证据不足。
- 行业页增加两个分位列、历史位置排序、双口径低位筛选、筛选覆盖图表和表格，并清楚披露该筛选尚不等于合理价值。
- 20%、60%、252和80%是**预设研究参数**，仅有最低数据质量合理性，没有收益预测的统计验证；排序只代表下一步研究顺序。
- 报告新增可选字段 `PublishedMedianSeriesPercentile` 和 `MedianPriorSamples`，老 Worker 未提供时维持不可判定，不能通过桌面临时猜测；研究指纹计算版本从 `industry-pe-report-v2` 改为 `v3`，输入与参数归档可复算。这里未宣称完整二进制跨版本兼容验收。

## 2. 反方架构师审查

| 反方质疑 | 失真机制 | 必须采取的处理 | 本次状态 |
| --- | --- | --- | --- |
| 低 PE 就是低估吗？ | 利润周期顶点时分母大，PE 反而很小，随后可能盈利塌陷 | 标签只能是“公布系列历史低位”，绝不叫“低估” | 已强制 |
| 加权/中位两者都低就是两份证据吗？ | 二者共享剔亏样本和财报，相关性高度重叠，并不独立 | 双口径低位仅确认**统计量一致**，不是基本面双重证据 | 已披露；真实基本面待接入 |
| 把不同产业 PE 绝对数横比合理吗？ | 银行与软件的增长、资本强度、会计规则及风险溢价不同 | 排序按各自同方法历史位置，不按 PE 绝对值便宜程度 | 已实现 |
| 样本包含亏损企业吗？ | 国证 PE 方法剔除亏损样本，特别可能低估亏损普遍的行业风险 | 保留剔亏标签；市值覆盖、亏损比例、PB 等缺失一律未知 | 尚不具备完整估值 |
| 历史只有约 261 交易日够吗？ | 满足 252 最低门槛却不能覆盖多次产业周期 | 明示“所选区间位置”，不叫五年分位；长期回补与方法变更再评估 | 短区间可研究，不可决策 |
| 同一行业口径跨期恒定吗？ | 企业调入调出、分类版本和会计变更导致序列漂移 | 固定国证 008200 一级行业、已知方法；跨版本需重建可比期间 | 当前仅固定体系 |
| 历史分位可用于回测择时吗？ | 公开历史现在才回补，财报之后修订，存在未来信息与首次知悉时间偏差 | 保留 CurrentKnowledgeResearch / NotProven；不可声称当年可交易 | 已强制；PIT 历史缺失 |
| 数据越全就一定有信号吗？ | 低价/低 PE 与产业结构衰退、负债扩张可能共存 | 需要 PB、ROE、ROIC、自由现金流、负债和周期供需反证 | 待接入 |
| 是否具备商业分发/自动采集授权？ | 可访问网页不代表许可自动历史抓取或再分发 | 遵守已有来源预算及官方授权界限，不从本 PR 扩大采集 | 保持原限制 |
| 是否一定能识别国家队加减仓？ | 行业估值不等于机构实际持仓/成交，ETF 份额也不等于国家队独家买卖 | 国家队持仓证据链与行业估值分离 | 保持隔离 |
| 老 Worker/UI 会不会把缺字段当低估？ | 旧响应没有中位分位时 nullable 默认为 null | 分类器同时校验两种前置样本、分母、分位和正式状态，否则证据不足 | 已加防线 |

## 3. 对完整“低估”识别的后续建设顺序

### P1：价格、PB、盈利质量事实链（发布前不能冒用当前研究结果）

- 建立**固定行业分类**、生效期、指数价格口径（价格指数或全收益）、币种和复权/分红处理，允许同一共同起点 100；缺日断线，不能补零或偷换起点。
- 确认独立、有许可的数据源与实际字段，取得同一行业的 PB、PE(TTM) 或可解释的公布统计方法、利润覆盖率/亏损比例、市值覆盖、ROE/ROIC、资产负债、自由现金流与净利润周期。上市公司公开报告可作为原始依据，但不能把单公司财报直接平均后冒称官方行业 PE。
- 后台对各来源保存公告日、首次获取、审核/更正、原件哈希、构成证券清单及计算版本；按同一业务快照产出、异常时拒绝得出肯定结论。
- 医药科技等重研发/创新行业增加研发费用资本化、一次性收益、收入质量检查；金融行业主要看 PB/ROE/资产质量/拨备，不能用同样的 PE 条件“一刀切”。

### P1：行业周期差异化反证

- **水泥建材**：产能真实退出、错峰兑现、库存/发运、价格与吨毛利、煤价和现金流；低 PE 需要排查是不是盈利峰值，低 PB 需要验证资产减值和产能退出。
- **轮胎/制造出海**：出口数量与单价、海外产能爬坡、原料/海运成本、反倾销与汇率影响；ROIC 与库存周转不可缺。
- **医药器械**：集采降价、品种毛利、研发管线成功率、合规/治理/现金回款；亏损创新企业 PE 不适用。
- **互联网与消费**：收入质量、资本开支、利润与经营现金流背离、监管/竞争格局；低估值不代表护城河未被削弱。
- **银行保险/资源周期**：PB-ROE、资产质量和利差；资源品采用中周期价格和标准化利润，不在商品涨价顶部用当期低 PE 判“低估”。

### P2：从“观察”升级为可审计的投资研究

制定行业特定权重和候选晋级要求，至少满足：①同口径足量历史 ②盈利质量与资产负债反证通过 ③行业供需没有结构性恶化 ④对合理价值的多情景估算和安全边际 ⑤异行业对照已做会计差异调整。

数据长度建议至少覆盖一个完整产业周期，并在多行业、多市场阶段做**滚动样本外、未来信息隔离、交易摩擦与失效案例**测试。没有这些证据，任何红黄绿灯只能表示“资料/风险/研究优先级”，不能代表预期收益概率。

## 4. 本次代码验收边界

应运行：

```powershell
dotnet run --project tests/CRS.Tests.IndustryPe -c Release -- --output artifacts/industry-pe-checks
dotnet run --project tests/CRS.Tests.SectorResearch -c Release -- --output artifacts/sector-research
dotnet run --project tests/CRS.Tests.SectorUi -c Release -- artifacts/sector-research/synthetic-input.json artifacts/sector-research/sector-ui.png
dotnet build CRS.sln -c Release
```

反方用例应覆盖：加权低/中位不低、双口径低、两口径冲突、零/负 PE、任一口径不足252样本或低于80%覆盖、官方历史数据不足、日历未核、知识截止后修订、旧 Worker 无新增字段、筛选与图表一致、查询失败后不能保留旧结果。

以上检查属于**合成/隔离计算和UI断言**；通过 CI 仍不能声称官方历史代表性、长期来源许可、正式 Worker 升级、稳定在线性能、历史实盘可回测或“真低估”。最终发布仍以真实发行包、独立市场复核及已登记证据为准。

## 5. 可复盘的用户展示规则

展示字段：行业、查询日期、滚动加权 PE / 中位 PE、两种本行业历史位置、各自正值样本量、审核/日历状态、研究标签、报告指纹与知识截止。排序按“双口径低位→明显分歧→单口径低位→其他→证据不足”，不以横向绝对 PE 从小到大排名。

例如，**纯假设**某行业加权 PE 历史位置 7%、中位 PE 68%，只显示“加权与中位明显分歧”，不显示低估；另一行业两种位置均为 12%，也只显示“双口径历史低位（待核查）”，直到独立 PB/盈利/行业供需证据齐备。

正式业务报告继续显示 `NotEvaluatedMissingCoveragePbFundamentals` 和 `TimingProof=NotProven`。不得给用户误导性的“便宜程度分数”或者未经验证的确定性仓位建议。

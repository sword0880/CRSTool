# 独立数据库与备份管理窗口（2026-11-05）

设置中的“数据库与备份管理”改用独立的 `DatabaseBackupWindow` 和 `DatabaseBackupViewModel`，不再以登录窗口承载维护。窗口只显示当前实际打开的数据库位置、创建加密备份和恢复加密备份；没有手机验证码、登录准备提示、进入工作区、手机绑定或登录方式设置。备份目标与恢复来源各用独立的路径和文件选择框。

当前目录来自本次工作区实际打开的位置，不以用户为下次启动另选的目录冒充当前数据库。备份继续通过原有数据库服务生成并验证加密快照，不覆盖已有备份，也不改变当前数据库或启动位置。

恢复表单验证凭证和新主密码后，由应用停止原工作区并关闭旧数据库，再调用既有恢复服务，只恢复到新空目录。恢复成功才保存新的默认位置；恢复已完成但位置保存失败时分别说明。关闭窗口后按正常身份验证流程创建新工作区，未认证时不会开放恢复后的数据。恢复失败保持原启动位置，可重新认证原数据库。

系统锁定时，应用同时关闭独立数据库窗口、取消未完成的备份/恢复并清空密码控件；普通关闭不打断正在执行的文件操作。窗口和模型均不引用登录窗口或登录模型，底层数据库应用端口沿用现有实现。

验证入口：`CRS.Tests.Wpf --database-backup-model` 检查独立备份路径、恢复前关闭原库、恢复后位置保存、失败与取消、凭证清理，并回归原有 TOTP/Windows Hello 登录流程；`--database-backup-ui <目录>` 用合成服务渲染560/760/1040 DIP的真实独立窗口，检查无登录/手机内容、固定关闭按钮、备份接线和系统锁定清理。不打开实际数据库或创建真实备份。

验证结果：Release桌面与WPF验证项目构建通过；独立数据库模型11项及既有TOTP/Windows Hello登录回归通过；视觉规范门禁通过，真实独立窗口完成560/760/1040 DIP及恢复表单底部共4张合成渲染。源码与桌面开发构建已更新，没有打开实际数据库或创建、恢复实际备份。

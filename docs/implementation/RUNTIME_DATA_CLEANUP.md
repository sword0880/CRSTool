# 设置中的运行资料清理

## 后台任务模式（2026-11-06后续交付）

当前设置页只有“提交清理任务”入口和提交确认，不展示扫描进度、预览列表或完成结果。后台固定采用14天日志、当前快照加一份有效历史副本的规则，受理后自行扫描、校验并分批清理。主窗口每10秒读取小型任务摘要，完成、中断及未全部完成通过主窗口提醒；点击“知道了”后已读状态保存到后台。关闭设置、退出前台不取消后台任务，下次启动仍能找到结果，无需前台保留原操作编号。

完整任务和自动清理使用同一执行通道与限速策略；在途任务重复提交返回已有任务，不累积新队列。服务重启后，尚未开始的Queued任务可继续；执行中的任务标记Interrupted，保留统计不完整说明，并由后续按规则重新核对剩余资料。后台任务摘要存于 `maintenance/cleanup-tasks`，最近索引有界，旧任务记录保留用于审计及原编号重试。只有持有服务所有权租约的启动入口执行恢复，只读审计不会修改任务状态。

新端口为 `IDataCleanupTaskGateway`，命令为 `SubmitDataCleanupTask`、`GetDataCleanupTasks`、`AcknowledgeDataCleanupTask`。全部验证实际Windows管理员身份，提交与已读确认使用控制管道；个人任务按SID隔离，自动清理通知供管理员查看并分别确认。客户端不传清理选项、文件路径或删除清单。任务落盘后才响应提交，断线重试继续使用原编号。

下文的手动扫描/预览协议仅为旧客户端及隔离验证保留，当前设置页不再暴露这些控件。发布与验证见[后台清理任务记录](../validation/DATA_CLEANUP_BACKGROUND_TASKS_20261106.md)。

## 当前默认规则（2026-11-06）

后台启动并健康运行5分钟后检查清理计划，之后每24小时执行一次；未完成时1小时后重试，计划持久化，重启不会重新开始每日扫描。默认保留当前维护引用的快照及最近一份完整、可验证的历史快照，同时清理更早的已完成升级副本和超过14天的已关闭日志。损坏、来源不明或未完成升级的副本保留，不能抵扣这一份有效历史副本。

前台不再显示历史副本份数或是否清理旧副本的选项。后台任务复用已有清单、摘要、互斥及审计规则，使用约10%的工作占空比。升级、恢复和卸载脚本先通过管理员控制管道暂停托管任务、记录中断并等待释放维护锁；旧版手动预览操作仍须结束或过期后才能升级。活动插件的数据库、密钥和 `plugins/crs.national-team/raw` 原件不进入删除范围。

设置页栈溢出修复：安全验证方式使用单一状态和显式选择命令，单选按钮只读取状态，避免取消选中与互补属性相互写回。验证详情和安装结果见[自动保留规则验证](../validation/AUTOMATIC_UPGRADE_RETENTION_20261106.md)。下文注明日期的现场盘点使用当时规则，不能当作当前可删数量。

## 扫描与清理进度

用户主动扫描或清理期间，界面每秒刷新已用时，并每秒读取后台状态。扫描展示已扫描文件数、逻辑大小、当前文件或目录，以及校验实际已读取的数据量。总量尚未确定的扫描、删除前校验和整理目录使用活动进度条；逐文件清理时按实际已删除文件数与预览选中总文件数显示确定进度，不将校验阶段当成完成百分比。

后台在枚举文件、读取摘要的每个数据块和删除文件时更新独立状态，不为进度额外遍历资料，也不占用界面线程。扫描状态不再显示“已清理0”。旧后台未提供细分计数时，界面仍显示活动进度及已用时。前台持续跟踪同一操作直至取得最终状态，不再在三分钟后自动结束刷新；每次通信仍有独立超时。点击“暂不等待”或关闭设置只结束前台等待，保留操作编号，之后可查询同一任务，不能重复提交扫描；结束或停止等待后停止计时，迟到回调不能覆盖最终结果。

进度为可选的附加结果字段，原状态构造器、协议版本与已有清理审计保持兼容。所有扫描、校验、保留及清理范围沿用原有规则。新增验证覆盖真实临时资料统计、管道传输、扫描续查、迟到状态隔离、大文件读取计数、清理确定进度和真实WPF活动计时渲染。

2026-11-05验证：Release解决方案构建通过；31项合成资料清理、13项真实Windows管道和17项界面模型检查通过。真实清理视图在640/1040 DIP完成6张合成渲染，并检查了每秒计时、校验阶段活动进度、清理40%和结束收起。代码与桌面开发构建已更新，未替换已安装Worker，未执行正式资料清理；详细后台计数需要配套新版Worker。

## 旧版手动协议使用方式（兼容保留）

日常无需打开前台，后台按上述规则自动执行。需要手动核对时，打开“设置 → 数据管理 → 运行资料清理”，选择日志保留天数，点击“扫描可清理资料”。默认包含旧升级副本，保留一份有效历史副本。预览优先列出将清理的项，各项可展开查看相对路径与原因，未知大小显示“未统计”。

“按预览清理”单独执行，不随“保存设置”触发。需要管理员权限和支持新命令的配套后台；旧后台明确报告不支持，界面不会自行删除后台文件。旧副本清理后，无法再依靠它回退到对应的历史版本。

预览有效15分钟，更改选项或新扫描会使旧预览失效。受理后保留操作编号；断线或停止等待不等于取消后台清理，应点击“查询清理结果”。中断、未知结果及未完整记录的删除数量均不显示为完成；重新扫描会核对剩余项。

## 所有权与执行边界

- `CRS.Common/Maintenance` 只定义固定选项、预览项与结果合同，不接受客户端文件路径。
- `CRS.Application/Abstractions/IDataCleanupGateway` 定义设置端口。桌面 `WorkerDataCleanupGateway` 负责IPC及用户主动操作期间的状态查询；WPF只展示结果。
- `CRS.Worker.Service/Maintenance/WorkerDataCleanup*` 由后台资料所有者执行用途判断、摘要核验、维护互斥、删除和审计，不解密当前库或密钥。
- 新命令为 `BeginDataCleanupPreview`、`GetDataCleanupStatus`、`ExecuteDataCleanup`。全部再次验证实际Windows调用者的管理员身份；执行走管理员控制管道。记录按SID隔离，拒绝路径、重复字段和未知字段。
- 扫描与删除使用独立单操作通道，不占Quartz业务并发，也不长时间持有Runtime全局门闩。状态通过短请求返回。

执行前先落盘清理范围，获取与升级相同的 `maintenance.lock`，核对当前维护记录未变化，再核验所保留的历史副本。旧快照验证完整文件集合和摘要后，先移到本功能专用弃用容器，再逐文件清理；清单最后删除，空目录使用非递归删除。未知文件、链接、摘要变化、维护冲突、占用或取消会保留剩余现场并报告未完成。活动数据和归档维护记录不进入删除集合。

扫描拒绝目录及文件链接并限制文件数量；移动和删除前仍重新检查完整目标。重启发现在途记录时，计数标记为未完整记录，避免把未持久化计数误报为零。

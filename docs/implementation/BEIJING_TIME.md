# 全应用北京时间

2026-10-21：系统内部新建时间点统一由纯 BCL 的 `CRS.Time` / `CRS.Timing.BeijingClock` 产生，直接携带 `+08:00`，不依赖 Windows 当前时区。执行开始/结束/进度、计划和重试、来源预算、采集与证据首见、审计、计算历史及新诊断记录均采用这一入口。桌面直接格式化记录值，最近执行列明确标注北京时间；日志、状态栏、历史任务、插件时间字段及日期控件默认日期同步采用北京时间。

任务计划编辑固定使用北京时间；Worker 打开调度库时把非北京时间计划改为北京时间并增加修订号、重建触发器；Cron 字符串保留，不简化高级规则。手工资金事件假定为所选日期北京时间中午，手工日终估值为北京时间 23:59:59。市场公布的交易日、报告期等日期事实仍是日期；原始券商时区及未知时区标志保留，以免把原始来源事实改造成另一笔交易。Unix 协议时间仍是绝对秒数。

现有协议字段和数据库列的 `Utc`/`_utc` 名称暂不变更，内容的新时间偏移为 `+08:00`。任务中心既有执行、进度、审计、命令创建和退避字段在 Worker 打开库时，与启动恢复共用事务归一为 +08:00，保留原时间点；其它历史记录在仓储/IPC 读取边界保持真实时间点归一；不批量改写已冻结的金融底稿或原始证据。时间筛选、到期判断及排序使用 SQLite 时间值比较，避免旧 UTC 与新北京时间按字符串比较造成八小时错误。

验证入口：`CRS.Tests.Background --beijing-time` 检查 SQLCipher 中原始字段的 +08:00、进度/重试、跨日与混合偏移排序；`CRS.Tests.Wpf --beijing-time` 检查原值格式化、空结束时间和固定北京时间 Cron 预览。构建会自动同步 Debug/Release 开发插件。安装中的 Worker 需更新到本次构建后，才会按新口径写入新记录；桌面 IPC 可以读取旧服务的显式偏移时间。

本轮验证：全解决方案 Release 0 警告/0 错误、VS Debug 构建、北京时间专项、既有 Cron、执行结果分页筛选、状态栏、后台存储故障、绩效领域 32 项冻结回归、绩效 SQLCipher 集成、预警专项和国家队离线 301 条 PASS 均通过。架构/项目图门禁通过；金融冻结夹具未改写。记录位于 `artifacts/beijing-*.log`。还原使用本机缓存；NuGet 漏洞源不可达时仅在本轮还原命令临时设置 `NuGetAudit=false`，未修改仓库审计配置。离线管道回归在允许创建隔离命名管道的环境中运行，不访问安装服务；本轮未更新安装中的 Worker。

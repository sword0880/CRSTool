## 当前任务与执行记录

任务中心将执行中任务、插件内排队任务和尚未进入队列的持久请求分开展示。“当前任务”按活动快照刷新；持久待执行总数可能包含已排队请求，不能与排队数直接相加。

执行记录采用北京时间开始/结束日期，默认当天，按执行开始日期包含首尾。只有“查询记录”读取记录；切换页签、编辑筛选、刷新服务健康、管理任务和底栏直达不会自动查询或覆盖历史结果。较早版本的“最近执行每3秒刷新”和“今天”按钮已经被此交互替代。

日期、插件、任务与异常条件由后台在分页前筛选。客户端完整读取后统一应用，核对日期、游标、快照和重复记录；失败、取消或超过4096条时不显示半份结果，提示缩小范围。整段历史查询保持有界等待；当前待执行请求是当前状态，不随历史天数重复累计。

## 手动运行与未知结果

首次手动请求不继承定时计划的退避时间，仍遵守任务串行、全局额度和来源冷却。已经尝试并返回`RetryDeferred`的请求继续使用原参数和原重试期限，不因刷新或恢复循环无延迟重跑。

受理后断线保留原请求身份；“确认上次请求”沿原ID核对。待执行没有执行开始时间，不能伪造执行历史；`UnknownExecution`或历史被清理不等于执行成功或已取消、执行从未发生或业务没有生效。

旧服务缺少可选状态字段时显示未提供。服务不可用时保留带采样时间的旧快照并明确标识，不能将查询失败解释为空闲或零任务。

## 执行日志与计数

日志绑定稳定执行ID，不追随同名任务的新执行。执行中定期只读刷新，终态停止计时和刷新；关闭窗口、锁定或取消父会话后停止。支持选择复制、滚动、回到开头和跳到末尾，底部操作保持可达。

阶段由宿主分配时间和序号，只接受固定阶段名与标量。每次执行保存最近512条，单次查询返回最近128条；缺少更早阶段时明确说明，旧执行未保存的过程不能补造。诊断不记录完整URL、请求参数、业务原文、密钥或原始异常正文。

| 数据链 | 计数含义 |
| --- | --- |
| ETF份额 | 收到行数、新增接受事实、同值重复、新增待审修订分别计算；待审不是接受 |
| 市场成交 | 实际收到、复用、核验休市、空响应、尚未请求待重试和来源问题分别计算 |
| 旧日志 | 未记录的字段显示未知，不根据附近阶段推造业务计数 |

HTTP响应头不等于正文校验通过；解析行数不等于池内提交数；区间结束不等于全部来源成功。不同来源按既有事务提交，后续失败不抹去先前成功事实。最终终态以持久回执为准，阶段停滞本身不能证明死锁。

## 验证入口

WPF：`--task-center-refresh-checks`、`--task-center-deeplink-checks`、`--task-button-checks`、`--shell-status-checks`、`--market-log`和`--execution-log-ui`。后台日期过滤、阶段落盘、断线取消及读取隔离由相应隔离专项覆盖；完整参数见[测试说明](../../tests/README.md)。

只读实际执行日志不触发采集；现场采样只说明采样时状态，不证明长期覆盖。通信、查询取消和诊断阻塞的实现边界见[查询与IPC](QUERY_PERFORMANCE.md)。

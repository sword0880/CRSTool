## R06：移除隐式空实现，启动核验必需能力

市场仓储的 66 个方法分到 11 个明确端口：ETF 读取/写入、采集记录、成交统计读取/写入、
直接持股读取/写入、预警读取/写入、完整性维护和单连接操作。全部要求实现方显式实现，
不再默认返回空集合、null、false 或运行时 NotSupportedException。`IMarketRepository`
保留为组合根的完整存储族契约；披露、预警及成交统计用例的读取和写入分别依赖窄端口。

正式后台入口在初始化期间调用 `MarketRepositoryCapabilities.Validate`：核对独立读取、
有界证据、总览及完整性巡检能力，并真实打开一次独立只读事务。缺失能力、只读连接错误或取消
在作业开放前失败；失败释放已打开的仓储。核验不联网、不扫描全库原件、不修改业务事实。
它证明接口能力与读取接线，不替代新提供方的加密、迁移、备份和事务一致性验收。

慢查询界面测试改用真实存储的显式代理，覆盖结果仍为可控合成响应，不再依赖残缺仓储默认实现。
本轮没有新增数据库类型；保险库存储族仍是已有完整必需契约，未拆散其认证/事务/备份一致性边界。

验证入口：国家队 `--repository-contracts` 5 项；WorkerETF `--storage-providers` 11 项，
包括真实后台 StartAsync 拒绝能力缺失及连接释放。国家队完整离线回归通过，包含旧覆盖查询不能
覆盖新证券/新日期输入的界面竞态验证。

## R07：年度状态只使用北京时间

`CalculationService` 从注入时钟取得 UTC 时间，经 `BeijingClock.Read` 转为 +08:00 后判断年度。
历史重放继续使用冻结的 Provisional，不重新推断。税额、FIFO、汇率及金融冻结期望值不改。

应用默认回归增加 12 项检查：北京时间新年前一个 tick、整点和后一个 tick，主机时区分别为
UTC-12、UTC、UTC+14；检查临时状态、当前年度、金额不变，以及前后跨年双向重放状态冻结。
应用默认回归通过，并纳入 WPF PR 工作流。

## R08：仅推进内部持久授权边界，发布门槛仍 Open

新增 `DurableRecoveryExportCoordinator` 和 `RecoveryExportJournal`，将既有内部一次性授权会话
接入真实 SQLCipher 持久索引。使用独立 HKDF 域派生审计库密钥，保留原 ServiceKey 的 DPAPI、
账户 SID 和服务 SID ACL 约束。调用方仍必须持维护/数据租约、验证全树 ACL、提供真实认证身份，
并绑定已经停写核验的完整快照；此组件不能证明这些前置条件已经成立。

- 准备 ID、确认 ID 和包 ID 持久防重放；先持久消费再读原钥。授权和封装审计须提交后才可返回密文。
- 同目录独占协调器，全局最多 4 个待确认会话，每 SID 最多 1 个；沿用两分钟单调期限。
  持久索引最多 1024 次准备，不自动删除旧编号腾容量；达到上限拒绝，尚无安全归档/代次切换工具。
- 重启将 Prepared/Consuming/Authorized 持久转为 Abandoned，记录固定分类审计；旧挑战不恢复。
  Sealed 只保留“封装完成”事实，不能表示备份已交付、已认证打包或可恢复。
- 身份不符、未确认、取消及过期记录拒绝；正常销毁取消剩余会话。审计故障不返回封装、锁定本协调器，
  并触发调用者提供的存储故障回调。正式调用者仍须把该回调接入 Worker 停止新任务的故障流程。
- 初始化标记和索引必须同时存在；丢失索引、错误密钥、损坏/未知版本失败关闭，不初始化替代空库。
  没有写出主密钥、恢复秘密或挑战；测试子进程只通过私有标准输入接收测试密钥。

这仍是内部协调组件，**没有注册生产 IPC/CLI**，也没有新建正式审计库。尚缺源机显式认证入口、
安全独立凭据交付、停写/排空与维护租约交接、全业务文件认证加密打包、目标实际服务身份重封装、
全部 SQLCipher/Schema/原件只读核验及显式激活事务。干净双 Windows 机器和真实服务身份演练未做，
P0-02 / ARCH-005 继续 Open，ReleaseApproved=false。

验证入口：后台 `--recovery-export-persistence` 36 项通过，真实加密文件、并发确认、跨重启防重放、配额、
审计写锁故障、索引丢失/未知版本，以及 Prepared、Authorized、Sealed 三个持久阶段的真实子进程强杀。
原 `--recovery-export-authorization` 126 项和 `--service-key-recovery` 345 项继续通过。
这些检查证明本机内部授权持久化，不证明跨机恢复成功。

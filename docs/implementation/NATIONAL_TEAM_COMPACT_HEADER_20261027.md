# 工作台顶栏与紧凑页头

日期：2026-10-27。用户两张现状截图显示：顶部空白、菜单在内容区另占一行，再叠大标题、说明、长状态和操作栏，压缩表格及图表高度。本轮沿用原生WPF与品牌资源。

## 调整

1. 菜单上移适合当前布局。宿主提供通用`IPluginShellHeader`，菜单通过`TitleBar.Header`进入正式交互区域，只占所需宽度；系统按钮由标题栏模板预留，剩余区域继续支持拖动。宿主不引用具体业务插件。
2. 工作台移交同一个菜单实例，正文不保留重复菜单；独立打开仍有本页导航。切换插件、返回普通页和锁定时清空顶栏引用，再恢复原页面所有权。
3. ETF页使用20DIP小标题与单行状态。完整状态和研究口径可展开，状态也可悬停查看；日期、采集、刷新及取消合并为紧凑工具栏，窄窗口允许换行。缺失、异常和待核验状态没有改成成功或零。

`BeijingTime`迁到`CRS.Common/Time`，使用`CRS.Timing`命名空间；直接格式化和缺时区保留语义不变，读入归一化仍由`BeijingClock`负责。WPF绑定适配器`BeijingTimestampConverter`继续留在Plugin.Wpf，Common保持纯BCL。

## 用户反馈后的原生命中修复

用户现场报告菜单看得见但无法点击。旧实现将插件菜单作为`TitleBar`的同级覆盖层；`WindowChrome.IsHitTestVisibleInChrome=true`不能阻止WPF-UI 4.3.0标题栏自身的`WM_NCHITTEST`钩子把这块矩形判为`HTCAPTION`。其[上游命中实现](https://github.com/lepoco/wpfui/blob/4.3.0/src/Wpf.Ui/Controls/TitleBar/TitleBar.cs#L636)只识别`Header`、`CenterContent`和`TrailingContent`中的交互内容。

已将`PluginHeaderContent`移入`TitleBar.Header`，保留同一个插件菜单实例和原所有权交接。新增`--plugin-header-native`使用真实`FluentWindow`及其标题栏原生钩子；修复前菜单中心实测返回2（拖动区），故障日志为`artifacts/plugin-header-native-before-20261027.log`。旧测试将内容取出放入普通Window，并通过Invoke调用按钮；它只能证明事件处理，不足以证明原生鼠标命中，这一历史验证范围据此更正。

按用户要求，工作台全局“研究说明”按钮与声明面板已移除；对应页面的资料缺失、未审核、份额不能归因具名机构等具体数据说明保留。导航测试同时检查按钮与空声明面板均不存在，不增加替代弹窗。

当前调试进程占用Debug输出，直接Debug构建因此失败并留下文件占用日志；没有停止用户程序或调试器。后续使用独立Release构建验收，当前运行窗口需重新启动后加载新代码。

修复后原生命中8项通过：1040/1280 DIP菜单中心均返回1（客户区）、菜单可展开并选择、空白区仍返回2以支持拖动、离开插件清理引用。既有壳交互25项和分类导航27项通过；移除集中声明后的9张工作台与2张弹层渲染通过。最终38项目Release零警告/零错误，两个开发插件包88份文件摘要核对通过。隔离窗口不等同于用户仍在运行的旧调试进程已更新。

验收CLI同步改为拒绝未知专项参数，防止尚未重新构建的旧验证程序不认识新参数、转而执行默认套件并返回0，造成新的验证项目假通过。

## 首次点击的焦点竞争

旧导航由两个独立Button及ContextMenu组成，打开时手动聚焦子项，关闭时又无条件聚焦所属按钮。分类切换中，旧弹层关闭回调可能干扰新弹层的焦点；这一代码风险与用户报告一致，但没有连续捕捉到用户首次鼠标点击的完整过程，不能据此宣称现场原因已唯一确定。

共用导航已改为同一个WPF原生Menu中的MenuItem，保留品牌样式、选中态、路由和F4入口；分类切换、方向键和Esc由原生菜单模式管理，移除弹层关闭时强制抢焦点的回调及旧ContextMenu样式。不增加正文高度或新的说明按钮。

真实MainWindow的合成隔离验收取得前台窗口句柄后，1040/1280 DIP的18项检查通过，包括首次展开、向下进入子项、分类往返、Esc返回当前分类、快速连续切换和原生命中。日志：`artifacts/plugin-native-menu-checks-20261027.log`，标记`FocusVerification=Verified`。分类导航27项、9张工作台和2张原生菜单弹层渲染通过；已查看1040 DIP/100%工作台及资金菜单图片。上述交互使用自动化展开和路由按键，仍不等同于用户真实首次鼠标点击或旧调试进程已经更新。

若执行桌面没有真实前台窗口，常规`--plugin-header-native`仅验证命中及菜单操作，并明确输出`FocusVerification=Unavailable`；独立严格入口`--plugin-menu-focus`此时返回退出码2，不能记为焦点验收成功。`--plugin-header-focus-preview`只提供五分钟合成窗口观察，不执行自动断言。不启动正式插件、后台查询或个人保险库。

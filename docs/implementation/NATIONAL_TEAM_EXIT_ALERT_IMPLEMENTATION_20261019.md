## 用户确认的组件边界

邮件发送属于公共通知能力，不能直接堆在`CRS.Worker.Service`或国家队插件中。新增独立`CRS.Notifications`公共组件，不引用Worker、WPF、业务插件、税务或保险库。公共组件负责SMTP校验、TLS、受保护邮件配置及发送结果；Worker只负责组合根装配、IPC授权和现有调度。业务插件保留风险事件、事件与Outbox同事务、投递状态及业务幂等，不保存SMTP口令。

用户进一步明确后续可能切换钉钉或微信：公共接口采用`INotificationChannel`、渠道注册表`NotificationDispatcher`、渠道中立`NotificationEnvelope`和统一结果状态。渠道ID/配置Profile独立于业务事件；Outbox按事件变更版本、渠道和Profile分别去重并记录投递。邮件仅为首个适配器，未来添加钉钉/微信适配器不修改预警计算和事件模型。渠道未安装、不可用或失败均不自动改用邮件。钉钉/微信的实际连接与配置界面尚未实现，不列为已支持渠道。

公共契约的路由、Profile、重试及扩展约定见[公共通知渠道边界](../architecture/NOTIFICATION_CHANNELS.md)。公共接口明确区分受理、拒绝、可安全重试和受理结果未知；无效消息在外发前拒绝，适配器异常或串单结果不能记作成功。

系统设置通过应用用例和受限IPC配置邮件。默认关闭，保存不自动发信；测试邮件仅由用户显式点击。已保存密码不返回桌面，空值保持、明确清除；配置有修订号。SMTP强制STARTTLS或直接TLS并保持证书验证，服务受理与用户送达/已读分开表示。提交后的连接中断记为结果未知，不能假称恰好一次发送。

## 正在实施的业务能力

- 数据质量、ETF异常流出、机构最低净减少证据三条车道分离。
- 1/5/20交易日窗口独立校验，不填零、不跨缺口；不相加不同ETF份额。候选阈值保留版本，不称为已验证策略。
- 份额可比性和管理人/基金标识独立核验，不从基金名猜测；同一基金不同类别不重复计入集群。
- 具名机构基准份额使用严格公布/首见时间、独立主体和单位口径，匿名账户不因数量匹配升级具名。下界只描述相对披露基准日至少净减少，不描述单日交易。
- 事件生命周期、修订更正、缺失不解除、持久Outbox与WPF事件中心沿现有插件和唯一Worker实现；不新增服务或Quartz。

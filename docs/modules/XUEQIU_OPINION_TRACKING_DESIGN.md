# 雪球观点追踪设计（当前实现基线）

更新日期：2026-11-26

## 1. 目标与范围

只跟踪用户明确指定的雪球作者公开发言。系统从发言中识别股票名称或代码，按股票聚合展示；点击股票后查看提及该股票的原帖、作者和发布时间。观点方向由规则候选及人工核对辅助，不把股票提及直接等同于看多或看空。

本阶段不建设全网资讯平台，不接入 Google Alerts、Google RSS、RSSHub、Google News、交易所公告或其他外部订阅源；不做自动交易。

## 2. 数据采集链路

1. 用户在观察名单添加雪球主页链接或数字账号 ID。
2. Worker 通过 `XueqiuPostApi` 读取该作者公开动态时间线。
3. 每条动态规范化为雪球原帖 URL，并校验 URL 作者 ID 与当前观察作者一致。
4. 通过雪球原帖详情 API 核对正文和发布时间；无法取得完整正文时保留已取得的线索片段，并明确显示正文状态。
5. 对正文和片段识别股票名称、代码及多空措辞，按股票归类；最终观点由用户核对和录入。

发现动态与核验正文使用雪球 API，不通过外部 RSS 补充。公共 `CRS.Feed` 是独立的通用基础库，雪球插件不引用它。

## 3. 页面交互

- 页面标题、股票搜索、时间范围、作者筛选、刷新、设置作者和发言线索入口放在同一顶部行，减少纵向占用。
- 股票矩阵按 A 股、港股、美股分组。
- 明细视图固定为「原帖提及」，不再提供最新观点、历史时间线、待确认等切换项。
- 明细保留作者、北京时间、内容片段和原帖入口；选择记录后可查看已核验的原帖正文。
- 作者设置只保留添加、编辑、暂停、恢复和移除等必要操作。

## 4. 网络与可靠性

- 采集任务沿用任务中心配置的直连或 Mihomo 节点；不维护单独的 RSS 代理设置。
- HTTP 429 按服务端提供的重试时间退避。
- HTTP 567 暂停雪球 API 请求 6 小时。
- 分页读取发生中断时，已成功取得的页面先落库，失败页不推进完成基准。
- 新作者默认回补最近 30 天；回补过程保存页码和重叠锚点，支持任务重启后续跑。
- 不把 API 空结果、部分读取或访问失败解释为作者没有发言。

## 5. 数据与迁移

- Core 保存作者、股票、观点、原帖线索和正文版本模型。
- Jobs 使用独立 SQLCipher 数据库 `opinions.db`，不将个人研究正文写入公共调度库。
- 迁移保留现有作者、手工观点、已发现原帖和正文历史。
- 数据库版本 18 清理旧版 Google Alerts、Google 账号、RSS 代理和 Feed 覆盖状态表，并重新序列化作者资料以移除旧 Feed 地址字段。
- 共享 `CRS.Feed` 项目保持独立，不因雪球模块移除 RSS 而删除。

## 6. 验收重点

| 范围 | 验收条件 |
|---|---|
| 作者管理 | 添加、暂停、恢复、移除和修订冲突检查正常 |
| 动态采集 | 仅访问观察名单作者；原帖 URL 作者归属校验正确 |
| 分页与回补 | 部分页先保存；30 天回补可跨页、可重启续跑 |
| 正文核验 | 区分 API 全文、网页核验、片段和访问失败 |
| 股票聚合 | 股票提及按市场、股票和作者正确归类，不将提及直接计作观点 |
| 网络退避 | 429 按 Retry-After；567 暂停 6 小时；代理线路沿用任务设置 |
| 页面 | 顶部控件同一行；明细固定「原帖提及」；无 Google/RSS 入口 |

自动化验证入口：`--xueqiu-private-data`、`--xueqiu-timeline`、`--xueqiu-backfill`、`--xueqiu-original-page-fixture`。

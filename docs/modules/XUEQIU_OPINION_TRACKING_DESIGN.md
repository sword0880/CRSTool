# CRS 雪球观点追踪插件方案

评审稿 · 2026-11-20

## 1. 目标与范围

在 CRS 增加独立插件 **「扩展工具 → 雪球观点追踪」**。用户指定要关注的作者后，可以按股票查看他们最近谈过什么、为什么这么看、观点后来怎样变化，并把其中值得核实的问题加入研究清单。用原帖链接和发表时间串起每条观点，方便回看上下文。

| 阶段 | 交付内容 | 启用条件 |
| --- | --- | --- |
| 首版 | 作者观察名单、手动导入、规则识别、人工标注、行业与股票横向矩阵、个股观点明细、观点时间线、待核实问题 | 使用自己的研究笔记或有权处理的材料。未配置 AI 时也能完成整个流程 |
| 自动追踪 | 定时拉取新动态、手动补采、同步状态、更新或撤回记录处理 | 获得覆盖博主动态的授权数据源，确认采集、留存和展示范围。AI 处理单独确认 |
| 个股研究 | 引用有权使用的公告、财报等资料，记录待核问题的核实结果 | 先验证用户能从追踪结果中稳定找到有价值的研究问题 |

首版以能取得授权的文字主帖为主要输入，转发只拆解作者自己写的附言。评论串、纯图片和视频留到后续按样本价值决定。手动批量导入可验证分析流程，持续自动追踪则依赖授权源。

## 2. 数据来源与使用范围

雪球现行服务协议分别约束未经授权的自动化采集和未经同意将平台或用户内容提供给 AI。本方案尚未确认可直接接入的官方博主动态 RSS 接口。接入前核对来源授权允许的账号范围、可取字段、历史跨度、更新频率、留存期限和可用处理方式。RSSHub 等第三方路由只是技术适配，不代表雪球授权；若数据源仅授权采集和展示，保留人工标注与规则识别。 [雪球服务协议](https://xueqiu.com/about/terms)

首版允许用户录入自己的观察笔记，或导入来源与权限明确的文本。原帖链接用于定位和人工回看。能保存的证据按来源权限保留必要摘录或段落位置，其他场景记录链接、时间和用户自己的笔记。页面明确标出来源、导入时间和已记录范围。手动导入显示实际记录覆盖的日期，自动同步按来源返回的范围显示覆盖与缺口。

## 3. 用户操作与页面

1. **观察名单。** 在插件内管理作者。通过雪球主页链接或账号 ID 添加作者，可修改显示备注、暂停、恢复或移除。作者以平台账号 ID 为准，同一账号只保留一条，改昵称后仍关联已有记录。
2. **上方行业与股票矩阵。** 行业作为跨列标题，每只股票占一列，下面两行分别显示看多和看空的作者人数，数字配以浅红、浅绿底色。股票可横向滚动，左侧「行业、股票、看多、看空」保持可见。默认最近 30 天，可切换近 7 天，按作者、证券市场和行业筛选，或搜索股票名称与代码。暂无行业分类的股票归入「未分类」。
3. **下方个股观点明细。** 点击股票后，高亮上方整列，下方显示选中的股票名称、实质讨论帖数、看多及看空人数。明细表采用「多空、作者、时间、内容、原链接」五列，正文合并展示观点、理由及适用条件。每位作者以所选范围内最新一条已确认的明确观点归组，同一作者只计一次。早期观点从时间线查看，中性与待确认记录可单独查看。明细可纠正证券归属、作者归属和观点方向，汇总人数随确认结果更新。
4. **待核实问题。** 从观点中选出可验证的问题，记录具体查什么、参考资料和核实结论。例如「订单增长是否带来回款改善」可以对应后续财报的应收账款和经营现金流。用户确认后加入自己的研究清单。

## 4. 股票识别、拆解与排序

**识别标的。** 优先用明确的市场和证券代码，再用证券全称和常用简称匹配。证券键使用「市场 + 代码」，覆盖 A 股、港股、美股的目标样本。遇到跨市场同名、昵称多义或只提行业时，进入待确认列表。一个帖子可以谈多只股票，每只股票分别落到自己的证据段。

**规则提取候选。** 以证券代码、名称和所在段落定位相关发言。来源有明确的转发、引用和原创字段时，用这些字段区分发言归属。规则可以提示「看好」「暂时观望」「等季报确认」等明显表述，并带出对应句段。多只股票共用一句话、转述归属不清或缺少上下文时，先标为待确认。

**人工确认观点。** 用户确认证券和说话人，区分实质讨论与顺带提及，按需补录立场、依据、条件和证据位置。立场可取正向、负向、中性或不明确。明确自述的持仓或交易单列。仅确认了提及标的的股票也可在矩阵中点选，其待确认观点可在下方查看，确认方向后计入对应人数。

**AI 辅助拆解。** 用户开启后，可对符合 AI 使用范围的材料生成观点草稿，帮助归纳长文、跨段理由和隐含条件。草稿沿用同一字段结构并附证据位置，用户可确认或纠正。关闭 AI、调用失败或材料的授权范围仅支持人工处理时，按规则提取和人工确认流程处理。

**识别变化。** 按同一作者、同一证券比较当前与上一条可核对的实质观点，标记「新增依据」「新增或调整条件」「明确转向」。每个变化指向前后两条证据。更新条件、转述别人、或近期缺少新发言时，最近明确立场按证据所支持的结果展示。

**决定研究顺序。** 行业内优先展示近期有明确转向、实质性新依据或新条件的股票，其次按窗口内实质讨论帖数和最近实质发言时间排序。每只股票在同一原帖内最多计一次，重复导入、帖子修订和纯转发均按各自类别处理。个股明细可展示排序依据。持仓状态仅来自明确自述或另行核实的资料。

## 5. CRS 实现结构

- **桌面插件。** 通过现有 WPF 插件契约注册页面。桌面提供观察名单、导入、查询和人工纠正界面，经本机授权接口向 Worker 提交操作。复用 CRS 既有样式与插件入口。 [插件架构](../architecture/PLUGIN_ARCHITECTURE.md)
- **分析流程。** 把来源导入、证券匹配、观点提取和个股聚合做成可分别执行的步骤。模型输出需通过字段校验和证据位置核对，再进入汇总。按帖子版本和分析版本记录结果，失败后可按条重跑。人工纠正独立保存并优先应用，新版本的相关证据发生变化时标记重新复核。
- **可选 AI 接入。** 先验收规则与人工流程，再用相同样本评估 AI 能节省多少标注时间。若引入 CRS 已配置的模型，由宿主提供受限的分析调用。现有插件上下文没有直接的模型调用能力。若需在桌面关闭时运行 AI，再设计 Worker 的调用权限与凭证存取。 [插件宿主契约](../../src/CRS.Plugin.Abstractions/Contracts.cs)
- **后台同步。** 每位作者单独配置一个 RSS / Atom / JSON Feed 地址，由 CRS.Feed 负责抓取、解析、ETag / Last-Modified 和资源限制，现有 Worker 任务体系负责调度与并发。插件在保存线索前再次核对作者账号与原帖 URL，单个来源失败不阻断其他作者。未配置来源的作者跳过；304 只表示 Feed 未变化，空列表不代表没有发言，覆盖范围始终标为未知。RSSHub 用户动态路由可作为可选来源，建议自建实例或使用有权使用的数据源。旧 Google Alerts Feed 不迁移，升级保留已发现线索并重置旧覆盖状态。 [Feed Engine 规范](../architecture/FEED_ENGINE.md) · [Worker 运行方式](../implementation/WORKER_RUNTIME.md)

### 独立数据库

使用插件专属的数据库文件，存放在 Worker 为该插件分配的数据目录，沿用宿主的数据库版本目录、迁移和恢复机制。观察名单、导入笔记、来源覆盖、帖子与版本、证券匹配、观点证据、人工纠正、待核实问题和同步进度均归插件库。CRS 任务中心继续通过现有调度库保存计划和执行记录。插件与税务、绩效及国家队研究库分别维护，便于单独升级、备份和恢复。 [插件存储与升级架构](../architecture/PLUGIN_ARCHITECTURE.md#6-插件升级跨文件切换无法靠单个sqlite事务解决)

首版支持私人研究笔记，建议用 **SQLCipher** 加密插件库，使用 Worker 为本插件派生的专属密钥。Worker 负责维护数据库，桌面通过本机授权接口查询和提交更改，这一分工从手动导入阶段开始。导入正文、私人笔记和分析结果保存在插件库，任务执行记录只记录状态及必要摘要。 [Worker 插件存储契约](../../src/CRS.Worker.Abstractions/Contracts.cs)

授权原帖按「平台 + 帖子 ID」去重，手工材料使用导入标识和内容指纹。保存同步批次时，把数据和对应进度放在同一数据库事务内，便于中断后重试。插件升级前创建一致性快照，迁移失败按宿主恢复流程处理。恢复时检查观察名单、人工纠正和证据引用能否正确读回。

## 6. 效果验证与验收

从首批观察名单选 **3–5 位有可用材料的作者**，验证其近 30 天的样本。准备人工标注，覆盖常见代码、跨市场同名、多股票长文、转发、前后观点变化和少量疑难表达。用其中一批调整规则，其余样本留到正式对照。首版指标为评审建议，样本量与目标线在试点开始前确认。

| 验收项 | 验证方式 | 建议目标 |
| --- | --- | --- |
| 股票识别 | 以「帖子 × 证券」为单位。精确率是系统确认的匹配中正确的比例，召回率是人工确认的匹配中被系统正确找出的比例，另记待确认比例 | 对照样本中，明确代码和标准名称的匹配精确率 ≥95%，召回率 ≥90%。歧义样本独立报告 |
| 无 AI 流程 | 在未配置模型的环境中导入样本、核对证券、补录观点和依据，并点选对应股票 | 完成从导入到证据回查的全过程，人工确认结果可保存并重新读取 |
| 横向矩阵与明细联动 | 横向滚动并切换行业、日期和作者筛选，点选不同股票，核对高亮列、看多看空人数和明细。用方向反转、中性和转述样本验证归属 | 横向滚动时左侧行名固定。下方五列明细对应当前股票，人数与上方一致，同一作者只计入最新明确方向 |
| 观点可核实 | 抽查正负立场、观点变化与转发归属，核对原帖链接或对应的授权材料 | 展示的每条明确观点均能定位证据。验收样本中，转发误归为本人观点及无证据的持仓结论为 0 |
| 研究效率 | 同一研究任务分别用原始发言和插件完成，记录找出重点股票及待核问题的用时，再人工比较遗漏 | 中位用时比人工翻帖减少至少 30%，并记录漏掉的重点观点及原因 |
| 观察名单配置 | 验证首次预置、追加作者、同 ID 去重、暂停和恢复，再用手工修改后的名单和空名单验证重启及升级 | 名单及状态按保存结果生效，已移除的预置作者不会再次出现 |
| 独立数据库 | 单独运行插件库迁移、备份和恢复，模拟插件库无法打开 | 恢复后可读回观察名单、人工纠正和证据。数据库故障可在插件内定位，CRS 主程序仍可使用税务、绩效和其他插件功能 |
| 异常恢复 | 重复导入、纠正后重跑、模拟解析失败与帖子修订。自动阶段加测断点续采、限流和来源缺口 | 帖数不重复，已确认的纠正保留，错误和覆盖缺口能在页面确认 |

预计收益主要来自按股票聚合、压低重复信息和快速定位原帖。观点质量仍取决于来源覆盖、作者写法和证据完整度。先验收 **「能否更快找出两三只值得深挖的股票，并解释为什么」**。试点通过且授权源就绪后，优先补上自动追踪，再评估接入更多个股资料的价值。

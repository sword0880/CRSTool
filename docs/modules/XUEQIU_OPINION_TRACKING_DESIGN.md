# CRS 雪球作者股票观点追踪方案

> 设计基线为 2026-11-23，供后续代码实施、迁移和验收使用。
>
> 功能入口为「扩展工具 → 雪球观点追踪」（`crs.xueqiu-watch`）。

## 1. 目标和交付范围

用户在 CRS 添加或移除要跟踪的雪球作者，CRS 自动同步对应 Google Alerts 提醒与 RSS 地址。Worker 定时发现原帖，优先获取有权使用的完整发言，从发言中识别股票及作者对每只股票的多空观点。桌面首页按股票名称展示，点击股票可查看各作者的发言、方向、证据和原帖。

| 需求 | 交付内容 |
| --- | --- |
| 部分功能使用 VPN 线路联网 | 系统设置统一保存订阅，Worker 任务和 AI 模型各自选择节点，开源 Mihomo 执行代理。 |
| 自动管理 Google Alerts 订阅 | 连接 Google 账号后，新增作者自动创建 RSS 提醒，移除作者自动删除对应的 CRS 托管提醒。 |
| 订阅作者并按股票查看观点 | 按雪球账号订阅，自动提取股票候选，按股票聚合，可查看作者多空发言、原文和时间线。 |
| 尽可能取得完整发言 | Google Alerts 负责发现。正文经验证后才标为全文，并标明来自自动获取还是手工导入。暂时拿不到全文时，展示已取得的片段和原帖入口。 |

沿用现有插件、观察名单、任务中心和加密数据库。本期范围为指定作者的公开普通发言、长文及转发中的本人补充。评论区、全站发现、通用 RSS 管理和自动交易均在本期范围之外。

## 2. 从订阅到个股详情

1. 首次使用时，在「观察名单」连接 Google Alerts，由用户在 Google 页面登录并选定账号。之后在 CRS 输入雪球主页链接或数字账号 ID 即可添加作者。
2. CRS 按账号 ID 生成搜索条件 `site:xueqiu.com/{账号ID}`，自动创建 RSS 提醒并保存地址。移除作者时立即停止本地采集，并自动删除该作者对应的 CRS 托管提醒。观察名单显示同步结果和单作者试跑入口。
3. Worker 加载各作者的 Feed，校验原帖归属，归并重复结果，补充可用正文并记录来源状态。使用现有「发现雪球发言线索」任务，用户可手动运行或在任务中心设为定时计划。
4. 系统按证券代码、名称和别名提取股票，并为每只股票生成各自的观点候选和证据。能够确认的股票自动关联。股票或观点存疑时，用户可从「发言线索」核对、补录或修正。
5. 首页显示股票名称、代码、看多和看空作者数及最近发言时间。点击股票，下方显示作者发言，可切换「最新观点」「历史时间线」，并按作者、时间、市场、行业、股票名称或代码筛选。个股详情支持按观点方向筛选。

数字账号 ID 是作者唯一键，昵称变更时保留历史。复用代码中的九个默认观察账号，只用于初始化。保存过的观察名单以用户配置为准，包括主动清空的名单。暂停或移除后停止该作者的新同步，历史按用户选择及来源许可保留。

## 3. 发现原帖和获取全文

### 3.1 从 CRS 自动同步 Google Alerts

CRS 观察名单是同步依据。以「关联的 Google 账号 + 雪球作者 ID」为同步键，每个作者保留一个订阅绑定。

| CRS 操作 | Google Alerts 同步及本地状态 |
| --- | --- |
| 添加作者 | 按作者 ID 自动创建提醒，设置 RSS 投递，取得 Feed 地址后启用 Worker 采集。重复添加或重试复用已经确认的绑定。 |
| 暂停 / 恢复作者 | 暂停仅停止本地采集，保留远端提醒。恢复时重新使用已有地址。 |
| 移除作者 | 立即停止本地采集。按创建时记录的远端标识自动删除 CRS 托管提醒，核对远端状态后解除绑定。保留历史。 |
| 已存在同查询的外部提醒 | 对可用的 RSS 提醒复用现有地址，记录为外部订阅。移除作者只解除本地绑定。无法确认投递方式或遇到多个匹配项时，显示待处理。 |
| 变更昵称 / 备注 | 更新本地配置，沿用原订阅。 |

Google 官方帮助提供网页管理入口，目前未查到 Google Alerts 的公开管理 API。P0 验证使用开源 Playwright 驱动 Google Alerts 正常页面的可行性，包括创建、选择 RSS、读取地址、定位并删除同一提醒。核对链路是否符合 Google 条款和机器可读规则，特别是管理页面触发的请求及 RSS 投递流程。Google 要求重新登录或进行验证时，由用户在页面完成。使用当前 Windows 用户的独立浏览器配置，登录态由浏览器保持。Worker 只获取 RSS 地址和同步结果。[Google Alerts 帮助](https://support.google.com/websearch/answer/4815696?hl=en) · [Google 服务条款](https://policies.google.com/terms?hl=zh-CN) · [Google 网站机器可读规则](https://www.google.com/robots.txt) · [Playwright .NET 持久浏览器上下文](https://playwright.dev/dotnet/docs/api/class-browsertype#browser-type-launch-persistent-context)

- 本地保存作者与订阅同步意图使用同一个事务。绑定记录保存 Google 账号标识、作者 ID、查询条件、远端稳定标识、RSS 地址、托管归属、配置版本和最近同步状态。远端删除未确认时保留绑定供重试。
- 桌面在用户登录会话中按 Google 账号串行执行同步。每次先确认当前 Google 账号和最新配置，再核对远端状态。提交后若超时或退出，下次先对账再重试。只有能确认由 CRS 创建并绑定到当前账号的提醒才能自动删除，查询文字相同只用于发现候选。
- 新增和移除之间发生快速变更时，旧结果不得恢复已停止的采集。正在执行的远端操作完成后，按最新配置继续对账。桌面关闭时保存待同步操作，重新打开后继续；已绑定 RSS 的后台采集照常运行。
- 观察名单显示待创建、待删除、已同步、需登录、账号不匹配和同步失败。网络故障可重试，网页变更或无法确认远端标识时保留待处理状态。已有手工 RSS 可继续使用，手工创建或删除可作为故障时的备用入口，单独记录结果。

### 3.2 Google Alerts 发现

- 每个作者绑定一个独立 RSS 地址，由 `CRS.Feed` 下载和解析，沿用 HTTPS、资源上限、重定向校验、ETag / Last-Modified 和 Worker 取消机制。CRS 无需保存 Google 登录凭据。
- 雪球 Jobs 从 RSS 项取原帖 URL。遇到 Google 包装链接，从链接参数提取目标并重新校验。只接收可规范化为 `https://xueqiu.com/{authorId}/{postId}`、且路径作者与订阅账号匹配的帖子。主页、其他作者和格式无效的链接直接跳过。
- 同时保存标题、可用片段、首次发现时间和 Feed 时间。原帖发布时间经可靠来源核对后单独保存。时间未核实时显示「发布时间待核对」，详情可按发现时间显示待核对线索，观点时间线使用已确认的发布时间。
- 单作者失败时继续处理其他作者。分别显示未配置、未变化、无匹配条目、限流、拒绝访问、超时和格式错误等状态。空 Feed 和 304 均保持作者覆盖范围为「未知」。
- Google Alerts 能覆盖的范围受搜索收录和更新时间影响。试运行应核对漏报和时延。[Google Alerts 帮助](https://support.google.com/websearch/answer/4815696?hl=en)

### 3.3 正文来源顺序和展示规则

| 优先级 | 来源 | 处理方式 |
| --- | --- | --- |
| 1 | Feed 自带正文 | 核对原帖，确认来源字段提供的是完整发言、且保存和分析在许可范围内，再升级为「全文」。其余内容保留为片段。 |
| 2 | 获授权的正文来源 | 若 Feed 只有片段或链接，按原帖 ID 查询可用的授权接口或供稿来源。校验作者、原帖 ID、发布时间和正文完整性后入库。正文适配器属于雪球 Jobs，保持 `CRS.Feed` 的通用边界。 |
| 3 | 用户导入 | 用户打开原帖后，可将有权使用的完整文字粘贴或导入并绑定到已有线索。用户确认完整后显示「全文 · 手工导入」。只提供部分内容时标为片段。 |

「全文」指该条发言完整、未截断的文字正文，保留段落和引用边界。图片、视频和评论区继续通过原帖查看。转发的本人补充与被转发内容分别标出。搜索摘要、带省略截断的片段、加载失败或超出长度上限的响应均不得标为全文。本文基线尚未确认可用的自动全文来源。自动访问、保存及分析须符合来源许可，公开可浏览的页面仍按雪球服务协议处理。[雪球服务协议](https://xueqiu.com/about/terms)

每条原帖显示「全文」「仅片段」「仅链接」之一。获取失败原因单独记录，例如「正文来源未配置」「无访问权限」「请求超时」。限流按来源提供的重试时间处理，重试仅针对失败原帖，不重复拉取已保存的同版本全文。失败或后续收到摘要时保留已取得的全文。观察名单可查看发现数量、自动全文数量、手工补录数量和最近失败。

## 4. 按功能使用开源代理

在「系统设置 → 网络 → VPN」保存 HTTPS 订阅并刷新节点。Worker 加密保存订阅。每个配置了 VPN 的请求使用所选节点对应的本机代理。Mihomo 核心随兼容的 Worker 发行包提供。[Mihomo 项目](https://github.com/MetaCubeX/mihomo)

| 请求 | 路由 |
| --- | --- |
| 桌面自动管理 Google Alerts | 专用 Chrome 沿用系统网络。 |
| Worker 拉取 Google Alerts RSS 和获授权的正文 | 在「任务中心 → 发现雪球发言线索」为该任务选节点或直连，定时与手动运行均使用该计划。 |
| AI 模型 | 在「系统设置 → AI 模型」按供应商选择节点，默认直连。 |
| 用户手动打开 Google Alerts 或雪球原帖 | 由外部浏览器按自身配置联网。 |
| CRS 其他功能 | 沿用现有网络路径。 |

新任务默认直连。旧任务首次保存新线路前沿用既有 RSS 代理。选用节点后，代理不可达时记录失败并保留历史线索。订阅地址不写入日志。

## 5. 股票识别、观点和界面口径

### 5.1 从发言生成个股观点

- 用现有证券目录，按明确的市场代码、唯一标准名称、已确认别名的顺序匹配。以「市场 + 代码」作为证券键。同名、未标注市场的歧义代码和未确认简称进待确认。只讨论行业或指数时不创建个股关联。
- 一篇发言可关联多只股票。正文只保存一份，各股票分别保留对应证据句段、方向、理由、时间范围和条件。若同一股票短期看空、长期看多，同条发言分别展示两个时间范围，默认多空人数不为这条混合观点选定一个方向。
- 本地规则先定位证券和证据句段。全文中股票对象唯一、作者本人直接表达、方向明确且上下文没有冲突时，自动记录该方向并标注「规则识别」。遇到否定、转折、引述、跨股票归因或条件表达，规则无法可靠解释时进入待确认。仅有片段或链接时可生成候选，待核对完整上下文后再计入多空。首期使用本地规则和人工核对。
- 「看多」「看空」「中性」记录明确的本人判断。「不明确」表示已核对作者确实在表达本人的看法，但方向无法归类。「待确认」是处理状态。只提及股票、引用或转发他人发言单独标记；有本人补充时，仅依据补充内容判断。观点方向不推断作者的实际仓位。
- 可后续评估使用 CRS 已配置的 AI。适用范围限于已有股票候选且获准用于模型处理的内容。宿主提供受限调用，验证证券代码和证据原句，并按正文指纹及分析版本缓存。人工确认优先，正文变化影响原证据时提示复核。

例如，一条正文可明确表达看多甲股票、看空乙股票。两只股票各自显示该作者和对应句段，点击「查看全文」读取同一条原帖。原帖只有片段时，详情显示片段状态和打开原帖入口。

### 5.2 个股视图和聚合

- 首页沿用股票列表或行业横向矩阵。显示股票名称、代码、各方向作者数、讨论数和最近发言时间。行业内默认按讨论数、最近发言时间排序。讨论数按去重后的原帖计数。
- 个股详情每条显示作者、发布时间、方向、证据和正文状态，提供「查看全文」和「打开原帖」。无全文时提供「补录正文」入口。
- 在选定股票和时间范围内，先取每位作者最近一条已核实的本人观点，再按方向计数。已核实记录包括人工确认和通过上述明确规则的记录，并且使用已核实的原帖发布时间。最新观点为中性或已核实的不明确时，该作者退出旧方向。待确认内容、引用和单纯提及仍可查看，暂不覆盖上次已核实观点。股票列表与最新观点详情使用同一聚合结果。
- 历史时间线按原帖发布时间倒序。保存每条已记录发言及条件，支持看多转看空、转观望等有原帖证据的变化。用户修正及重新分析要保留可追溯记录。

## 6. 代码落地与数据兼容

| 位置 | 实施内容 |
| --- | --- |
| `CRS.Feed` | 继续负责通用 Feed 获取和解析。复用可注入的 transport，保持既有调用者行为及网络边界。 |
| `XueqiuWatch.Core` | 复用 `WatchInput` 规范化原帖链接。在 `WatchProtocol` 增加订阅绑定与同步状态，以及正文状态、来源、原帖引用和观点审核字段，兼容旧数据。 |
| `XueqiuWatch.Jobs` | 在 `WatchStore.SaveAuthor` 所在事务保存订阅同步意图及修订号，接收并核对桌面同步结果。现有 `XueqiuBackgroundEntry` 使用绑定的 RSS 地址、代理 transport 和正文补全。由 `WatchStore` 管理正文、版本和观点关联。修正 `WatchStore.Queries` 中最新观点先筛多空再去重的问题。 |
| `XueqiuWatch.Wpf` | 复用 `AuthorEditor`、发言线索和个股详情。增加 Google 账号连接、自动同步状态及重试，由桌面用户会话执行浏览器适配。增加正文补录及按帖查看，打开全文时再加载正文。 |
| `CRS.Worker.Service` | 继续负责调度、重试和运行状态，提供受控的网络配置与既有授权的数据访问。 |

按「作者账号 ID + 原帖 ID」去重。沿用 `PostLead` 管理来源线索，在现有 SQLCipher `opinions.db` 中为有正文的原帖保存独立正文记录，供多只股票关联复用。保存原帖 URL、首次发现时间、来源、正文状态、内容指纹和正文版本。每条观点引用原帖及对应版本，按股票保存证据。事务内更新正文与关联状态。同一帖子重复发现、重试或重复分析不会新增同一关联。内容变化后生成新版本，保留旧证据和手工确认，受影响记录进入复核。

Feed 线索正文最多保存 3,000 字符。手工补录支持最多 256 KiB 的 UTF-8 全文，按 Worker 管道限制分块传输，确认字节数和指纹后提交。正文未提交时只留在 Worker 内存中。按原帖与版本独立读取并校验指纹，个股观点可引用保存时的版本。管理界面标明获取方式及正文版本。

升级保留既有观察名单、手工观点、原帖线索和历史。旧线索按规范化 URL 补全原帖键，现存 Feed 内容按片段迁移；旧手工记录继续可查，能核对且足够完整时再关联正文。已有按作者配置的 RSS 地址迁移为外部订阅，继续采集，移除作者时仅解除本地绑定。单一旧 Feed 地址不自动分配给某位作者。首次连接自动同步时，既有无 RSS 的启用作者按当前观察名单逐个对账。

## 7. 实施顺序和验收

| 阶段 | 工作 | 验收 |
| --- | --- | --- |
| P0 订阅验证及真实样本试跑 | 用测试账号验证按 CRS 配置创建 RSS 提醒、读取地址和删除对应提醒。建议选 4 位现有作者试跑两周，核对普通发言和长文的搜索收录、延时和正文来源。 | 自动增删路径符合 Google 规则并完成实测。验证桌面管理和 Worker RSS 按各自配置出站，代理失败时无直连。记录原帖发现和正文样本。自动全文接入以取得可用的授权来源和完整正文样本为条件。 |
| P1 自动增删订阅、路由与状态 | 实现作者变更触发同步、独立 RSS 投递、待处理重试、Worker 代理与归属校验。 | 新增两个作者各得到一个 RSS，无需手工粘贴。重复添加、提交超时和重启后重试无重复提醒。移除只删除对应的 CRS 托管提醒，外部提醒和历史保留。覆盖暂停、重新添加、账号不匹配和远端操作中断。单作者失败不阻断其他作者，重复原帖只保留一条，304、空结果和失败分别显示。 |
| P2 正文入库和补录 | 实现正文状态、手工导入和按帖查看。通过 P0 验证的正文源接入自动补全。 | 普通帖和长文逐条对照原帖，验证作者、原帖 ID、发布时间及全文内容。测试只有摘要、无权限、超长、重复、正文修改及中途取消。若暂无可用自动全文来源，仅验收线索和手工补录，自动全文保留为待完成项。 |
| P3 识别和股票详情 | 跑通股票候选、证据提取、人工纠正、按股票分组和方向聚合。 | 同一篇全文中明确的一多一空能自动分到两只股票并正确计数。覆盖同名股票、否定、转发、短期看空长期看多和看多转中性。点击个股可查对应该股的作者发言、全文或片段和原帖。人工修正不被重跑覆盖。 |
| P4 升级回归 | 在旧版观察名单、手工观点和线索数据上试跑。 | 原有数据和用户清空过的名单保留，桌面经 Worker 正常查询。迁移后可去重、可重试；代理变更不影响未配置的模块。 |

自动增删须用实际 Google 账号验证新增、RSS 地址回读、重复重试和移除结果。只跑通手工配置或模拟页面时，自动增删仍为待验收。

试运行分别报告两项比例。**原帖发现率**按「试运行发现的对照原帖 ÷ 手工核对样本中的原帖」计算，并记录发现时延。**自动全文获取率**按「自动取得并核对无截断的原帖 ÷ 已发现且纳入试跑的原帖」计算，手工补录另计。普通发言和长文分别报告，手工对照样本缺失时标为无法评估。该比例用于判断实际可用范围，界面继续如实标明每条原帖的正文状态。

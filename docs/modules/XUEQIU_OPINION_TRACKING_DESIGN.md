# CRS 雪球作者股票观点追踪设计

> 设计基线：2026-11-23  
> 适用模块：现有插件 \`crs.xueqiu-watch\`  
> 文档性质：目标设计与实施边界，不代表本文提及的目标能力已经全部实现。

## 1. 核心决策

本模块的目标是：**跟踪用户指定的雪球作者发言，并以股票为中心，整理这些作者对每只股票的看多、看空及中性观点。**

作者是内容来源，股票是主要查询对象，发言是证据。

用户打开 CRS 后，首先看到的是股票列表及其观点分布；选择一只股票后，查看不同作者对该股票的发言、判断依据、发表时间和原帖链接。作者名单只负责配置跟踪对象，不作为主要分析结果页面。

### 1.1 本期范围

| 纳入 | 说明 |
| --- | --- |
| 指定雪球作者 | 用户自行添加、修改、暂停和移除作者 |
| 作者发言采集 | 通过已验证且有权使用的数据来源获取指定作者动态 |
| 股票识别 | 从作者发言中识别证券代码、名称和简称 |
| 多空观点提取 | 识别作者对具体股票的看多、看空、中性或不明确观点 |
| 股票维度聚合 | 按股票汇总不同作者的观点，并保留逐条发言 |
| 原始证据回查 | 保留作者、时间、原文或必要摘录、原帖链接 |
| 人工纠正 | 允许修正股票归属、作者归属和观点方向 |
| 必要的采集状态 | 展示最近采集时间、失败、限流和来源未配置状态 |
| 独立网络代理 | CRS 可配置指定服务使用指定 Mihomo 节点组，作为独立公共基础设施 |

### 1.2 明确不做

本期不建设通用信息情报平台，不接入以下内容：

- Google Alerts、Google News、Gmail API。
- 交易所公告、上市公司官网、新闻媒体或其他资讯平台。
- 全网搜索、通用 RSS 订阅管理或多来源新闻聚合。
- 雪球全站用户发现、评论区监控、热帖排行或全量舆情分析。
- 自动交易、自动下单、自动调整持仓。
- 与股票观点无关的复杂研究工作流、待办系统或报告平台。

**不要因为未来可能有用，就把这些功能放入本期架构。**

## 2. 目标使用方式：股票优先，作者观点作为证据

### 2.1 主界面

沿用现有「扩展工具 → 雪球观点追踪」插件，不新建第二个插件。

主界面继续以股票为入口：

1. 顶部提供时间范围、市场、行业、作者和股票名称/代码筛选。
2. 股票区域展示股票名称、代码、行业、看多作者数、看空作者数、讨论数量和最近发言时间。
3. 用户选择股票后，下方展示该股票对应的作者观点。
4. 可切换「最新观点」和「历史时间线」。
5. 作者观察名单、采集状态和手工纠正属于管理入口，不替代股票主视图。

现有行业/股票横向矩阵可以保留，作为股票列表的紧凑展示方式；它不是独立的行业研究系统。

### 2.2 个股观点详情

选择一只股票，例如「紫金矿业」，页面展示：

| 观点方向 | 作者 | 发言时间 | 发言内容与依据 | 原帖 |
| --- | --- | --- | --- | --- |
| 看多 | 作者甲 | 2026-11-20 | 对铜价、产量或成本改善的具体判断 | 查看原帖 |
| 看多 | 作者乙 | 2026-11-19 | 对项目投产及未来利润的判断 | 查看原帖 |
| 看空 | 作者丙 | 2026-11-18 | 对估值、资本开支或项目风险的担忧 | 查看原帖 |
| 中性 | 作者丁 | 2026-11-17 | 认为仍需等待业绩或价格数据确认 | 查看原帖 |

以上仅为界面示例，不代表真实作者观点。

个股详情至少提供：

- 当前筛选时间范围内的看多作者数、看空作者数、中性作者数。
- 各作者最近一条有效观点。
- 每条观点的原始发言、证据摘录、理由、条件和时间。
- 同一作者对同一股票的历史观点时间线。
- 观点从看多转为看空、增加条件或转为观望的变化记录。
- 原帖链接，便于回到雪球核实上下文。

### 2.3 统计口径

- 统计单位是「作者 × 股票」，不是帖子数量。
- 同一作者在同一股票上连续发布多条看多发言，当前看多作者数只计 1 人。
- 历史发言仍全部保留，不能因为只显示最新观点而覆盖旧观点。
- 只把作者本人明确表达的观点计入看多/看空/中性统计。
- 单纯提及股票、转发别人观点、引用别人观点，不计为作者本人的多空观点。
- 最新一条有效本人观点如果是中性或不明确，不得继续沿用更早的看多/看空方向。
- 「看空观点」不等于作者实际做空或持有空头仓位；不得从发言推断真实持仓。

## 3. 雪球作者管理与采集

### 3.1 作者管理

沿用当前插件的作者管理能力，以雪球数字账号 ID 作为唯一身份：

- 添加作者：输入雪球主页链接或数字账号 ID。
- 修改昵称、备注和启用状态。
- 暂停作者：停止后续采集，但不自动删除历史观点。
- 移除作者：停止后续采集；历史记录按数据使用许可和用户选择处理。
- 昵称变化不影响历史记录，因为关联键是账号 ID。

当前代码中的默认观察名单继续沿用，不在本设计中重复维护另一份作者名单。用户保存后的名单是运行时配置；不得在每次升级时重新覆盖用户配置。

### 3.2 采集来源

每位作者配置独立的数据来源地址。优先复用现有 \`CRS.Feed\` 和 Worker 任务体系：

- \`CRS.Feed\`：负责 RSS / Atom / JSON Feed 的通用 HTTP 抓取、条件请求、格式解析和资源限制。
- \`XueqiuWatch.Jobs\`：负责作者来源配置、雪球作者归属校验、发言去重和观点库写入。
- \`CRS.Worker.Service\`：负责定时调度、运行状态、取消和重试。
- \`XueqiuWatch.Wpf\`：负责作者配置、股票查询、观点查看和人工纠正。

**关键限制：RSS 发现链接不等于取得了发言正文。**

当前代码的自动任务主要把 Feed 中符合作者账号的雪球原帖链接保存为待核验线索；它并没有因此自动取得全部正文、识别股票或判断多空。后续要完成自动观点整理，必须先验证数据来源是否能稳定提供：

1. 作者账号 ID；
2. 原帖 ID 和原帖链接；
3. 发言时间；
4. 可供分析的正文内容；
5. 必要的转发/引用归属信息。

如果 Feed 已提供正文，直接解析 Feed 内容；如果只提供链接，只有在确认存在可合法使用且稳定的正文获取方式后，才增加对应的雪球正文适配器。不得假设 RSSHub 公共实例长期可用，也不得把第三方路由视为平台授权。

不得通过绕过验证码、规避访问控制、伪造身份或未经许可的私有接口调用来保证采集。若没有合适的自动正文来源，保留现有「RSS 发现线索 + 用户打开原帖后手工录入」流程，不以不可靠采集伪装成自动覆盖。

### 3.3 增量与去重

- 使用「雪球作者账号 ID + 原帖 ID」作为原帖去重依据。
- 同一原帖提及多只股票时，原帖只需识别一次，每只股票分别建立观点关联。
- 保存 Feed 的 ETag / Last-Modified，支持条件请求。
- 304 只表示来源未变化，不表示作者没有发言。
- RSS 返回空列表不能证明没有新发言，也不能证明完整覆盖。
- 429、403、超时、格式变化和来源不可用必须显示为不同状态。
- 单个作者来源失败不能阻断其他作者。
- 采集结果与采集覆盖范围分开记录；没有可验证的数据时，显示「未知」，不显示「已完整采集」。

## 4. 股票识别与观点提取

### 4.1 股票识别

识别目标仅限于作者发言中实际讨论的股票。

匹配优先级：

1. 明确的市场代码，例如沪深代码、港股代码和美股代码。
2. 证券目录中的标准名称。
3. 用户维护或确认过的常用简称、别名。
4. 其他模糊文本只能产生待确认候选，不能自动归属。

证券唯一键使用「市场 + 证券代码」，避免不同市场代码相同或公司名称相似造成串标。

一个帖子可以关联多只股票。例如一篇发言同时讨论紫金矿业和洛阳钼业，应为两只股票分别建立观点记录，并保留各自对应的证据句段。不能把整篇帖子笼统地标成所有股票都看多。

只提及行业、指数或宏观变量，没有明确证券对象时，不生成个股观点。

### 4.2 观点分类

每条「作者 × 股票 × 原帖」关联记录使用以下方向：

| 方向 | 定义 | 示例 |
| --- | --- | --- |
| 看多（Bullish） | 作者明确表达对该股票未来价值、业绩或价格表现的正向判断 | 看好、低估、未来利润有望增长 |
| 看空（Bearish） | 作者明确表达对该股票未来价值、业绩或价格表现的负向判断 | 不看好、估值过高、盈利将承压 |
| 中性（Neutral） | 作者明确表示观望、等待验证或暂不判断方向 | 等季报确认、暂时观望 |
| 不明确（Unclear） | 提及股票但无法可靠判断作者方向 | 只列事实、转述观点、语义含混 |
| 待确认（Pending） | 系统已发现候选，但证券、归属或观点仍未确认 | 代码歧义、引用归属不清、证据不足 |

「不明确」是分析结果；「待确认」是处理状态。两者不能混为一类。

### 4.3 不能把正负情绪直接当作多空观点

以下情况必须区分：

- 公司公布了好消息，不代表作者本人看多。
- 作者批评某项业务，不一定代表看空整家公司。
- 作者转述其他人的看空观点，不代表作者自己看空。
- 作者说「估值不便宜，但长期仍看好」，应保留完整条件，不能只抓取「估值不便宜」判为看空。
- 作者说「短期看空，长期看好」，应分别记录时间范围或标记为多时间周期观点，不能压缩成一个无条件方向。
- 作者没有表达方向时，不允许 AI 或规则强行给出看多/看空结论。

### 4.4 提取方式：规则优先，AI 辅助

为控制成本和误判，采用轻量流程：

1. 规则识别证券代码、股票名称和可能的观点词，生成候选句段。
2. 只对确实包含股票候选的帖子进行观点拆解，不对所有内容无差别调用 AI。
3. 如启用 AI，使用 CRS 已配置的模型能力，要求输出结构化结果：证券、观点方向、证据原句、理由、时间范围、条件和置信度。
4. 对 AI 返回的证券代码和证据原句进行程序校验；证据必须能在原文中定位。
5. 证券或归属不明确、正反观点冲突、低置信度的记录进入待确认。
6. 用户人工修正优先于自动提取结果；重新分析不能覆盖人工确认结果。

AI 只负责拆解雪球指定作者的发言，不负责搜索其他信息源，也不自动形成投资建议。未配置 AI、调用失败或材料不允许外发时，仍可使用规则候选和人工确认完成流程。

AI 分析应按原帖内容指纹和提示词版本缓存；原文未变化且分析版本未变化时，不重复消耗模型调用。模型费用由用户现有模型配置和预算控制，不新增强制付费服务。

### 4.5 发言归属

每条记录必须区分：

- 作者原创或作者本人明确表达；
- 作者仅提及股票；
- 作者转发或引用他人内容。

只有第一类可以进入作者本人多空统计。转发没有附加本人观点时，只保留为转发线索；不能把被转发人的观点记在转发作者名下。

## 5. 数据结构与存储

继续使用当前插件独立 SQLCipher 数据库 \`opinions.db\`，由 Worker 插件维护。不得把雪球原始内容写入 CRS 税务/绩效数据库，也不另建数据库服务器。

### 5.1 当前已有模型

当前 Core 已有以下主要模型：

- \`Author\`：作者账号、昵称、备注、启用状态和 Feed 地址。
- \`Security\`：市场、代码、名称和行业。
- \`Opinion\`：作者、股票、发言时间、方向、归属、内容、证据、原帖链接和修订号。
- \`PostLead\`：Feed 发现的原帖链接。
- \`FeedCoverage\`：每位作者来源的最近检查状态和条件请求信息。

当前数据库已支持按股票汇总、个股明细、历史时间线和待确认记录。现有 Feed 采集主要保存链接线索；不能把它等同于正文采集和自动观点分析。

### 5.2 目标字段增量

优先在现有模型上小步扩展，不另建复杂的通用内容平台。

| 对象 | 建议补充字段 | 用途 |
| --- | --- | --- |
| 原帖/观点 | \`PostId\`、\`ContentHash\`、\`FirstSeenAt\` | 稳定去重、内容变化检测和首次发现时间 |
| 观点 | \`ExtractionMethod\`、\`Confidence\`、\`ReviewState\` | 区分规则/AI/人工结果及审核状态 |
| 观点 | \`Reason\`、\`Horizon\`、\`Conditions\` | 保存判断依据、时间范围和成立条件 |
| 股票目录 | \`Aliases\` 或独立别名映射 | 支持常用简称并减少误识别 |
| 来源状态 | \`LastSuccessAt\`、\`LastError\` | 区分成功、失败和覆盖未知 |

现有 Opinion 以「作者 + 股票 + 原帖」作为一条关联记录。一个帖子关联多只股票时，可保存多条关联记录，但原帖 ID 和内容指纹必须一致。若后续正文体量明显增长，再评估拆分独立 Posts 表；当前阶段不为理论上的扩展预先增加复杂度。

数据库迁移必须保留现有人工录入观点、作者名单和历史线索。旧记录没有 PostId 时，使用原帖链接或现有记录 ID 作为兼容去重依据，不得批量删除或静默重置用户资料。

## 6. 股票观点聚合规则

### 6.1 当前观点

对选定股票和时间范围：

1. 先筛选作者本人、与该股票明确关联的有效观点。
2. 按作者分组。
3. 每位作者按原帖发布时间选取最新一条有效本人观点。
4. 最新观点为看多，则该作者计入看多人数；为看空则计入看空人数；为中性则计入中性人数。
5. 最新观点为不明确或待确认，不计入明确多空人数，但仍可在明细中查看。
6. 转发、引用和单纯提及不覆盖作者本人最新观点。

**重要修正：必须先选出每位作者最新的有效观点，再判断方向。** 不得先过滤出看多/看空，再选最新记录。否则作者最新一条发言已经转为中性时，系统仍可能错误地沿用早期看多/看空观点。

### 6.2 历史观点

历史时间线按发布时间倒序展示，同一作者的每次有效观点变化均保留。

观点变化类型只需支持：

- 新增明确观点；
- 新增依据或成立条件；
- 方向转为中性/观望；
- 明确由看多转看空；
- 明确由看空转看多；
- 原观点被作者更正或删除（来源能够验证时）。

变化判断必须能回指前后两条原帖。没有证据时只展示时间线，不自动推断作者改变了立场。

### 6.3 排序

默认优先展示：

1. 最近有新发言的股票；
2. 最近出现明确多空变化的股票；
3. 当前时间范围内实质讨论作者数较多的股票。

排序只帮助用户找到讨论较多或观点变化较大的标的，不形成买卖排名，也不将讨论热度解释成投资价值。

## 7. 技术结构与现有项目复用

沿用当前已存在的三个项目，不新增一个平行雪球插件：

~~~text
src/Plugins/XueqiuWatch/
├── CRS.Plugins.XueqiuWatch.Core
│   ├── 作者、股票、帖子和观点模型
│   ├── 股票识别与观点校验
│   └── Worker/WPF 共用协议
├── CRS.Plugins.XueqiuWatch.Jobs
│   ├── 作者来源采集
│   ├── 原帖去重与增量同步
│   ├── 股票和观点提取
│   └── opinions.db（SQLCipher）
└── CRS.Plugins.XueqiuWatch.Wpf
    ├── 股票观点主界面
    ├── 个股观点详情与时间线
    ├── 作者观察名单
    └── 人工确认与纠正
~~~

公共能力继续复用：

| 能力 | 复用项目 | 约束 |
| --- | --- | --- |
| Feed 抓取 | CRS.Feed | 不在雪球插件中重复实现 RSS/Atom 解析器 |
| 定时任务 | CRS.Worker.Service / Quartz.NET | Worker 是唯一调度宿主 |
| 插件隔离与存储上下文 | CRS.Worker.Abstractions | 不由 WPF 直接打开 Worker 数据库 |
| 加密存储 | 现有 SQLCipher 方案 | 插件数据库独立加密 |
| 日志 | Serilog | 记录采集状态和异常，不把不必要的原帖正文写入日志 |
| 界面 | 现有 WPF 插件框架 | 复用 CRS 统一样式和导航 |
| AI | CRS 现有模型配置 | 仅用于雪球帖子拆解，按需调用并缓存 |

## 8. 网络代理：独立公共基础设施

代理能力不是雪球业务逻辑，不应写入 XueqiuWatch 插件内部，也不应让雪球插件自己维护节点、协议或路由规则。

### 8.1 选型

优先复用开源项目 **Mihomo** 作为代理核心：

- CRS 不自行实现 VPN/代理协议、DNS 代理、节点握手或规则引擎。
- 节点订阅和节点配置由用户提供；Mihomo 开源不代表代理节点免费。
- CRS 只负责保存服务到代理组的映射、导入/更新 Mihomo 配置，以及展示运行状态。
- 不把 CRS 做成完整的 FlClash 替代品。

项目地址：[MetaCubeX/Mihomo](https://github.com/MetaCubeX/mihomo)

### 8.2 最小配置能力

用户可以为指定服务配置使用哪个节点组，例如：

| 服务匹配规则 | 代理组 |
| --- | --- |
| \`xueqiu.com\`、\`*.xueqiu.com\` | 用户选择的「雪球」节点组 |
| 其他指定服务 | 用户自行添加服务与节点组映射 |
| 未配置服务 | 按用户设定的默认策略处理 |

CRS 需要的只是：

1. 导入或选择 Mihomo 配置文件；
2. 展示节点组和可用状态；
3. 为指定域名配置节点组；
4. 测试目标服务连通性；
5. 显示当前服务实际使用的代理组；
6. 代理失效时按配置执行失败关闭或明确回退，不允许静默切换成未授权直连。

### 8.3 接入方式与非目标

- 首期优先使用 Mihomo 提供的本机 HTTP/Mixed 代理端口，让需要代理的 CRS HttpClient 显式使用该代理。
- 域名分流规则由 Mihomo 负责；CRS 不实现第二套路由引擎。
- 先不开发 TUN、虚拟网卡、系统级流量接管和完整桌面代理客户端。
- 代理进程的启动、停止、健康检查和配置更新应与 Worker/桌面进程职责分开，避免代理故障拖垮 Worker。
- 不在日志、普通配置或 Git 仓库中保存代理订阅 URL、密码和节点凭据。

代理配置可以被其他 CRS 服务复用，但本期只需验证雪球访问按配置节点分流，不借此扩展消息订阅范围。

## 9. 实施顺序

| 阶段 | 内容 | 通过条件 |
| --- | --- | --- |
| P0 数据源验证 | 选 1–2 位指定作者，验证 Feed 是否提供真实正文、原帖 ID、作者归属和发布时间；同时验证雪球域名经 Mihomo 指定节点访问 | 连续样本可用；若只能发现链接，明确记录正文获取缺口，不假称自动采集完成 |
| P1 原帖采集 | 在现有 Feed 线索基础上补充有权使用的正文获取方式、原帖去重和增量同步 | 原帖不重复，作者和时间正确，失败状态可见 |
| P2 股票识别 | 证券代码、名称、别名匹配；支持一帖多股和待确认 | 对照样本中的证券归属正确，歧义不自动确认 |
| P3 多空观点 | 规则候选、窄范围 AI 辅助、证据定位和人工纠正 | 每条明确观点均可回查原文；无法判断时不强行分类 |
| P4 股票主界面 | 股票列表/矩阵、个股作者多空发言、当前观点与历史时间线 | 股票为默认入口；统计和明细口径一致 |
| P5 代理配置完善 | Mihomo 配置导入、服务到节点组映射、状态与故障行为 | 雪球请求实际按指定节点出站，故障时行为符合配置 |

P0 没有通过前，不要先开发复杂的自动登录、反爬、网页解析或 AI 批处理。先确认数据拿得到，再决定需要补多少代码。

## 10. 验收标准

### 10.1 数据来源

- 每条自动采集记录均能确认作者账号、原帖 ID、原帖链接和发布时间。
- 正文为空或只拿到链接时，明确显示为线索，不生成看多/看空结论。
- 来源限流、拒绝访问、超时、格式变化和未配置均可区分。
- 一个作者来源失败不影响其他作者。
- 不宣称覆盖了作者所有历史发言，除非数据源确实提供可验证的覆盖范围。

### 10.2 股票识别和观点提取

- 一个帖子讨论多只股票时，各股票分别建立记录。
- 同名证券、市场代码歧义和仅提及行业时进入待确认。
- 看多、看空、中性和不明确均有独立结果。
- 否定词、转折句、引用、转发和多时间周期观点有专门测试样本。
- 每条明确观点均能定位到原文证据句段。
- AI 结果不能凭空补充原文没有的理由、持仓或目标价。
- 人工修正后重新分析，不得覆盖用户确认结果。

### 10.3 股票聚合

- 选择股票后，展示该股票所有已记录作者的观点。
- 同一作者同一股票的最新观点只计一次。
- 最新中性/不明确观点不能被早期看多/看空覆盖。
- 观点统计人数与明细作者集合一致。
- 历史时间线不因新发言或重新分析而丢失。
- 转发和单纯提及不进入作者本人多空人数。

### 10.4 代理

- 雪球域名按用户配置使用指定 Mihomo 节点组。
- CRS 能显示 Mihomo 未运行、节点组不可用和目标站点不可达。
- 指定服务代理失效时，不得静默直连。
- 不影响未配置代理的 CRS 本地功能。

## 11. 反方审查：主要失败条件

| 风险 | 为什么会失败 | 控制措施 |
| --- | --- | --- |
| RSS 只有摘要或链接 | 无正文就无法可靠识别股票和多空观点 | P0 验证正文；没有正文就保持线索/手工录入 |
| RSSHub 路由变化或不可用 | 第三方服务不受 CRS 控制 | 来源可配置；保留历史；失败时明确显示 |
| 股票名称误匹配 | 简称、同名和跨市场代码可能造成串标 | 证券唯一键、别名确认和待确认队列 |
| 情绪误判为多空 | 正面/负面新闻不等于作者投资立场 | 必须保存证据句段，识别归属和上下文 |
| 转发观点归错作者 | 转发内容可能是其他人的观点 | 独立记录原创、提及和转发归属 |
| 最新观点统计错误 | 先过滤多空再取最新，会忽略更新后的中性观点 | 先选最新本人观点，再计算方向 |
| AI 输出幻觉 | 模型可能补充不存在的理由或目标价 | 证据原文校验、置信度、人工纠正 |
| 代理故障导致意外直连 | 可能违反用户指定的网络路径 | 明确失败关闭策略并做出站验证 |

## 12. 本次设计对应的当前代码事实

截至本设计核对的仓库 main：

- 已存在 \`CRS.Plugins.XueqiuWatch.Core\`、\`CRS.Plugins.XueqiuWatch.Jobs\` 和 \`CRS.Plugins.XueqiuWatch.Wpf\`，不需要新建平行插件。
- 已有作者管理、证券目录、观点录入、股票汇总、个股明细、时间线和独立 SQLCipher 观点库。
- 已有 \`CRS.Feed\` 接入和按作者配置 Feed 的发言线索发现任务。
- 当前 Feed 任务保存的是符合作者账号的雪球原帖链接线索；尚不能据此认定已自动采集完整正文、识别全部股票或自动形成可靠的多空结论。
- 当前股票识别以明确代码和证券目录中的唯一名称为主；方向短语识别只用于候选提示，不等于完整观点理解。
- 当前观点录入已区分作者本人、提及和转发归属。

需要特别复核现有最新观点统计实现：必须先选出作者对该股票最新一条有效的本人观点，再判断方向。如果先排除中性/待确认记录再取最新，作者已转为观望时仍可能被错误统计为早期看多/看空。

本文是目标设计，不代表 P0 数据源验证、自动正文获取、AI 观点拆解或 Mihomo 配置界面已经完成。实施状态应在代码和专项测试完成后另行更新，不得把设计写成已实现。

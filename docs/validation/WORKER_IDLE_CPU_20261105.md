# Worker持续CPU占用优化

## 现场证据与范围

2026-11-05只读采样35秒：14个逻辑处理器，`CRS.Worker.Service`持续约5%～6%，两个PluginRunner几乎为0。正式日志记录`StorageCapacityWarning Entries=231478`；同次目录枚举中，`maintenance`有225243项，当前`plugins`有6212项，日志13项，约97%的目录项来自历史维护副本。

已安装程序集确认包含默认30秒的完整巡检；源码对每个文件/目录读取ACL及所有者。原PeriodicTimer在一次慢扫描后可能立即消费积压到期信号，造成连续全树扫描。以上证据高度指向巡检负载；未采集正式进程调用栈，也未通过停止巡检做生产A/B实验。

## 代码行为

- 启动检查与运行中巡检共用全树扫描游标，原所有者、ACL、继承权限、链接及消失临时文件处理保留。
- 运行中的完整巡检默认连续处理至多20ms或128项，按实际工作耗时安排9倍休息，工作占空比约10%。时间片以文件检查之间为边界，不能中断正在执行的Windows系统调用；该值不是整进程CPU硬上限。
- 一轮结束后再等待30秒，避免追赶积压周期；容量预警逻辑保留。
- 根目录及顶层文件/目录独立每30秒检查，包含密钥、调度库和来源预算库；完整扫描过程中也复核关键权限。两项检查任一故障都会取消并排空另一项；宿主等待监听/巡检故障，不再只在30秒协调时发现失败。
- 完成事件`StorageSecurityScanCompleted`记录Entries、ElapsedMs、ActiveMs、PausedMs，不包含完整路径、密钥或ACL主体。
- 真实ACL测试显式恢复DACL修改标记，避免仅把未修改的权限快照传回Windows而未真正恢复，污染后续负例。

## 测量

隔离目录含1000个空文件和10个子目录，同一测试进程先执行同步全量检查，再执行默认预算的完整巡检。2026-11-05计时如下；同时运行的正式服务保持原状态。

| 指标 | 同步巡检 | 默认分批巡检 |
| --- | ---: | ---: |
| 实际覆盖目录项 | 1010 | 1010 |
| 总耗时 | 1764ms | 14155ms |
| 测试进程CPU时间 | 1141ms | 969ms |
| 平均逻辑处理器占用量 | 0.647 | 0.068 |
| 折算整机平均CPU（14逻辑处理器） | 约4.62% | 约0.49% |

分批巡检工作时间1419ms、休息12734ms。平均CPU负荷下降约89.4%；总CPU时间的小幅差异受缓存和环境影响，不作为计算量降低的承诺。这项优化主要把同等检查工作分散到更长时间，不能将此结果当作已安装Worker或23万目录项的现场降幅。

## 验证与发布边界

已通过：后台项目与Background测试项目Release构建（0错误；NuGet漏洞源不可达保留NU1900警告）、38项目架构/依赖门禁、11项默认预算/覆盖/取消/独立关键检查、9项真实ACL/链接/隔离宿主故障退出检查，以及4项大目录增长检查，共24项动态检查。9项权限检查使用本次新生成的HeartbeatOnly包，已确认权限故障后非零退出、原密钥内容保持不变。

大目录夹具创建101000个文件和101个子目录，实际完整检查101101项。同步检查与无休息预算的分批检查均完整通过，发出一致的容量预警；启动/全量检查响应取消，加入真实额外读取权限后仍拒绝。此夹具检验大目录覆盖与异常处理，默认10%预算的性能由上面的独立计时验证，不将两者混用。

日志保存在`artifacts/worker-cpu-20261105/`。`heartbeat-package`仅供隔离宿主测试，不是替换正式国家队插件服务的完整安装包。

完整巡检的间隔因限速变长；非顶层文件的权限异常可能更晚被发现，独立关键检查不等于对所有业务文件的实时变更监控。启动的两次全树验证保留，不将启动耗时的优化混入本次运行时改造。未删除正式维护副本，未修改正式数据、密钥、计划或通知设置，未更新或重启已安装Worker。

上述部署边界描述2026-11-05的隔离验证状态。2026-11-06已按用户要求更新本机已安装服务，实际CPU、原计划保留、新增默认任务暂停及目录清理候选见[现场安装与验证](WORKER_IDLE_CPU_DEPLOYMENT_20261106.md)。

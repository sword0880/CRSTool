# NationalTeam 原件核验范围与查询开销整改（2026-10-23）

## 发现

`MarketRepository.ScanEvidence` 会对所选范围内的每个原始/规范化 SHA-256 做真实字节核验，这是重要的完整性保证；但多个只读方法原先调用无参数的 `ValidateEvidence()`，导致它们扫描 `source_fetch` 中所有抓取，包括没有被份额、交易日历或市场成交事实引用的孤立 `RawSaved`/解析失败记录。

这些查询实际读取的是有限的业务事实。例如：
- `Overview` 读取份额修订、接受份额、交易日历及仪表盘证据；
- `Calendar` 读取交易日历；
- `History`/ `PointsForKeys` 读取接受份额及其所属市场日历；
- `Coverage(key)` 只读取指定证券的份额修订与该市场日历。

因此，未被这些事实引用的孤立抓取被独占文件锁、临时 I/O 失败或损坏时，不应阻断所有 ETF 查询。后台完整性作业仍必须全量扫描所有原始抓取并持久化 Q15 状态；这次修改不减少后台全量巡检范围，也不放松任何被业务事实引用的原件核验。

## 修改

- `Evidence()`、`Calendar()`、`Overview()`、全池 `History(null)` 与 `PointsForKeys` 改用现有 `dashboardOnly` 扫描范围：仍核验份额、市场成交、官方交易日历和交易日事实，排除未关联的其他抓取。
- `History(key)` 改为校验该证券及所属市场日历。
- `Coverage(key, from, to)` 改为校验该证券与所属市场日历，并使用已有 `ReadEvidence(key)` 直接在 SQL 中筛选，避免先读取全池证据后再在内存中过滤。
- `Points(key)`、`Evidence(key)` 原有单证券核验范围保持不变；`ReconcileEvidenceIntegrity()` 仍执行全量扫描并在单一事务中记录损坏/恢复事件。

## 回归验证

`ScopedEvidenceChecks` 新增一个已写入 `source_fetch`、但未关联任何业务事实的原件；测试对该文件持有真实独占文件锁，并验证概览、日历、历史、批量份额和全池证据查询仍可读取。随后对覆盖报告所引用的采集尝试原件施加独占锁，断言 Coverage 仍失败关闭；再继续使用已被份额事实引用的原件进行损坏测试，断言相关查询仍失败关闭、只读查询不写数据库、完整性巡检仍幂等。

CI 新增 `--scoped-evidence` 专用入口，避免该重要回归仅因挂在较大退出告警测试组中而未执行。

## 不在范围

- 不缓存哈希结果，不依赖文件长度/修改时间代替 SHA-256，不降低被业务事实引用原件的核验强度。
- 不更改 ETF 份额、交易日历、市场成交的业务阈值/接受规则、原件格式、数据库 Schema 或国家队风险判断。
- 本修复只缩小只读查询的完整性依赖范围；不能据此声称完成大样本性能基准。真实数据库的 P95/P99 延迟与原件数量上限仍需独立测量。

## 修复内容

后台清理已有持久任务摘要，但桌面仅消费完成通知，忽略Current；任务中心和底栏原先只消费插件调度。本次保留当前清理摘要并接入任务中心：Queued进入排队列表，Scanning/Running进入执行列表，显示真实扫描、核验和删除计数。设置页继续只有提交入口，完成后仍由主窗口提醒并持久确认已读。摘要按既有管理员和SID边界读取，前台不接收或处理删除目标。

按用户最终确认，底栏仅显示“运行 N · 等待 N”，清理计入对应数量，不单列清理名称或阶段。旧健康采样的Waiting与PendingManualCommands有重叠，不能直接相加。底栏与任务中心共用有界分页读取器，核对同一GetTaskActivity快照的观察时间、完整分页和状态数量；该快照已从Pending排除进入Waiting的请求，等待总数由Waiting+Pending取得。清理摘要失败时总数显示未确认，任务中心保留并标记旧快照；任务快照失败时不沿用旧等待总数。健康与任务采样不被慢同步历史阻塞。

任务详情原先只编辑Cron。本次显示“已启用/已禁用”，加入“启用任务/禁用任务”操作；禁用任务的触发时间标明启用后生效。启停使用既有Resume/Pause命令、固定任务身份及预期修订号，不依赖主列表后来选中的任务。服务确认后更新状态和修订，保留未保存的频率草稿，后续保存计划仍带新修订。权限失败、修订冲突不冒充成功；响应丢失时显示未确认并禁止继续覆盖，沿用任务中心原请求确认流程。

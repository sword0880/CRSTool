# 后台清理任务与主窗口提醒（2026-11-06）

## 用户行为

设置页只保留“提交清理任务”及受理确认，不显示执行进度或完成结果。提交后即可关闭设置或退出前台。后台自行核验、按固定规则清理，主窗口显示完成或未全部完成提醒，点击“知道了”后持久保存已读状态。前台关闭时后台保留结果，下次启动再提醒；通知不依赖设置窗口。

## 后台可靠性与保护

- 任务先写入受保护资料目录再响应受理；同一编号重试不重做，已有在途任务时复用，不重复排队。
- 手动提交与每日自动任务共用单执行通道、10%工作占空比、维护锁、清单摘要和审计机制。前台只读小型摘要，默认10秒检查一次，没有长等待或持续文件扫描。
- 当前快照、一份完整有效历史副本、未知或损坏副本、活动数据库、密钥、插件raw原件保持原有保护规则。
- `maintenance/cleanup-tasks` 保存任务及已读记录，最近索引最多32条，旧记录继续支持原编号重试及追溯。个人提交记录按SID隔离，自动结果按管理员身份分别确认。
- 服务重启后，Queued任务继续执行；Scanning/Running任务转为Interrupted。执行阶段异常退出时删除统计标记不完整，不把未记录的删除误报为零。
- 恢复只在服务已取得所有权租约后进行，普通构造及只读审计不写运行中的任务；损坏任务记录阻止进一步清理，不影响业务服务启动。
- 维护可暂停托管任务并保存中断结果，后台随后按保留规则重新核对，不覆盖活动库或原件。

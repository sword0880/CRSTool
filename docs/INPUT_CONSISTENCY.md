# 导入原件与快照摘要一致性

2026-10-11。本轮实现对应 AR-08，适用于 IBKR Activity Flex XML、期初 LOT XML、富途交易／收入 XLSX 与文本收入 PDF。

## 当前行为

每个所选原件通过 `FrozenInput` 一次读取到私有内存副本，单文件必须非空且不超过 25 MB。读取期间按块检查取消，Windows 文件共享设置禁止其他进程同时写入或替换；读取不完整、大小越界或额外字节均拒绝。读取完成后关闭原件。

SHA256 从同一份私有字节计算。XML 使用只读流；富途 Excel 用该副本识别用途并解析，交易表识别后复用同一工作簿；PDF 用该副本的独立字节复制解析。对外只提供不可写流或独立数组复制，调用者不能修改冻结字节。富途只保留一份收入原件副本及当前交易原件，不累计保存全部报告字节；第二份收入主表立即拒绝。

应用层的活动／期初文件引用采用解析器返回的 `SourceReport.Sha256`，计算结束时不重新打开原路径。一个文件包含多个账户时，各账户来源须提供相同摘要；缺失或冲突拒绝产生结果。源文件名必须唯一，大小写不同的同名文件也拒绝，包括活动与期初之间的重名。

IBKR 同一规范化路径重复选择时先去重，只读取和记录一次，不重复计税；此规则不允许不同目录的同名来源，也不取消富途唯一收入主表及交易来源重叠检查。

IBKR 来源及规范化文件引用使用小写 SHA256。富途来源摘要及其参与生成的成交编号保留原大写格式，规范化引用统一为小写。完整快照仍为 `CRS.CanonicalInput.v2`，引用快照仍为 `CRS.InputReferences.v1`，未增加原件正文持久化。

原件在解析完成后被替换或删除时，本次结果和快照仍绑定已解析副本。历史“校验原件”会独立读取用户重新选择的现有文件，修改后的文件不能冒充历史原件。完整规范化快照可在原件丢失时复算；只有引用的快照不能因此恢复原始交易。

## 验证及边界

`ImportConsistencyChecks` 覆盖活动／期初解析后替换或删除、来源与规范化引用同源、无原件复算、只读副本、Excel／PDF 原路径删除后读取、空文件／超限／预取消，以及同名文件、缺失／冲突摘要拒绝。正常券商金额、历史复算及导出继续由六组回归检查。

本轮验收产物位于 `artifacts/input-consistency-acceptance`。使用合成脱敏文件，不代表真实全年样本签认。

最终 Release 构建零警告、零错误；六组回归、架构检查和 WPF 桌面冒烟通过，原有 68 个综合场景全部通过。验收脚本使用同一批已构建 Release 文件，因此报告的 Build 字段明确为 skipped_existing_release_binaries，不冒充脚本重新构建。公开发布仍为 ReleaseApproved=false。

本机制保证每份原件内部的解析与摘要一致，不提供多个文件在同一瞬间的原子快照，不证明券商来源或业务完整性。AR-09 结构校验见 [快照校验](CANONICAL_VALIDATION.md)；后续结果冻结、计算程序集指纹与固定编码封存见 [冻结结果与运行证据](FROZEN_EVIDENCE.md)，完整执行环境保全和迁移仍未完成。Windows 以外或特殊文件系统的共享行为需另行验证。

冻结字节只驻留内存，不生成新的磁盘原件缓存；内存、系统分页及高权限程序访问的保护边界仍见隐私声明。数据库加密、明文库拒绝和导出确认策略保持原有安全要求。

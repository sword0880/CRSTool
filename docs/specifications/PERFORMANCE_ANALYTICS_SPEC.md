# CRS 海外投资收益率统计需求规范（PERFORMANCE_ANALYTICS_SPEC）

> 文档状态：需求基线；P0 已接入，真实独立金额验收未通过（2026-10-14）  
> 版本：v0.1  
> 日期：2026-10-13  
> 适用项目：CRS（.NET 10 / WPF / SQLCipher / 完全离线）  
> 需求定位：新增独立的“海外投资绩效中心”，与既有税务计算中心并列。  
> 约束：本文件定义新模块需求，不替代 `TAX_ENGINE_SPEC.md`、`CAPITAL_GAIN_FIFO_SPEC.md`、`EXCHANGE_RATE_SOURCES.md`、`FUTU_FIELD_MAPPING.md`、`IBKR_IMPORT_GUIDE.md`、`CALCULATION_EVIDENCE_SPEC.md` 等既有规范；实际字段及实现以项目当前已生效规范为准，冲突须显式评审。

---

## 1. 背景、目标与非目标

### 1.1 背景

- 用户已有**同花顺投资账本**，用于管理不同 A 股账户的投资收益；本阶段**不重复开发 A 股账户账本**。
- 目前缺少适合统一统计**境外证券账户**收益的工具。CRS 已规划富途（Futu）与盈透证券（IBKR）的交易导入、标准化交易记录、汇率及税务 FIFO 引擎，可在这些能力之上建设独立的投资绩效模块。
- 当前重点覆盖港股、美股，以及境外账户可能涉及的新加坡证券；统计口径以“账户/资产所属投资范围”为准，而不是简单按券商名称判断市场。
- 目标为**本地、完全离线、可审计、可复现**的收益统计，不依赖登录券商账号、实时行情 API 或云端服务器。

### 1.2 要回答的核心问题

1. 我在所有境外账户中，扣除费用后总共赚了多少钱？
2. 考虑历次入金、出金和投入时点，我的实际年化收益率是多少（XIRR）？
3. 排除出入金时点干扰后，投资策略在各年度表现如何（TWR）？
4. 富途和 IBKR 分别表现如何；跨账户转钱、转股票是否被重复计算？
5. 盈亏来自哪些股票、股息、外汇变动以及融资利息？
6. 哪些统计结果已由结单核对，哪些是重建/估算，哪些因资料不足不能算？
7. 与可选基准指数比较，是否获得超额收益？

### 1.3 本阶段不做

- 不替代同花顺投资账本、不强制导入或同步 A 股账户。
- 不自动访问券商账号、下载数据、拉取在线行情或同步云端。
- 不把投资绩效收益率当作 CRS 税务应税所得口径。
- 不在首版覆盖复杂期权策略、期货、CFD、债券久期归因、借贷证券、加密资产等；发现相关数据时识别并提示“暂不支持或需人工处理”，不得静默忽略。
- 不承诺以缺失历史成本或资产净值数据生成精确的成立以来收益率。

## 2. 用户场景与统计范围

### 2.1 用户与账户

- 用户可管理若干个**境外投资账户**，至少支持富途和 IBKR；未来可扩展自定义券商与手工账户。
- 账户字段：账户内部 ID、券商、别名、账户基础币种、统计起始日、是否纳入合并组合、是否存在融资、数据完整性状态。
- 原始账号仅作为受保护的匹配信息，UI 默认仅展示脱敏别名；不应把账号直接写入普通日志。
- 支持账户分组（如“富途+IBKR”“港股账户”“美元资产”），同一账户可纳入多个**报表分组**，但每份报表的去重及范围必须明确。
- 允许股票跨市场/双重上市，同一证券识别使用证券主数据及稳定标识（券商代码+市场+币种及可用 ISIN），避免仅按股票简称聚合。

### 2.2 支持资产（V1）

- 股票、ETF、现金及外币余额、应收股息/利息（若可靠）、负现金/融资借款及应付融资利息。
- 支持 HKD、USD、CNY、SGD 为首批币种；数据库与算法应允许扩展其他 ISO 4217 币种。
- 证券转仓、拆合股、现金分红、股息预扣税、佣金及费用属于首版必须识别的事件。
- 尚未支持的公司行动（如复杂分拆/合并、供股、实物分派等）设为待核对事件，不可无提示计入绩效。

### 2.3 时间窗口与币种

- 支持：本月、本年、上一自然年、近 12 个月、近 3 年、成立以来、自定义起止日。
- 报表展示币种：默认 **CNY**，可切换 HKD / USD（未来扩展）；账户原币指标与统一币种指标应分别保留。
- XIRR 是不规则现金流的**年化资金加权收益率**；TWR 默认显示所选区间**累计时间加权收益率**，跨年年化应另列并明示，不得直接对比不同期限的累计与年化百分比。
- 时区和估值日采用明确的市场交易日/报表截止日，保存 UTC 时间戳及本地交易日期；不得将跨市场不同收盘时间混为同一瞬间快照。

## 3. 指标定义和计算规则

### 3.1 必备指标（P0）

| 指标 | 说明 | 备注 |
|---|---|---|
| 期初/期末净资产 NAV | 证券公允价值 + 现金 + 已确认应收 - 融资负债 - 已确认应付 | 必须保留原币明细、估值日及汇率来源 |
| 区间净投入 | 外部入金 - 外部出金（按组合视角） | 内部转账、外汇兑换、股息均不是外部净投入 |
| 区间投资损益 | 期末 NAV - 期初 NAV - 区间外部净投入 | 必须与 NAV 桥接表核对；证券实物出入按市值计入外部流量 |
| 累计投资损益 | 自可信统计起点至报告日的投资损益 | “可信统计起点”不得伪造为开户日 |
| TWR | 外部现金流切分子区间，各期收益几何链接 | 仅在所需估值点可靠时标为“已核对/重建” |
| XIRR（MWR） | 以期初 NAV、期间外部现金流、期末 NAV 求解年化回报 | 不收敛、多解或不足数据必须提示 |
| 已实现/未实现损益 | 证券卖出及当前持仓的市场损益 | 独立“投资绩效成本口径”，不得冒用税务结果 |
| 股息与利息净收入 | 区分毛额、预扣税、实收净额 | 属于投资收益，不是外部入金 |
| 费用和融资成本 | 佣金、平台费、交易税费、融资利息等 | 明确总收益/净收益和税前/税后口径 |

**净值桥接校验**：`期末NAV = 期初NAV + 外部净投入 + 投资损益`。对不能解释的差额单独记录为 `ReconciliationDifference`，不得自动摊入收益。

**区间范围**：任何“区间投资损益”与 XIRR 都必须有可信期初 NAV 和期末 NAV；中途首次导入不代表期初 NAV = 0。

### 3.2 TWR（时间加权收益率）

- 按外部现金流发生时点切分子期间，严格匹配外部流量前/后的净值（或清楚定义的日初/日末口径）。
- 子期间收益按 `TWR = ∏(1 + r_i) - 1` 进行几何链接。
- **精确 TWR**：有可用资金流时点及对应估值；**日频重建 TWR**：使用完整仓位、现金、行情和外部现金流在确定的 EOD/BOD 约定下重建，并明确估计误差来源；**Modified Dietz**：当无法满足前述数据要求，可单列近似收益率，不得冠名为精确 TWR。
- 多个市场跨时区、周末入出金、同日多笔流量、负 NAV、高杠杆、闭仓重新开仓均需作为测试场景；零或负分母时返回不可计算/需人工确认。

### 3.3 XIRR（资金加权收益率）

- 从**投资者现金流方向**定义符号：区间期初 NAV 为负；外部入金为负；外部出金为正；期末 NAV 为正。区间 NAV 为负的特殊杠杆账户应单独校验有效性。
- 保留精确金额和日期，按实际日期间隔及 365 天折现；折算至同一种报告币种后求根。
- 计算必须至少存在正、负两类现金流；不存在数值根、不收敛或出现多个有效根时标记异常，不能默认显示 0% 或任意一根。
- XIRR 数值求解需有迭代上限、精度门槛、不同初值检查、单元测试、和 Excel/XIRR 官方示例交叉校验。
- 单股 XIRR 是**证券视角**：买入=流出、卖出与股息=流入、期末剩余市值=流入；区间起点已有持仓则以起始日市值作为投入，不直接沿用若干年前买入金额。

### 3.4 收益与损益口径

1. **账户总回报**优先从 NAV 和外部资金流确认，不依赖税务 FIFO 的损益加总；避免漏掉股息、现金、融资和汇兑。
2. **单股成本/持仓损益**单独定义投资绩效成本分配法；V1 可以采用与当前交易账本一致的逐笔匹配实现，但须有明确 `PerformanceCostMethodVersion`。此法与税务 FIFO 结论不保证一致。
3. 境外股息既可显示毛额、预扣税、实际净额，又应默认按**扣除源泉预扣税与投资费用后的账户净回报**展示；个人最终所得税若未从账户真实扣款，不应未经选择直接从 NAV 里扣除。
4. 港币/美元股票按 CNY 报告时应包含真实汇率变动；分析汇率贡献要避免与股票价格收益重复加总。
5. 当存在融资时，以**净资产 NAV（资产减负债）**为绩效基础，同时单独显示总资产、借贷额、融资利息与杠杆率，避免把借入资金当外部投入。
6. 外汇交易只是账户内部的币种转换；汇兑手续费与汇率点差通过现金资产变化体现，不应算作新增入金。

### 3.5 可选指标（P1/P2）

- P1：年度收益率列表、年度收益金额、股息贡献、单股累计总回报、收益前/后 10 名、账户对比、净值曲线、最大回撤。
- P1：可离线导入的指数基准。2026-10-13 用户确认首批固定为**标普500、纳斯达克综合指数、上证综指、中证500**；纳斯达克明确采用综合指数。基准必须标注**总回报/价格指数**、币种、费用假设和数据区间；使用同一基础货币和起点 100 做比较。该确认更新基准范围，当前仍优先交付 P0。
- P2：行业/国家/资产类别贡献、外汇归因、夏普率、波动率、年度热力图、税前/税后回报对比、滚动收益分析。

## 4. 数据来源、导入与质量控制

### 4.1 来源优先级

1. 券商官方活动结单、日结单/月结单、历史资产净值报表（交易、现金、融资、公司行动、NAV）。
2. 已由 CRS 标准化导入的富途、IBKR 历史交易及资金事件。
3. 手工导入/补录的期初资产、外部现金流、价格、汇率、估值快照，必须标明用户录入。
4. 纯推算/重建数据须标明为 `Reconstructed` 或 `Estimated`，不得与原始结单同等视为已核对。

> 对 IBKR，可研究 Activity Statement、PortfolioAnalyst 的官方 CSV/PDF 报告用于校验；对富途先依现有映射规范分析实际可取得的结单字段。**不得假定任意券商文件一定含有全部所需字段或固定导出格式**。

### 4.2 必须支持的事件分类

| 事件 | 账户层级 | 合并组合层级 |
|---|---|---|
| 外部银行入金 / 出金 | 外部资金流 | 外部资金流 |
| 富途 → IBKR 现金转账 | 富途流出、IBKR 流入 | **内部转账：净额为 0**（折算差异及费用单列） |
| 账户内 HKD ↔ USD 兑换 | 非外部现金流 | 非外部现金流 |
| 买卖股票 / ETF | 内部投资交易 | 内部投资交易 |
| 现金股息、利息、股息预扣税 | 投资收入/成本 | 投资收入/成本 |
| 交易佣金、平台费、融资利息 | 投资成本 | 投资成本 |
| 富途 → IBKR 证券实物转仓 | 按转出/转入日公允价值记为账户外部证券流 | 整体范围内内部证券划转，**不产生合并组合收益或资金净流入** |
| 从合并范围之外转入证券 | 实物资产流入 | 按公允价值记录外部证券流入 |
| 拆股、合股等无现金公司行动 | 调整持仓数量及单位成本 | 不直接创造收益 |
| 复杂公司行动 / 无法识别事件 | 待核对 | 不得静默确认收益 |

- 跨账户匹配应按金额/币种/日期/证券/数量/券商参考号及费用容差关联，允许人工确认。
- **合并组合必须只在当前被选择的账户范围内消除内部转账**：若只选择富途，该笔转出对于富途仍是外部流出；若富途与 IBKR 同时入组才消除。
- 实物转仓的市值与后续成本追踪应分开处理：绩效视角转仓不应带来虚假回报，税务成本继承按独立税务规则执行。
- 导入资金变动事件必须防止与标准化成交现金分录、券商结单汇总重复记账。

### 4.3 原始记录和重复导入

- 保留加密存储的导入文件原始内容/经确认的标准化原始快照及 SHA-256 哈希；文件格式或体积限制遵循现有导入基础设施约束。
- 每笔事件建立稳定的 `SourceDocumentId` + `SourceRowIdentity`，以业务键+来源追踪，实现幂等导入、重新导入预览、重复/冲突报错。
- 对同一账户的同一天多来源 NAV 冲突，须标记来源、时间点、币种和差异，不自动挑选“较大值”。
- 发生导入规则修正时，可重新运行标准化，但原始文件及已发布的历史绩效结果不可静默覆盖。

### 4.4 价格与汇率

- 价格来源：优先结单估值，其次用户离线导入的历史行情数据；保存是否复权、交易所、币种、价时、来源和版本。
- 汇率来源遵循现有 `EXCHANGE_RATE_SOURCES.md`；同时存储实际成交换汇率与报表估值汇率，分别用于实际现金变动和统一币种估值。
- 周末/假期或缺失行情：允许显式配置合规的最近有效收盘价回退窗口，并显示价格日期；超出窗口或发生重大公司行动后不可默认继续沿用旧价。
- 对于无法取得的必要行情和汇率应阻止“已核对”绩效状态，允许展示有条件的估算，但需清晰列出缺失资产/日期。

### 4.5 数据完整性状态

所有统计结果必须伴随状态：

- `Verified` 已核对：与券商结单 NAV、现金流及关键持仓在容差内一致。
- `Reconstructed` 可重建：依据完整、可追踪的交易/估值重建，尚未完成全部结单核对。
- `Estimated` 估算：采用 Modified Dietz、价格回退或人工估值等简化方法。
- `InsufficientData` 不可计算：缺少起始净值、结束净值、外部资金流或关键资产估值。

不同指标可有不同质量等级（例如累计损益已核对，但精确 TWR 仍缺分段估值）；不能仅给整份报表一个“已完成”状态。

## 5. 功能与交互需求

### 5.1 海外投资绩效工作台（P0）

顶部操作：`账户/组合选择`、`统计周期`、`展示币种`、`更新/重算`、`数据质量`、`导出`。

首屏显示：

- 期末净资产（含与账户结单的差异提示）
- 区间累计投资损益
- 区间 TWR（明确精确/重建/无法计算）
- 区间 XIRR 年化（不收敛显示原因）
- 区间外部净投入
- 当前数据截止时间和完整性状态

页面下方：账户分布、净值曲线（数据足够时）、年度绩效、数据异常列表。每个指标可下钻“定义与计算依据”。

### 5.2 多账户分析（P0）

- 展示富途 / IBKR 独立指标及合并组合指标。
- 报表可切换“账户视角”“合并组合视角”，明确对内部转账消除范围。
- 允许任意指定多个账户组成临时分析组合；可保存为用户命名的组合。
- 展示净资产、现金、融资负债、币种敞口、外部流量、收益差异。

### 5.3 交易/资金流检查台（P0）

- 列出未匹配内部转账、未知类型资金变动、对账差异、价格/汇率缺口、转仓待确认、期初数据缺失。
- 每个异常可查看原始来源、建议修复动作和修复后影响；支持修订分类并重新计算（保留审计记录）。
- 不允许通过修改原始成交数据“让收益率对得上”；用户修订应作为带来源的调整事件或映射规则版本。

### 5.4 个股绩效（P1）

- 证券维度显示：买入额、卖出回款、实际股息、费用、在途/当前股数、市值、已实现和未实现收益、持有期 XIRR。
- 支持同一证券跨多个账户合并查看，但同股不同市场代码和不同币种需要明确证券关联关系。
- 展示“交易明细 → 现金流 → 投资回报”的逐项展开与跳转。

### 5.5 年度报告与基准比较（P1）

- 每年展示期初 NAV、净投入、期末 NAV、投资损益、TWR、XIRR 和数据可信度。
- 对比基准采用一致的区间和折算币种；对基准未覆盖日历/上市前期间提示数据不可用。
- 导出摘要报告与完整审计版报表；遵守 CRS 既有敏感文件导出安全要求，防止 Excel/CSV 公式注入。

## 6. 建议数据模型（与现有实体映射，不强制重复造表）

| 实体/逻辑表 | 主要字段或职责 |
|---|---|
| `InvestmentAccount` | AccountId、Broker、Alias、BaseCurrency、ScopeFlag、EffectiveFrom |
| `InvestmentPortfolio` | PortfolioId、Name、SelectedAccountIds、ReportingCurrency |
| `PortfolioScopeHistory` | 组合成员历史（避免历史报表随选中账户变化） |
| `NormalizedInvestmentEvent` | 类型、资产、金额、币种、日期时间、来源键、关联交易；优先复用现有标准化流水 |
| `CashFlowClassification` | IsExternal、BoundaryScope、方向、确认状态、分类版本 |
| `TransferLink` | 转出/转入事件、跨账户匹配、汇率、差额、费用、确认人及时间 |
| `PositionSnapshot` | 账户、证券、日期、数量、成本参考、估值状态 |
| `ValuationSnapshot` | AccountId/PortfolioId、AsOf、BaseCurrency、Assets、Cash、Liabilities、NAV、Source、Quality |
| `SecurityPriceSnapshot` | 证券、交易市场、估值日、币种、价格、价格类型、来源 |
| `FxRateSnapshot` | 货币对、日期、类型（成交/估值）、来源、版本 |
| `PerformanceRun` | RunId、范围、时间、参数、规则版本、数据版本/哈希、时间戳、执行状态 |
| `PerformanceMetric` | RunId、MetricId、Value、Unit、AnnualizedFlag、Quality、Explanation |
| `PerformanceIssue` | 问题类型、关联来源、严重程度、处理状态、对结果影响 |
| `PerformanceReconciliation` | 各日/各账户净值与账单差异、阈值、解释及审查记录 |

要求：

- 金额、数量和汇率的**存储**采用固定精度表示（如数据库 Decimal 映射策略或定点整数），避免二进制浮点累计误差；数值求根内部可用 `double`，输出按统一精度约束并做残差验证。
- 运行结果必须可追溯到输入版本（交易/价格/FX/NAV/分类规则），同参数和同版本数据应得到确定性输出。
- 外部入金与转仓关联到用户选定的**组合边界**，不要把 `IsExternal` 做成脱离统计范围的永久单值。
- `PerformanceRun` 不得回写税务计算结果；税务计算版本改变后如影响共享标准化数据，必须提示用户重算绩效并记录版本差异。

## 7. 架构及模块边界

```text
Crs.Domain
  ├─ Tax                         # 现有税务领域
  └─ Performance                 # 新增：收益率、组合、现金流、估值领域模型
Crs.Application
  ├─ Tax
  └─ Performance
       ├─ ImportAndReconcile
       ├─ BuildValuation
       ├─ CalculateReturns
       ├─ AnalyzeSecurityPnl
       └─ GeneratePerformanceReport
Crs.Infrastructure
  ├─ SecureDatabase              # 复用 SQLCipher
  ├─ BrokerImporters             # 复用富途/IBKR 导入
  ├─ HistoricalMarketDataImport  # 离线价格与汇率导入
  └─ PerformancePersistence
Crs.Wpf
  ├─ TaxCenter
  └─ PerformanceCenter
       ├─ Overview
       ├─ Accounts
       ├─ Securities
       └─ DataQuality
```

建议服务接口（名称仅为设计建议）：

- `IPerformanceCalculationService`：计算 TWR、XIRR、NAV 桥接与年度绩效。
- `IPortfolioBoundaryService`：判断所选范围内的外部/内部流量。
- `IValuationService`：读取或重建资产净值，追踪价格与汇率来源。
- `ITransferMatchingService`：现金/证券跨账户匹配与人工复核。
- `IPerformanceReconciliationService`：与结单对账、差异分类。
- `IPerformanceReportingService`：一致口径导出及版本快照。

严格区分职责：**税务 FIFO 引擎负责税务口径；投资绩效引擎负责经济收益率**。二者复用来源记录但不互相当作真值。

## 8. 安全、隐私与离线要求

- 沿用 CRS 已确定的 SQLCipher 加密数据库、主密码/离线 TOTP、敏感文件导出控制与安全日志脱敏。
- 账户原始编号、交易明细、历史 NAV、绩效报表均视为敏感数据；文件导入和报表导出不得在未加密临时目录长期留下副本。
- 禁止后台向任何第三方发送交易、账户或持仓数据；用户主动访问外部网站不属于本模块自动数据链路。
- 加密备份必须包含收益统计需要的历史价格、汇率、估值快照、分类规则和历史绩效版本，否则跨电脑恢复后会出现“税务能算、收益率不能算”。
- 原始数据库、导入文件与历史 `PerformanceRun` 在恢复后必须完成完整性核验。

## 9. 关键验收标准（首版必须覆盖）

| 编号 | 验收场景 | 预期 |
|---|---|---|
| PA-01 | 只有成交，无入出金和期初/末 NAV | 不显示伪精确 TWR/XIRR，提示缺项 |
| PA-02 | 单账户初始 10,000、期末 11,000、无现金流 | 区间 TWR=10%；一年期 XIRR 约为 10%（按实际天数） |
| PA-03 | 期间增加入金且市场无涨跌 | 区间投资损益和真实回报应为 0（在完整 NAV/流量条件下） |
| PA-04 | 富途转 HKD 至 IBKR，均在组合范围内 | 合并组合不算外部流量；各账户分别反映出入 |
| PA-05 | 富途/IBKR 内部换汇 | 不算外部入金，不创造无依据收益 |
| PA-06 | 富途股票实物转仓 IBKR | 合并组合资产连续，转仓本身不产生回报 |
| PA-07 | 股息 100，预扣税 10，到账 90 | 净股息增加 90（无其他因素）；股息不是外部流量 |
| PA-08 | 账户证券资产 120，借款 20（同币种同单位） | NAV=100，借款不算外部资金贡献 |
| PA-09 | 相同文件重复导入 | 不重复记账，保留来源及冲突处理 |
| PA-10 | 价格或汇率缺失且超出可接受回退范围 | 结果标记 Estimated/InsufficientData，列出缺项 |
| PA-11 | 更换报告币种 CNY→USD | 以同期匹配的历史汇率重新估值，保留同一输入规则版本 |
| PA-12 | XIRR 现金流缺少正负符号/无解/多解 | 显示未定义/无法确定与原因，不填 0% |
| PA-13 | 只有半年的可靠历史、用户选择成立以来 | 只计算有效覆盖期并警告，不回溯虚构历史 |
| PA-14 | 导入交易与结单现金汇总出现重复 | 通过来源/分类避免重复记账，异常可追溯 |
| PA-15 | 两次同数据同规则重算 | 输出一致，包含输入哈希与引擎版本 |
| PA-16 | 同一笔转账一侧账户退出统计组合 | 对新范围正确识别为外部流量 |
| PA-17 | 历史加密备份在另一电脑恢复 | 能恢复账户、估值、汇率、绩效快照和原始证据 |
| PA-18 | 股票拆股但市值不变 | 不产生凭空收益，持仓数量按公司行动调整 |
| PA-19 | 税务 FIFO 重算后 | 投资绩效记录不会被税务计算静默覆盖 |
| PA-20 | 导出含特殊字符的券商描述字段 | CSV/Excel 不执行公式，敏感数据处理策略生效 |

**对账阈值**：不采用一个适用于所有币种/规模的固定容差。规范实现需支持“原币绝对金额 + 相对比例 + 最小货币单位”组合配置；超出阈值必须显示差异来源。

## 11. 待决策项（不阻塞 P0 基础建模）

1. 统计起点：使用各账户最早**可核验完整 NAV** 日期，还是允许用户指定统一起始日？**默认：最早可信完整 NAV 日期，并允许后续指定共同区间。**
2. 默认收益率：主页同时显示 `TWR(区间累计)` 和 `XIRR(年化)`；不强制只选一种。
3. 估值时点：按账户结单与市场 EOD 来源明确映射，跨市场/跨时区需要单独规则及对账样本。
4. 价格文件：优先重用现有汇率/行情配置；不强制绑定第三方行情 API。
5. 账户维度：是否纳入保证金、证券借出及其他非证券资产。首版以明确列入的账户资产范围为准，不能漏记后仍展示已核对。
6. 投资绩效的“总收益 vs 净收益”和股息预扣税口径：默认净收益，并允许另设毛收益补充分析。
7. 组合成员变化时，保留历史范围版本，保证相同 `PerformanceRun` 可复现。

# 保险库与 Authenticator 当前实现

2026-10-10，按最新用户确认接入“首次主密码保护数据库、日常仅手机验证码进入”。本机 DEK 由 Windows 当前用户 DPAPI 保管，主密码和独立数据库恢复槽继续支持跨电脑恢复。本文记录源码行为和验收边界，不能替代正式安全发布审批。

## 使用流程

1. 新空目录创建保险库，设置至少 12 字符的主密码，离线保存一次显示的数据库恢复密钥。
2. Microsoft Authenticator 中选择“添加账户 → 其他账户”，扫描界面的二维码，输入六位验证码。
3. 离线保存八条手机恢复码，分别勾选数据库恢复密钥、手机恢复码的保存确认，再进入工作区。
4. 默认在已启用的 Windows 用户环境中打开或解除锁定，只需手机验证码，成功直接进入，不显示数据库位置、创建主密码入口或主密码输入框。同一组验证码只能消费一次；刚绑定、登录或改密后，请等待下一组代码再进行敏感操作。
5. 左侧入口可主动锁定；十分钟无真实输入、Windows 锁屏／注销、休眠／恢复会失效会话。旧仓储、旧导出和后台任务不能借新解锁复活。

首次设置／显式恢复时由主密码解封 DEK，日常由 DPAPI 本机槽准备五分钟受限上下文，两者均不发布业务仓储。只有手机验证成功后才开放业务；首次绑定还必须确认保存恢复凭证。本机槽只在完整认证后原子写入，不保存主密码。超时清空二维码和恢复显示；中断初始化仍须用已设置的主密码继续绑定，不能以目录存在判定已认证。

换电脑、更换 Windows 用户资料、本机槽损坏或丢失时，使用原主密码及手机验证码重新启用本机登录，不重新创建数据库；遗忘主密码可以通过独立数据库恢复密钥重设并强制重新绑定手机。安全窗口也提供“本机凭证异常”选项，避免损坏凭证形成无恢复入口。

## 设置手机验证与目录显示

左侧“设置 → 登录验证”提供“启用手机验证”，默认开启。关闭后，已完整初始化的保险库使用当前 Windows 用户保护的本机密钥直接进入，不显示验证窗口、不要求手机代码；数据库仍加密。启动与解除锁定均在创建验证窗口之前完成本机登录检查；凭证缺失、损坏或初始化未完成时仍进入设置／恢复流程。重新启用后，下次进入／解除锁定恢复手机验证。关闭不删除已有手机绑定，恢复启用仍可使用原 Authenticator 代码。

修改时填写主密码和一组新的六位代码，点击“保存手机验证设置”。该开关直接保存到加密认证表并记录审计，与“保存目录和日志设置”分开；修改 settings.json 不影响登录保护。开关保存使用 SecurityVersion=2，旧程序不能忽略新版开关继续打开。旧加密库保持默认开启，首次切换时事务升级认证表；不涉及明文库迁移。备份包含该策略，恢复后保留备份时的启用／关闭状态。

首次创建或目录格式异常时显示位置选择；日常登录隐藏路径。在安全窗口展开恢复选项、勾选“选择其他数据库位置”可主动显示目录。未完成初始化／密码恢复的库不能凭关闭开关绕过绑定确认。

关闭手机验证意味着保护依赖当前 Windows 用户环境及本机受保护密钥；能使用该用户环境的人可直接进入应用。新电脑或本机槽失效仍需要原主密码／独立恢复路径，不会变为明文库或游客访问。

## 恢复与更换手机

- 手机丢失：验证主密码，再消费一条未使用的手机恢复码。进入只允许重新绑定的状态，必须完成新手机验证及新恢复码保存确认。
- 忘记主密码：独立数据库恢复密钥解封 DEK，重设密码并强制重新绑定手机。数据库恢复密钥与手机恢复码用途不同。
- 更换手机：当前已认证会话中验证旧密码与新的旧手机验证码，扫描新手机。新手机首码通过后替换绑定并旋转全部手机恢复码；首码未通过或取消时旧绑定仍有效。
- 改密：要求已认证会话、旧密码及新验证码；仅替换密码封装，随机 DEK 与数据库恢复密钥不变。
- 恢复备份：只恢复到新空目录，恢复后仍须手机验证。旧备份会重现旧绑定、恢复码与消费记录；离线快照不能保证旧凭证全局撤销。遗失手机时使用明确恢复入口重新绑定。

数据库恢复密钥与主密码全部丢失后不能按便携备份方案迁移到新电脑；本机槽仍可用且手机有效时，日常访问可继续，但它不能重设未知主密码。本机槽也不可解封时，没有后门。明文 SQLite 库不读取、不迁移、不删除、不覆盖；不能用于创建或恢复目标。

## 实现边界

CRS.Security 保留 Cryptography、Vault、Recovery 分层，新增 Authentication/Totp 和 MfaRecoveryCodes。仅使用 .NET 密码学基础 API，实现 RFC6238 HMAC-SHA1、六位 ASCII、30 秒 UTC 步骤、前后各一步窗口，并用全部六组 SHA1 标准向量检验；没有新增候选 Otp.NET 依赖。

Infrastructure 中的 VaultAuthenticationStore 使用受限 SQLCipher 连接管理 SecuritySettings、RecoveryCodes、SecurityEvents。验证码验证与步骤消费处于同一个写事务中，条件更新必须影响一行；并发只能有一个成功。五次失败持久冷却十五分钟，当前进程另有递增延迟和单调时钟辅助。时钟回退不能重复消费当前数据库上的已用步骤；恢复旧快照的风险不能由纯离线软件消除。

TOTP Secret 是独立随机 20 字节，仅写入加密库。二维码由固定 QRCoder 1.7.0（MIT）在内存生成，不保存 URI、二维码图片或复制到剪贴板，不使用微软在线账户、推送或网络服务。八条手机恢复码各有 128 位随机熵，库中只存随机盐、用途隔离 SHA-256 哈希与单次消费状态。审计只记录类别、结果、时间与保险库标识，不记录秘密。

主密码、Argon2id、AES-GCM 封装、SQLCipher、恢复槽及加密在线备份沿用原方案。新增 Infrastructure/DeviceKeyStore，固定 System.Security.Cryptography.ProtectedData 10.0.12（MIT），以 CurrentUser 和绑定 VaultId 的用途数据保护随机 DEK，密文存于 vault.device。便携备份不含此 Windows 本机槽，恢复时依靠主密码或独立数据库恢复密钥；因此 DPAPI 不是唯一恢复条件。参见 [微软包说明](https://www.nuget.org/packages/System.Security.Cryptography.ProtectedData/10.0.12)。实际本机 SQLCipher 引擎报告 4.5.2 community；NuGet 包版本不代表引擎版本或官方支持。普通报表、结转与原始券商文件仍需用户管理。

**离线 TOTP 是客户端业务访问门槛，不是数据库密钥的第二重加密。** 掌握主密码者仍可能在程序之外解封 DEK；能使用当前 Windows 用户资料的进程也可能解封本机槽，因此本次免输入主密码策略将本机保护边界扩展为 Windows 用户环境，不能承诺阻挡同用户恶意程序、管理员或客户端补丁。锁定会销毁业务内存会话，但保留受保护本机槽供下一次手机验证。托管运行时中的秘密字符串、二维码显示缓冲也无法保证绝对擦除。

本机登录专项使用真实 Windows DPAPI：确认保存恢复凭证前不记本机密钥；本机解封不授予业务；日常无主密码输入仍须 TOTP；损坏／丢失／身份混搭槽阻断；原主密码重新启用；便携备份不携带本机槽，恢复后重新启用。

# 加密保险库与恢复

> 首次设置主密码保护数据库，日常在已启用的 Windows 用户环境中只用 Microsoft Authenticator 验证码进入。首次扫码、本机密钥、两种恢复凭证、改密与换手机边界见 [AUTH_IMPLEMENTATION.md](AUTH_IMPLEMENTATION.md)；下文密码学与备份基础方案继续适用。

首次启动先选择保险库目录。不存在保险库时，明确点击“首次创建并加密”，填写至少 12 个字符的主密码、绑定手机，并离线保存恢复凭证后进入。日常只输入手机验证码。本机受保护槽不可解封、主密码和恢复密钥也全部丢失时，没有管理员密码或软件后门可以恢复；两种离线凭证丢失后也无法依靠便携备份迁移到新电脑。

已有明文 `crs.db` 时本版本直接拒绝，不连接、读表、迁移、删除或重命名；旧 WAL／SHM、明文备份和同步副本也不会自动清理。请选择新空目录创建加密保险库，再从券商原件重新导入。不能通过更名数据库把旧资料带入新库。

## 目录结构和实现

```text
CRS.Security
├── Cryptography
│   ├── KeyDerivation.cs          Argon2id 和参数校验
│   ├── KeyWrapping.cs            AES-256-GCM 密钥封装
│   ├── AuthenticatedEncryption.cs 认证正文加密与用途隔离
│   └── SecretKey.cs              受控密钥材料
├── Vault
│   └── VaultKeyManager.cs        随机 DEK、主密码解锁、改密
└── Recovery
    └── RecoveryKeyManager.cs     独立恢复凭证和恢复槽
```

Security 不访问文件，不引用任何 CRS 业务项目、WPF、Dapper 或 SQLCipher。Application 只引用 Domain，安全端口不暴露密钥。Infrastructure 执行 SQLCipher、文件、会话和备份 I/O；前台经 Application 端口操作，启动组合根负责装配。

新保险库包含 SQLCipher 4 格式的 `crs.db` 和非秘密密钥封装元数据 `vault.json`。数据库密钥为随机 256 位 DEK，不使用主密码直接开库。主密码通过每槽随机 Salt 的 Argon2id 派生 KEK，以 AES-256-GCM 封装 DEK；恢复槽使用独立随机秘密及 HKDF。版本一固定参数为 65536 KiB、3 次、并行度 2；本机创建含首次派生实测约 425—583 ms，不是所有设备的性能保证。未知 KDF 参数在分配内存前拒绝。

实际使用 `Microsoft.Data.Sqlite.Core 10.0.12`、`SQLitePCLRaw.bundle_e_sqlcipher 2.1.11`，随机 DEK 按 SQLCipher raw-key 形式设置；每次连接核对 `cipher_version`，没有加密提供器即失败，禁止回退标准 SQLite。启用内存临时表、密钥内存清理配置及外键；不使用连接池。SQLCipher bundle 是社区构建，不能宣称为 Zetetic 官方支持或已经通过公开发行供应链审查。参见 [微软加密指南](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/encryption) 和 [SQLCipher API](https://www.zetetic.net/sqlcipher/sqlcipher-api/)。

## 锁定与改密

菜单提供“保险库与备份”和“锁定”。10 分钟无输入、Windows 锁屏／注销、休眠／恢复时触发安全关闭；工作区重新进入需要解锁。锁定销毁当前会话，旧仓储和旧导出门闩不能借后续解锁复活。正在执行的数据库或文件提交与锁定串行；锁定返回后旧会话不能继续提交。导入和下载取消；被取消的旧任务无法保存进新会话。

改密要求验证旧主密码，仅原子替换密码封装槽，随机 DEK 和恢复密钥不变。遗忘密码时必须使用恢复密钥验证、检查库完整性，再设置新密码。启动向导因系统锁屏关闭后，重新运行程序继续解锁。受托管运行时和操作系统影响，不承诺所有内存副本彻底擦除，无法阻挡管理员级运行时监控。

## 加密备份与离线恢复

解锁后在安全入口选择新的 `.crsbak` 路径，点击创建加密备份。备份调用 SQLite 在线备份 API 取得一致的加密快照，包括尚在 WAL 中的已提交记录；不是复制正在写入的数据库。快照验证完整性后，与封装元数据、摘要一起用 HKDF 用途隔离后的 AES-256-GCM 密钥认证加密，容器自带版本和恢复槽；正文和凭证原文不会直接写入备份文件。

外层可见格式、保险库标识、非秘密封装参数及密文长度，因此不能认为文件大小等元数据也被隐藏。临时快照本身仍为 SQLCipher 加密库，完成或失败后清理；没有明文数据库临时副本。当前实现是内存容器，限制加密数据库 128 MB、备份容器 256 MB，超限明确失败而非降级成明文备份。备份不覆盖已有路径。

恢复时选择备份、新的空目标目录，提供**备份时**的主密码或独立恢复密钥，并设置新主密码。先验证认证标签、元数据、摘要、SQLCipher 和业务版本，成功后才提交暂存目录。支持换 Windows 用户或电脑，不使用 SID、硬件绑定或 DPAPI；同目录覆盖恢复完全禁止。恢复后的旧原件路径只是业务来源信息，仍需自行保留券商原件。

旧备份仍可使用备份时密码或恢复密钥，修改当前保险库密码不会撤销已经复制出去的旧备份。备份必须包含 `vault.json` 的封装信息；单独复制 `crs.db` 不能作为完整恢复方案。

Excel、结转 JSON 和下载的券商原件仍是用户主动选择的明文材料。普通导出要求明确确认，失败时不留下半成品目标；公开版独立加密报表导出尚未实现。

## 验证与发布边界

安全专用测试覆盖解封、恢复、错误凭证、参数上限、篡改、改密及释放；基础设施测试覆盖实际 SQLCipher、无密钥连接拒绝、WAL 不出现合成敏感字符串、一致性加密备份、两种凭证恢复、目标及备份覆盖拒绝、旧会话阻断、明文旧库与 WAL 保持原样。架构检查和原有财务回归独立运行。

模拟恢复到新的隔离目录不等于真实不同电脑、Windows 锁屏／休眠硬件或安装包的人工演练。公开发行前仍需供应链／原生许可证、真实跨设备恢复、安全评审、安装包签名及业务验收；`ReleaseApproved=false` 保持不变。

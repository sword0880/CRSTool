# 年度计算职责与对账性能优化

日期：2026-10-10。范围：共享后台及 WPF 验证。前两轮按当时要求停止维护 WinForms；随后按用户最新要求删除项目和 AntdUI，当前只有 WPF。

## 依据与调整

原 CalculationService.CalculateParsed 同时处理账户范围、期初结转、报告连续覆盖、FIFO、三项对账及快照封装。程序集拆分后，这些职责仍集中在一个方法，修改报告检查时容易连带影响结果封装。

- 期初及报告检查移至 Application/Imports/AnnualInputPreparation：保留年度账户选择、结转复制、富途真实成本门槛、逐账户报告覆盖及取消检查。
- 三项核对移至 Application/Reconciliation/AnnualReconciliation：保留持仓可信性、收益差异容差、可空未知收益及现金风险说明。
- 卖出收益核对原先为每笔卖出执行 matches.Where，工作量随卖出数乘以年度匹配数增长。现在一次建立完整 SecurityKey 与 SellId 的索引；账户、券商、市场、币种和证券仍全部参与隔离。收益汇总顺序和 decimal 金额语义保持一致。这是扫描次数优化，未做真实账户耗时基准，不声称固定加速倍数。

两个组件为 Application 内部类型，前台仍通过既有用例入口操作。未增加新的公共用例或框架，也未更改 SQLite、JSON 快照格式和税务规则。

## 验证

Application 新增四组端到端计算检查：年度开始缺一天、结转余额不被消耗及跨券商拒绝、跨账户相同卖出编号与未知成本隔离、导入完成后取消。使用合成事实，经公开 CalculationService 入口运行。

本次验证均通过：68 项综合回归、Application 10 项检查、WPF 展示模型 5 项检查、架构边界检查；WPF 及相关验证项目 Release 构建零警告、零错误。隔离数据库的 WPF 实际窗口检查通过，覆盖九页导航、测试报告计算、历史、复核、导出和取消流程。未执行 WinForms 窗口验收。

## 保留的问题

快照封装仍在 CalculationService 中。严格历史重放仍存在结转确认语义、执行版本和同秒排序等既有缺口，见反方复审 AR-02～AR-04。系统日期与缺失冻结汇率回退已在下面的第二轮调整中处理；其余问题需要版本化快照契约和专门验收。

多账户年度聚合尚未接入 WPF 选择流程，旧结转兼容与抵免证据门槛也继续保留在原整改清单中。后续优先处理结果可信性的这些缺口，再扩充交互入口。

## 第二轮：历史执行上下文

代码确认 Replay 原先会在冻结汇率缺失时调用当前汇率提供器；Provisional 也按执行当天重新判断。现在 ReplayExecutionContext 校验审计记录中的年度、规则及算法标识，拒绝缺失元数据、错年度、非正汇率和重复币种。重放只使用历史汇率，缺少所需币种时明确失败；重放审计沿用历史配置指纹，临时状态沿用原结果。计算服务使用可注入 TimeProvider，生产默认系统时钟，验证可控制跨年场景。

新增六组检查：当前汇率与配置提供器禁止访问仍能重放、缺失冻结汇率拒绝、重复／无效／错年汇率拒绝、未知规则或算法拒绝、跨年状态不升级、缺失执行元数据拒绝。旧历史的查看与导出路径不经过这些重放门槛。

此调整部分修复 AR-03，但不等于严格历史重放已经完成：执行程序集未被封存，同一标识下的实现兼容性仍待定义；结转确认与同秒排序问题仍未解决。WPF 历史页继续只恢复冻结结果，本次未增加重放按钮。

第二轮实际验证：68 项综合回归、Application 共 16 项检查和架构边界检查全部通过；WPF 与相关验证项目 Release 构建零警告、零错误。未改动界面，未重复执行窗口验收。

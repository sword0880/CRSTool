# WPF 迁移与项目分层评估

更新日期：2026-10-10。此前评估指出共享后台位于 WinForms 目录、Core 内层仅用文件夹隔离、主窗口承担工作流。本次按用户确定的两个方向完成调整。

## 页面方向

以提供的 CRS Tax Manager 图稿作为布局方向，实现左侧导航、年度概览、四个状态卡片和最新任务列表。保留真实年度、账户范围、资料完整性、对账及用途状态；概览没有填入图稿里的演示数量。

业务页面为数据导入、交易记录、FIFO、汇率、税务核算、核对与人工复核、报表导出；历史任务单独放在导航底部。概览卡片可跳转，任务行可恢复冻结结果。导入成功后进入税务页并刷新任务列表。

## 分层方向

| 原问题 | 当前调整 |
| --- | --- |
| 后台放在 CRS.WinForms/src | 共享后台与唯一 WPF 前台位于根目录 src，使用根目录 CRS.sln |
| Domain / Application / Contracts 位于 Core 同一程序集 | 拆为 CRS.Domain 与 CRS.Application，Domain 不引用外层，Application 仅引用 Domain |
| 前台取得 Repository、Reports、CreateCalculator 等实现端口 | WPF 调用 IDesktopUseCases；IDesktopOperations 仅供后台装配 |
| MainForm 保存、导出占用 UI 线程，存在两套编排 | WPF 使用 DesktopWorkflow，计算、SQLite 和输出在后台任务中执行 |
| 单一 MainViewModel 承担全部页面 | 拆为导航壳、共享会话及页面职责模型 |
| 领域层混入历史索引、结果 DTO 和 JSON 快照 | 移至 Application；领域层保留交易、成本、汇率事实和规则 |
| 图表与 Excel 依赖绘图库版本可能分歧 | Directory.Packages.props 集中版本，锁定已验证的 SkiaSharp 与 UI 库 |
| 仅有综合控制台验证 | 保留综合验证，增加 Domain / Application / Infrastructure / Wpf 四个独立验证项目 |

完整结构见 [项目结构](PROJECT_STRUCTURE.md)。所有启动、配置和测试入口已改为中性路径。

## 数据与旧前台

按用户最新要求，2026-10-10 删除 WinForms 项目及其专用 AntdUI 依赖，只保留 WPF。WPF 继续使用原本地数据库目录，沿用已有 JSON 属性、枚举及结转字段，未自动改变旧任务金额。WPF 旧历史可恢复冻结结果并导出；没有完整交易快照时需要重新导入原件查看交易。

ImportedTradeCount 为可空事实：旧任务缺失时显示“未登记”，新任务真实零笔显示 0。SessionTrades 只在本次会话展示，不在默认存储中增加原始交易明细；完整规范化快照依然要求用户选择。

Python 程序已移除，资料归档在 storage/python-legacy，源码可以从 Git 历史恢复。旧版 Python / C# 结转互转仍需专用转换与验收。

## 验证

- 根解决方案覆盖四个生产项目和五个验证项目。
- 原有 68 项综合回归保留并通过；迁移时增加 17 项分层验证，2026-10-10 再增加四组年度计算及六组历史重放检查。
- 架构脚本检查程序集引用、UI 禁止直接访问基础设施、九个页面及集中包版本。
- WPF 实际窗口检查九页导航、绑定错误、历史加载、人工依据、Excel 导出、取消不保存、输入失效与规范化交易恢复。
- 概览、导入和税务页截图已核对。WinForms 窗口检查是迁移阶段的历史结果，停止维护后不再执行。
- Flex 使用模拟协议验证，没有连接真实账户。

## 后续工作

CalculationService 已拆出期初与报告覆盖检查、持仓／收益／现金对账；卖出对账已增加索引。系统日期通过 TimeProvider 注入，历史重放使用独立执行上下文，缺少冻结汇率时拒绝回退当前配置。快照封装与序列化仍可进一步拆解。抵免证据、复杂证券事件、严格历史重放和旧结转兼容等业务问题仍按原复审及整改记录推进。

实时行情采集、节流、重连将来应在后台提供数据接口，WPF 只绑定推送结果。本次没有接入模拟行情或新增税务口径。

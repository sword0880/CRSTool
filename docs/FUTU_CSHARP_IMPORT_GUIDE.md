# 富途 C# 导入与迁移验收

更新日期：2026-10-10。对应开发规范 §6；当前版本使用 .NET 10 WPF、WPF UI、NPOI、PdfPig、NLog，以及 SQLite + Dapper。

## 桌面操作

1. 打开“数据导入”页面，在券商选择框选择“FUTU”，填写测算年度。
2. 点击“选择年度报表”，同时选择一份该年度收入主表（XLSX 或 PDF）和年度交易 XLSX。只有收入表也能输出收入测算，但会明确提示交易和预扣税资料未完整。
3. 有期初持仓时选择“C# 版上年结转 JSON”。也可加入不重叠、连续覆盖的历史年度交易工作簿；必须提供真实历史成本，持仓表的价格仅为市价，不能替代 LOT 成本。
4. 确认最早交易报告期初确实无持仓时才勾选确认；与实际期初持仓矛盾时列为成本问题。确认报告没有过滤账户、证券或现金类型。
5. 开始计算，查看税务汇总、FIFO、年度收入、成交金额核对、资金明细、证券事件、资本收益／入金／现金派息汇总。
6. 导出 Excel 底稿。仅成本链及年末数量满足门槛时开放 C# LOT 结转；未知事件不会因填写备注自动解除。

切换券商会清除已选文件、期初来源和确认，旧结果立即失效。富途不使用 IBKR 下载令牌或期初 XML。程序运行不依赖 Python。

## 输入及计算规则

| 内容 | 当前实现 |
| --- | --- |
| 交易 XLSX | 账户信息、交易流水、持仓总览、资产进出、资金进出、资金总览；按表头读取，列顺序可变，公式／错误单元格拒绝，保留工作表与原始行号 |
| 年度收入 XLSX | 唯一股息收入表；支持原版中文字段及英文别名，年度为四位整数；币种缺列时从股息、利息和其他收入字段共同识别，冲突拒绝 |
| 收入 PDF | 可提取文字的英文账户收入表；带牛牛号／年份／全年收入字段的中文旧表头。三语 CRS 报告优先读取英文收入页一次；未知布局、扫描件、加密或损坏文件明确拒绝 |
| 金额 | 使用 decimal；总费用作为合计，佣金／平台费等不再重复加收；券商成交总额用于 FIFO 分配，缺失时显式重建并列复核 |
| 成交核对 | 数量×价格与有符号成交金额、成交金额减总费用与变动金额分别核对，超过 0.01 原币的差额列复核；异常成本链不发布完整收益 |
| 收入来源 | 年度收入汇总是主数据；现金派息明细只作辅助核对和汇总，不重复计税；其他收入保留原值且列复核 |
| 税款 | 备注含 Withholding Tax 的现金流提取预扣税；负现金流为缴税，正现金流为退回；年度净退税列复核，抵免不为负数 |
| 身份 | 完整账户号码、券商、市场、代码名称和币种隔离库存；收入账户仅在名称唯一匹配时绑定，无法确认时保留独立身份与问题，不猜测跨语言账户关系 |
| 范围 | 同账户同年度成交来源重叠拒绝，不能只按相同行值去重；一批仅允许一份年度收入主表，Excel 和 PDF 不重复计入 |
| 证券事件 | 沿用迁移前的保守规则，资产进出、赠股、更名、拆并股等保留原事件并阻断受影响成本；仅同日 In/Out 不足以证明可信更名。IVD 等未支持事件币种保留原值，不套用汇率 |
| 持仓与余额 | 期初数量不能制造成本；年末数量对照 FIFO。原币资金总览存在时核对期初＋成交净额＋资金流＝期末，缺失余额保持未知 |
| 来源及历史 | 文件用途、SHA256、页码／工作表／行号进入底稿。富途事实进入 SQLite 结果及可选规范化快照，简单零期初场景可服务重放 |

单文件最多 25 MB，单工作表最多 100000 行，一批最多 36 文件，PDF 最多 200 页。参考汇率工作表不参与计算；系统年度汇率配置是实际使用来源。

## 结果限制

富途这些原始文件不提供可用于独立核对的逐笔券商 FIFO 盈亏。即便原币现金和数量一致，也不会显示“全部对账完成”或填充确定的年度预计补税；辅助公式金额和已确定的明细仍可查阅。未支持基金、缺成本、其他收入、账户无法绑定或金额差异均列待复核。

真实样本完成了模板和规范化金额验收，不能替代全部成本批次、税款抵免证据、账户所有权和全年业务验收。通用的历史结转重放、版本冻结、旧结转兼容等缺口继续跟踪 AR-02～AR-12。

## 验证记录

- Release 构建及目录依赖检查通过；68 项常规验证通过：既有 45 项、新增 FUTU-001～022 和 DB-DAPPER-001。
- 显式指定本地样本与 Python 参考事实时，额外 5 项真实样本验证通过，合计 73 项。
- 2021～2025 年成交逐行核对方向、数量、单价、成交总额、费用、现金净额、币种及时间；年度收入按币种核对股息、利息、其他收入，以及预扣税笔数、净税款和入金金额。
- 三语 PDF 的收入与 Python 提取结果一致，只计入一次；中文旧表头使用脱敏合成 PDF 验证，尚未取得该布局的真实年度样本。
- 五年度真实模板完成统一计算入口检查，使用明确标记的固定测试汇率，仅检查流程和复核状态，不签认真实成本或人民币税额。
- XLSX 实际行数不依赖文件内可能错误的 dimension 元数据；仅表头但缺少账户和年度记录的合成文件明确拒绝。
- Dapper 验证覆盖历史索引映射、JSON 恢复、复核正文参数化、重复主键失败后的事务一致性；数据库表结构和 user_version 保持原有版本。
- 富途窗口构造、券商切换、下载区隐藏和结果标签页检查通过，并检查合成截图；界面及 Excel 的四维状态使用统一中文名称。Visual Studio 交互式设计器未在本轮操作。

在仓库根目录运行：

```powershell
./tests/Verify-Architecture.ps1
dotnet build CRS.sln -c Release -m:1
dotnet run --project tests/CRS.Tests.Verification -c Release
```

真实资料只在本地验收，不提交样本和参考金额文件。Python 版本已移除；若已保留迁移前的本地参考金额文件，可用 C# 验证入口继续对照：

```powershell
dotnet run --project tests/CRS.Tests.Verification -c Release -- --futu-samples samples/FUTU storage/futu-reference.json
```

该可选命令需要本地五个年度对应样本和自行保存到 storage/futu-reference.json 的迁移前参考事实，仓库不提供该文件；它是迁移验收工具，不是桌面程序的运行依赖。中文 PDF 合成测试使用 Windows 字体目录的 STFANGSO.TTF；字体不复制进仓库。

PDF 组件接口参考 [PdfPig 官方说明](https://github.com/UglyToad/PdfPig)；数据库访问参考 [Dapper 官方说明](https://github.com/DapperLib/Dapper)。依赖固定为 PdfPig 0.1.16 和 Dapper 2.1.89，并记录在 packages.lock.json。

# CRS 数据安全与用户体系设计规范

> **文档状态：设计基线及完整验收目标。** 独立 Security、主密码、SQLCipher、加密备份、离线 TOTP 与锁定已进入源码；公开版加密导出与全部发布验收尚未完成。当前实现和证据边界见 [AUTH_IMPLEMENTATION.md](AUTH_IMPLEMENTATION.md)，运行事实以 [PRIVACY.md](PRIVACY.md) 与源码为准。
>
> 版本：1.3（设计基线：五项目分层 + 拒绝明文库 + 离线 TOTP）｜修订日期：2026-10-10｜适用：.NET 10 / WPF / SQLite + Dapper 的 CRS 项目。

## 1. 设计决策与边界

CRS 的正式产品名称为“境外证券投资所得税辅助计算工具”，当前由开发者自用，可能在公司管理的 Windows 电脑运行；后续拟向其他投资者发布独立桌面软件。优先采用 **Local-first（本地优先）+ Encrypted Vault（加密保险库）**：本地完成导入、FIFO、税额计算、核对与导出；不要求登录互联网账号。安全能力按阶段推出，不把未来云端功能提前做进税务引擎。

**决策：**

1. **本地解锁 ≠ 在线登录。** 首次设置主密码保护本地数据库，Windows 当前用户保管受保护本机密钥；日常仅验证完全离线的 RFC6238 TOTP 后进入业务。换电脑／本机凭证失效时保留主密码和独立恢复路径。TOTP 详见 [SECURITY_AUTH_SPEC.md](SECURITY_AUTH_SPEC.md)。
2. **加密数据 ≠ 应用界面上锁。** 数据库静态加密是基础；解锁界面只是访问入口，不能代替数据库加密。
3. **不绑定公司 Windows 账号。** 不把 Windows SID、机器标识或 DPAPI 当作唯一解密/恢复条件，确保更换电脑可恢复。
4. **不改动既有计算口径。** Domain 的 FIFO、税额、证券身份、来源证据和冻结复算规则不依赖 UI、数据库加密实现或在线身份认证。
5. **不支持明文 SQLite 数据库迁移。** 检测到旧明文 `crs.db` 立即拒绝访问，不提供自动或人工的旧库转密流程；仅允许用户在新的空位置创建加密保险库。
6. **安全核心独立为第五个生产项目。** 新增 `CRS.Security` 只实现密码学与密钥机制；`CRS.Infrastructure` 负责 SQLCipher、文件、备份和保险库会话适配；`CRS.Application` 仍仅依赖 Domain，不能反向依赖安全实现。
7. **现状和目标必须分开。** 未实现的第五项目、加密、备份、导出选项不能写成现有功能或已通过测试。

> **受管设备风险：** 企业管理员、终端检测/远程管理、截屏、输入监测、进程内存采集及企业备份可能接触程序运行时的数据。保险库加密主要抵御静态文件泄露；它**无法承诺**阻挡拥有充分权限的公司终端管理系统。优先在个人电脑处理真实财务数据，公司电脑优先使用脱敏样本，且须遵守企业软件与数据使用政策。

## 4. 本地保险库及密码体系

### 4.1 核心对象

- **VaultId**：随机且稳定的保险库标识，仅识别独立数据集，不绑定姓名、邮箱、Windows SID 或硬件号。
- **DEK**：使用密码学安全随机数生成的 256 位数据库密钥，供 SQLCipher 开库；不由用户口令直接充当数据库密钥。
- **KEK**：由主密码通过 Argon2id + 每保险库随机 Salt 派生，仅用于封装 DEK。
- **Key Envelope / Key Slot**：保存版本、KDF 算法与参数、Salt、Nonce、认证加密后的 DEK、认证标签等**非明文密钥材料**；不得保存主密码或裸 DEK。
- **Recovery Key**：独立随机生成的高熵恢复秘密（建议 256 位，适于离线保存），用独立封装槽保护同一 DEK；用户须在离开创建向导前确认保存。

采用经过审查的密码库及 `.NET` `AesGcm` 对 DEK 做 AES-256-GCM 认证加密。Argon2id 的具体内存、迭代和并行参数在目标电脑上实测并记录版本；不得在未经性能测试的情况下把某个固定值写成已验证基线。Nonce 对每个封装操作唯一，密钥封装元数据应被认证保护；解锁失败统一报告，不暴露密码、密钥或认证细节。

可参考 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) 和 [OWASP Cryptographic Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)，但实际依赖、参数、格式需要实现前单独评审。

### 4.2 初始化、解锁与锁定

**首次启动（目标行为）：** 创建或恢复保险库 → 设置主密码 → 创建 DEK/Key Envelope/Recovery Slot → 初始化加密库 → 验证可以重新解锁 → 提醒用户离线保存恢复密钥。创建失败不得遗留看似成功的空保险库。

**每次启动：** 检查目标库及格式；有效加密保险库由本机 DPAPI 槽准备受限认证，验证 TOTP 并原子消费时间步后进入工作区。首次／本机凭证失效时使用主密码及恢复流程；不得把本机槽解封当作已通过手机验证。发现明文头即拒绝读取及迁移业务；库损坏、错误凭证或未知格式不回退明文、不自动覆盖或新建。

**重新创建：** 文件不存在，或者用户在收到“不支持旧明文库”提示后明确选择“创建新的加密保险库”时，才进入初始化向导；必须指定不存在的文件／空目录作为目标。如果默认目录已有旧 `crs.db`，要求用户另选新位置或自行在应用外妥善处置旧文件；应用不得自动重命名、删除或覆盖它。新保险库不会继承旧库中的历史任务、快照和复核结果，必要数据需要重新从券商原始报表导入。

**会话管理：** 默认 10 分钟无操作锁定；Windows 会话锁屏/休眠后需要重新解锁；锁定时终止/取消未结束的导入、复算或导出操作，关闭数据库连接、释放密钥引用、隐藏工作区的敏感内容。受托管运行时限制，不承诺密钥在进程内存中被绝对彻底清除。

错误口令的用户体验可以采用适度延迟，但不能把该措施当作防离线猜测的核心机制；离线防护主要依靠强口令、Argon2id 与高熵 DEK/恢复密钥。

### 4.3 修改密码与遗忘密码

- **修改密码**：先用旧密码/有效恢复密钥证明拥有访问权，再派生新的 KEK、重新封装同一个 DEK；不要求全库重写。更新封装槽应原子完成，失败可回滚。
- **遗忘密码**：只有持有有效恢复密钥时允许重新设置主密码；不提供默认管理员密码、万能密码或服务器后门。
- **全部凭证丢失**：主密码与恢复密钥丢失后无法按便携方案换电脑；本机槽也不可解封时无法恢复。仍有效的本机槽及手机只能维持本机访问，不能重设未知密码。
- **DPAPI 本机槽**：日常无需重复输入主密码，由 Windows CurrentUser 保护 DEK，手机 TOTP 仍为必需。本机槽不纳入便携备份，不替代主密码／独立恢复槽，也不能抵御拥有同用户环境权限的恶意进程；Windows Hello 暂未接入。

## 5. 数据库集成、明文库拒绝策略与新建

### 5.1 新增独立 CRS.Security，不改变现有业务规则

**当前代码现状：** 五个生产项目，独立 Security 提供密码学和 TOTP；Infrastructure 使用 SQLCipher + Dapper、受限认证和原子防重放。下列目标表仍包括尚未完成的公开发布能力。

**目标项目及责任：**

| 项目 | 负责内容 | 依赖边界 |
| --- | --- | --- |
| `CRS.Domain` | 交易事实、FIFO、税额规则与证据语义 | 不引用任何安全或基础设施项目 |
| `CRS.Application` | 保险库创建/解锁/锁定、备份恢复的业务用例与端口；访问门槛、会话状态检查 | **只引用 Domain**，不持有 DEK，不调用密码学算法 |
| `CRS.Security`（新增） | Argon2id、随机 DEK/恢复密钥、AES-256-GCM 密钥封装/验证、密钥材料及格式的纯机制 | 可复用 `net10.0` 类库；不引用 Domain、Application、Infrastructure、WPF、Dapper、SQLCipher，不做文件 I/O |
| `CRS.Infrastructure` | 实现 Application 端口；通过 Security 核心管理会话、驱动 SQLCipher、检查数据库文件格式、执行加密备份/恢复的持久化 | 引用 Application、Domain 和 Security；密钥使用限定在受控会话内 |
| `CRS.Desktop.Wpf` | 创建/解锁/锁定/恢复 UI 和启动装配 | Views/ViewModels/Controls 仅调用 Application，用例以外不得直接使用加密或持久化实现 |

**模块划分：**

- `CRS.Security/Cryptography`：KDF、Key Wrapping、CSPRNG、认证加密与参数版本化。
- `CRS.Security/Authentication`：离线 TOTP、`otpauth` URI 及恢复码的纯机制；不得访问数据库或文件。
- `CRS.Security/Vault`：Key Envelope / Slot 的纯数据结构与密码学校验；不认识 `crs.db` 路径。
- `CRS.Security/Recovery`：恢复凭证的生成与封装验证；不操作备份磁盘文件。
- `CRS.Infrastructure/Security`：Application 安全端口适配、保险库会话生命周期、密钥封装元数据持久化协调；增加受限 MFA 认证连接、防重放步骤原子事务与恢复审计。
- `CRS.Infrastructure/Persistence`：SQLCipher Provider、加密库打开、明文旧库检测并拒绝、数据库完整性及 schema 操作。
- `CRS.Infrastructure/Backup`：版本化 `.crsbak` 文件、一致性快照与恢复；密码学操作通过 Security 提供的安全机制完成。

**目标引用：** `Application → Domain`；`Infrastructure → Application + Domain + Security`；`WPF Composition → Application + Infrastructure`。`Security` 不反向引用其他 CRS 项目；WPF 页面不能直接访问 Security 及 Infrastructure。Composition 负责装配，不能借 DI 让页面绕过应用门槛。

新增 `CRS.Tests.Security` 专测密码派生、密钥封装、恢复密钥、失败条件及版本兼容；`CRS.Tests.Infrastructure` 专测 SQLCipher、磁盘格式识别和备份 I/O。`Verify-Architecture.ps1` 需新增项目引用、程序集及命名空间边界检查。

保留 **SQLite + Dapper** 访问模型，不因为加密改用 EF Core，也不引入云端计算服务或在线账号。详见 [SAD.md](SAD.md) 与 [PROJECT_STRUCTURE.md](PROJECT_STRUCTURE.md)。

SQLCipher 的 NuGet 构建、原生运行库、加密参数、兼容性、许可证及供应链应做独立验证；`Microsoft.Data.Sqlite.Core` 与支持 SQLCipher 的底层提供器需要一致配置。不得将标准 SQLite Provider 误认为天然具有加密能力。微软的 [SQLite 加密指南](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/encryption) 示例采用 `Microsoft.Data.Sqlite.Core` 加 `SQLitePCLRaw.bundle_e_sqlcipher`；该 bundle 为**非官方、无官方支持的 SQLCipher 构建**，不能因示例存在就直接认定满足正式发布维护要求。

SQLCipher Community Edition 允许按其 BSD 风格许可用于闭源商业软件，但公开发行必须向用户提供对应版权、许可证全文及依赖 NOTICE；商业/官方版本的授权模式另行评估，详见 [Zetetic 许可说明](https://www.zetetic.net/sqlcipher/license/) 与 [Community Edition 说明](https://www.zetetic.net/sqlcipher/community/)。项目的许可证检查必须覆盖最终打包的**具体原生库和转递依赖版本**。

### 5.2 不支持旧明文数据库；仅允许重新创建

**明确决策：不实现明文 SQLite → SQLCipher 的任何迁移工具、转换模式或历史数据导入通道。** 现有 `%LOCALAPPDATA%/CRS/data/crs.db` 为明文 SQLite，可能附带 `-wal`、`-shm` 及明文备份。新安全版本遇到这类数据库时必须直接拒绝打开；原有数据不自动转换、不继承、不覆盖、不删除。

**启动检测规则（待实现）：**

1. **文件不存在：** 展示“创建加密保险库”向导；必须经用户明确操作后才建立新库，不在异常处理分支悄悄创建。
2. **文件存在且为明文 SQLite：** 可用文件头 `SQLite format 3\0` 作为识别信号之一；提示“检测到未加密的旧数据库，本版本不支持。请选择新的空目录创建加密保险库”。不打开明文 SQLite 连接，不尝试转密，不扫描业务表。
3. **文件存在且为受支持的加密保险库：** 完成元数据校验、主密码验证、SQLCipher 打开及完整性验证，再进入工作区。
4. **文件存在但格式未知、口令错误、数据损坏或版本不支持：** 明确报错并停止；不能因为无法读取文件头就推断它一定是加密库，也不能以失败作为重建覆盖条件。
5. **重新创建：** 仅写入新文件或新的空目录；如果目标路径已有任何数据库，拒绝同路径创建。提示用户自行管理旧明文库及其 WAL/SHM、历史备份、同步副本等潜在泄露物；应用不负责自动清理，也不承诺文件删除可彻底抹除历史副本。

**数据连续性取舍：** 旧明文库中的历史任务、人工复核、冻结快照和抵免关联**不会被迁入**新保险库；需要使用富途/IBKR 原始文件重新导入、计算和核对。重新导入不能保证自动恢复全部旧历史状态，应在界面中明示这一限制。现有历史重放和旧结转 JSON 的业务兼容问题属于独立事项，不意味着支持旧明文数据库。

**未来的升级**只处理已经加密且明确支持的保险库版本；区分数据库 schema 版本与保险库/密钥封装版本。加密库结构升级仍需安全备份和失败回滚，但不包含明文库迁移。

### 5.3 SQLite 特别要求

- 核验数据库已通过 SQLCipher 成功加密，普通 SQLite 工具无法读取业务记录。
- 包括 WAL、journal、临时表、查询中间结果、数据库导出/备份在内的写入路径，需验证不会意外产生明文副本。
- 不得在日志或异常对象中输出 SQLCipher 密钥、含密钥连接字符串或完整用户数据。
- 导入及计算时的会话对象不得从锁定状态继续执行后台提交。

## 6. 导入、导出、备份与日志

### 6.1 数据导入（沿用原有业务规则）

IBKR Activity Flex XML、富途 XLSX/受支持文本 PDF、期初 LOT/结转等输入范围不变；继续进行文件大小、字段、期间、账户和事实完整性验证。导入不等于匿名化：避免将原件复制到无保护缓存或日志。用户原始文件本身仍是用户需要独立管理的敏感明文资料。

当前 IBKR Flex Token 只在窗口会话保留，不能为了实现保险库而擅自改为自动持久化。下载到用户指定位置的 XML 仍可能是明文，界面应明确提示。

### 6.2 导出（分阶段实施）

- **V1.0 自用加固目标：** 保持当前 Excel/结转业务导出能力；增加明显的**明文导出风险提示**，导出取消/失败不留下半成品文件（既有 AR-11）。
- **V1.5 公开发布门槛：** 提供独立的加密导出（例如经验证的 AES-256 ZIP 容器，内含 Excel/CSV/PDF），用户设置与保险库主密码不同的导出密码；保留经用户明确选择的明文导出。
- 不能把普通 ZIP 密码保护视为必然等于 AES-256；选型需验证加密算法、认证/防篡改属性、跨平台兼容性及文件名元数据是否暴露。
- PDF/Excel 原生文件密码加密作为可选能力单独选型，不假定当前 NPOI/其他导出库已实现。

### 6.3 加密备份（V1.0 必做）

设计版本化 `.crsbak` 容器，携带加密数据库**一致性快照**、必要密钥封装元数据、格式版本、校验信息与恢复说明。备份默认加密；导出前后校验完整性，不能直接复制正在写入的数据库文件充当完整备份。使用主密码或恢复密钥恢复到另一台电脑，**不依赖**原 Windows 账户或 DPAPI。

不得仅凭扩展名宣称备份安全。避免备份过程中以明文数据库作为普通临时文件，允许用户验证离线恢复；覆盖式恢复前要备份现有目标，且必须经过确认。

### 6.4 日志/隐私

继续遵守现有 NLog 脱敏与 Flex Token 不落盘规则；新增的异常处理不得记录口令、Salt 派生的秘密、裸 DEK、密钥封装输入、完整券商账户、交易文件正文、原始抵免凭证等。路径和文件名也可能包含个人信息，需要按最小必要原则处理。禁用日志不代表历史日志已经删除。

## 7. UI 与未来用户体系

WPF 原有九个业务页面不变，增加启动层（创建保险库、解锁、恢复、旧明文库不支持提示）及设置中的安全入口；锁定时不允许绕过启动层进入历史与报表。

| 功能 | V1.0 | V1.5 | V2.0 以后 |
| --- | --- | --- | --- |
| 本地保险库（首次主密码，本机日常 TOTP） | 必须 | 必须 | 保留 |
| 自动锁定、改密、恢复 | 必须 | 必须 | 保留 |
| 加密数据库/备份 | 必须 | 必须 | 保留 |
| 多保险库/本机多个使用者 | 可不做 | 必须独立隔离 | 保留 |
| 加密报表导出 | 风险提示，待实现 | 必须有可选加密模式 | 保留 |
| 注册/邮箱登录/云同步 | 不做 | 不做 | 按需求独立设计 |
| 订阅授权 | 不做 | 可另立方案 | 按商业模式 |

在线身份认证未来只负责网络服务的授权与访问，不能把在线账号密码等同于本地库的 DEK 或恢复密钥。若未来规划“服务器不可读取明文”的端到端加密同步，需独立评审密钥同步、设备撤销、冲突解决、恢复及威胁边界；本文件不宣称已经具备该能力。

## 9. 实施顺序与变更控制

1. **先验证选型与新分层：** SQLCipher Provider/发行许可证、Argon2id 依赖、备份格式、明文旧库识别拒绝样本、内存和性能基准。
2. **新建 `CRS.Security` 与 `CRS.Tests.Security`：** 实现纯密码学的 Key Envelope、创建/解封/改密/恢复，更新集中包管理、项目引用与架构检查；此时不得直接访问业务数据库。
3. **接入 Application 和 Infrastructure：** Application 声明/编排安全端口；Infrastructure 的 Security 适配器调用新类库，Persistence 使用 SQLCipher，会话与本机设置联动。
4. **落实明文库不兼容门槛：** 检测明文旧库即拒绝访问；只在用户明确选择的新空路径创建加密库，不修改原文件。
5. **完成备份、导出和发布核验：** 加密备份恢复、明文导出提示、公开版可选加密导出、依赖许可证及分层回归测试。
6. **最后按需评估在线账号：** 只有确有同步/网络服务需求时才单独设计身份服务。

安全改造不得更改 `FIFO_TOTAL_COST_V3`、`CRS.CanonicalInput.v2` 的业务语义，也不得以当前加密架构重写冻结历史事实。测试、发布与剩余问题分别参考 [TEST_SPEC.md](TEST_SPEC.md)、[RELEASE_ACCEPTANCE.md](RELEASE_ACCEPTANCE.md)、[KNOWN_ISSUES.md](KNOWN_ISSUES.md)。

## 10. 离线 TOTP 认证专项（P0，规划/待验收）

**规范入口：** [SECURITY_AUTH_SPEC.md](SECURITY_AUTH_SPEC.md)。在 V1.0 正常使用路径中，主密码只解封装 DEK；TOTP 验证成功且在 SQLCipher 内原子消费时间窗口后，才建立 `Authenticated` 业务会话。受限认证连接在 MFA 完成前不得暴露给业务工作流或视图。TOTP 的安全边界仅为应用会话门槛，不应宣称拥有主密码者在外部无法解密数据库。

- 首次创建：必须扫码并成功确认首码；中途中断仅可继续绑定/恢复，不可进入业务。
- 正常登录：首次主密码保护数据库，日常在已启用 Windows 用户环境中仅输入 Authenticator 六位 TOTP；仍沿用 **10 分钟无活动锁定**，主密码用于显式维护／跨机恢复。
- 密钥：TOTP Secret 与高熵恢复码属于独立安全数据；不得将六位 TOTP 用作 DEK/KEK；不依赖 Microsoft/Entra 网络服务。
- 手机丢失：主密码 + 已保存的一次性高熵 MFA 恢复码进入 `RecoveryOnly`，强制重新绑定；忘记密码由独立 256 位数据库恢复密钥走紧急恢复。
- 本地局限：本机管理员/恶意软件、主密码泄露者绕过 UI、Windows 时间或数据库快照回退不能由离线 TOTP 根治。
- 版本与兼容：继续 **拒绝所有明文 SQLite 数据库，不迁移、不读取、不删除、不覆盖**；仅支持已加密保险库的明确版本升级。
- **新增发布验收编号 AUTH-01～AUTH-18：** 与上面 SEC-T01～SEC-T14 并行，按 [SECURITY_AUTH_SPEC.md](SECURITY_AUTH_SPEC.md) 第 8 节验证；其中架构约束、原子防重放、跨机恢复、后台会话失效、故障关闭均为阻断项。

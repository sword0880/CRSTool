# 报税 Excel 与 PDF 文件打开密码

在“设置 → 文档加密”保存文档密码后，到“报表导出”选择“导出加密 Excel”或“导出加密 PDF 摘要”。生成的 `.xlsx`／`.pdf` 文件本身加密，发给他人后，在 Excel 或支持 PDF 2.0 AES-256 的阅读器中打开也需要该密码。

Excel 包含完整税务底稿；PDF 为冻结的税务摘要、状态、警告及人工复核说明，完整 FIFO、来源、汇率和抵免凭证仍需结合 Excel。未知预计补税显示“不可确定”，不会用原始公式填补；状态允许的真实零值仍为零。

应用密码要求至少12个字符。文件格式另有限制：Excel最多255个字符；PDF最多127个UTF-8字节（中文通常每字3字节），超过限制会明确拒绝，不截断。更改设置只影响之后生成的文件，旧文件继续使用原密码。文件密码遗失无法由数据库恢复密钥找回。

格式写入及打开密码统一由 `CRS.Documents.Excel.ExcelWriter.WritePasswordProtected` 和 `CRS.Documents.Pdf.PdfTextWriter.WritePasswordProtected` 处理。报税基础设施仅组装内容并协调原子文件保存；会话锁定、取消、目的地校验、汇率指纹和审计沿用应用服务。生成期间不保存明文文档，失败或取消不替换原目标文件。

现有 `.crsexport` 归档保留；其解密恢复会输出普通文件，与本功能直接在文档阅读器中输入打开密码的方式不同。

验证入口：Infrastructure 的 `--password-documents-only`；Application 默认回归；WPF 默认回归。均使用合成报税结果，不读取正式账户资料。

防替换：构建时将 `CRS.Documents.dll` 的 SHA-256 编译进主程序；启动时先校验再加载，缺失、改动、抢先加载或链接路径均停止启动。Windows 下保留禁止写入和删除的只读句柄至进程退出，正常升级需先关闭程序。指纹不是可随 DLL 一起替换的旁置清单。现有插件公共依赖核验继续有效。

原生文件在内存生成后，公共文档层用读取路径再次确认空密码不能打开、指定密码可还原，再把密文交给调用方保存；异常不会回退成明文文件。专项另外使用合成明文确认检查会拒绝；WPF 的 `--document-trust-checks` 用独立进程验证真实指纹、修改／缺失／预加载拒绝，以及运行期间覆盖和改名失败。

保护依赖未被改写的主程序与可信构建。若攻击者同时修改主程序校验逻辑或控制进程内存，单机软件无法保证阻止；本次没有启用混淆器，也没有新增发布者签名。发布防逆向方案见 [发布保护边界](RELEASE_PROTECTION.md)。

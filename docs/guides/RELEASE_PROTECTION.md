# 发布保护边界

C#／.NET 桌面程序无法保证不可反编译。发布保护应提高阅读和修改成本，并验证软件来源与完整性；文件加密密码由用户设置，不应硬编码成可从程序中提取的万能秘密。

本次已实现：主程序内嵌文档组件构建指纹、启动前校验、只读句柄固定组件，以及密文输出复核。它防止在主程序保持可信时单独替换 `CRS.Documents.dll` 来取消文档加密，不代表主程序本身不可被补丁修改。

后续发布可加入：

1. 使用维护中的 .NET 混淆工具保护业务逻辑、控制流和内部名称。WPF 绑定、反射、JSON 合同、插件公开接口与序列化成员须明确保留并回归，避免混淆后功能损坏。不要把 Release、单文件、自包含或删去 PDB 当成混淆。
2. 对正式主程序、程序集与安装包使用真实发布者证书签名，并在发布中验证签名。签名提供发布者和完整性证据；自动阻止非可信版本还需部署权限或系统执行策略，不能仅凭存在签名作保证。
3. 文档组件如经过混淆或签名，必须在这些处理完成后更新主程序内嵌的最终文件指纹，再完成主程序签名和整包验证。对 DLL 的任何后处理都会改变本次使用的完整文件 SHA-256。
4. 安装到普通用户不可写的位置；默认以普通用户运行。许可如需要抵御本机补丁，应由受控服务判定关键授权，不把唯一信任依据交给本地可修改代码。本项目的离线报税资料不因此上传。

当前未接入混淆器，未新增代码签名证书或签名流程；不能宣称“已防反编译”或“已签名发布”。

参考：[Microsoft：.NET 应用混淆](https://learn.microsoft.com/visualstudio/ide/dotfuscator/)、[Microsoft：Authenticode 发布者与完整性验证](https://learn.microsoft.com/windows-hardware/drivers/install/authenticode)。

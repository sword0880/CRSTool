# 有凭证的账户活动期间

2026-10-13。解决反方审查 P0-2 的表达与核对缺口；不改变税额公式，也不以开户日期推断真实零成本或真实收入。

## 使用

在“数据导入”展开“年中开户／关闭账户”，选择账户期间 JSON 清单。参照 [清单示例](../examples/account-periods.example.json) 填写实际账户号、开户日期、可选关闭日期及凭证路径。日期格式为 `yyyy-MM-dd`；字段区分大小写，全部示例字段必须保留。`ProofPath` 可以相对于清单所在文件夹；原件按只读、有界方式读取，不修改原件。

只有人工核对原件后才能把 `Reviewed` 改为 `true`。`OpeningZeroConfirmed` 仅表示明确核对了开户时无持仓；不能因为报告从年中开始就勾选。示例默认未核对，不能直接用于计算。当前入口为 JSON 清单，尚未提供逐项填写的图形编辑器。

库中和完整快照保存规范化开户／关闭事实、已核对声明、凭证文件名及 SHA256，不复制凭证正文和本地路径。摘要只证明本次读取内容的身份，不证明原件真实性；原始凭证应自行保留。重新计算会重新读取凭证，历史完整快照重放使用冻结声明，不重新要求凭证文件。

## 核对门槛

- 未提供声明的账户继续检查 1 月 1 日至 12 月 31 日。
- 有效声明的目标期间为自然年与账户生命周期的交集；成交和现金仍必须连续覆盖，期末持仓使用活动期截止日核对。
- 只对本年度新开户且确认开户零持仓的账户解除期初确认缺口。旧账户仍需要期初 LOT、结转或明确期初确认。
- 未核对、未知账户、重复账户、非法日期／摘要以及生命周期外的交易、现金、成本或矛盾持仓明确拒绝。其他成本、对账、汇率、范围与抵免问题继续保留。
- 已关闭账户的任务不生成下一年结转；混合任务含关闭账户时采用保守门槛，整体结转关闭。

结果和 Excel 增加“账户期间依据”“期间覆盖状态”。类型区分“完整自然年”“账户活动期”“临时报告”；期间完整只表示成交和现金的日期覆盖，不代表全部对账、税额人工签认通过或允许申报。年度汇总保留父任务关系，单个账户的期间凭证在父任务查看，不把不同券商的同号账户合并为同一声明。

## 快照与验证

带期间依据的完整快照使用 `CRS.CanonicalInput.v3`，引用型使用 `CRS.InputReferences.v2`。没有期间依据时保留完整 v2／引用 v1，不向旧契约添加字段。声明必须与冻结结果一致；完整重放再执行同一期间与矛盾校验，并比较期间声明及覆盖输出。

自动场景覆盖无依据保守处理、有依据活动期、缺一天、关闭账户、未核对／重复／错误归属／矛盾／非法摘要、冻结重放，以及凭证摘要、原件不变、必填／未知／重复字段、取消和界面选择隔离。真实 IBKR 2025 开户凭证尚未人工提供、核对，不能用文件名或程序输出倒填真实验收。

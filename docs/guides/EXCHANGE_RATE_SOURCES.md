# 年度测算汇率来源与存储

桌面端「汇率管理」从后台 Worker 读取所选年度的汇率；开始年度核算时也会自动读取。「更新官方汇率」由 Worker 重新查询官方来源并写入数据库。美元、港元取自国家外汇管理局公开的中国外汇交易中心人民币汇率中间价，按每单位外币兑人民币换算。人民币折算系数固定为 1。[国家外汇管理局人民币汇率中间价](https://www.safe.gov.cn/safe/rmbhlzjj/)

## 计算口径

- 任务中心的「年度人民币汇率中间价更新」默认使用 Cron `0 0 9 1 1 ?`，在北京时间每年 1 月 1 日 09:00 更新上一年度。服务错过触发时会检查并补跑；年初未取得末日报价时会复查。
- 已结束年度使用 12 月 31 日的中间价。当天没有报价时，取该年最后一个有报价日的中间价，并标记为临时测算。界面与汇率底稿显示实际日期。[境外所得有关个人所得税政策公告](https://www.chinatax.gov.cn/chinatax/n810219/n810744/n3752930/n3752974/c5143076/content.html)
- 当年采用年初至今各报价日中间价的算术平均，四舍五入保留六位小数，并标记为临时测算。非报价日跳过。
- 官方来源暂时不可用时，优先使用同年度已入库的官方快照；没有官方快照时，才使用当前 Windows 用户迁入的旧本地快照；最后才使用旧年度手工汇率记录。来源不确定的旧资料保留未确认标记。

## 数据库与唯一事实源

正式存储统一由 Worker 服务持有，使用现有 SQLCipher 数据库：

`%ProgramData%\CRS\Background\scheduler-config.db`

汇率资料不再由桌面端持续读写 JSON，也不另建明文数据库。桌面端通过 Worker IPC 查询、刷新和导入；后台任务、前台税务测算使用同一数据源。

Schema 从 v2 升级到 v3：
- `exchange_rate_snapshot`：年度、来源类型、Windows SID（仅旧桌面缓存）、统计期间和抓取时间。
- `exchange_rate_quote`：逐报价日 USD/HKD 中间价。汇率以十进制文本保存，避免 SQLite REAL 浮点转换。
- `legacy_annual_exchange_rate`：旧年度手工汇率及来源、期间、计算方法、临时标记、首次观察日、样本数和累计值。
- `exchange_rate_migration`：一次性迁移版本、源文件 SHA-256 和导入数量。

已有 v1/v2 数据库在迁移前先创建加密快照备份；备份数量达到安全上限时停止迁移，不自动覆盖或清理历史备份。

## JSON 迁移边界

JSON 只作为一次性迁移输入，不再作为运行时事实源：

1. 旧版 `exchange_rate.json` 与 `exchange_rate_sources.json` 已合并为 Worker 程序内嵌的迁移种子。首次启动时写入 `legacy_annual_exchange_rate`，按原值导入 2021–2026 年 USD/HKD/CNY 及 2026 年来源元数据。迁移种子不是运行时配置。
2. Worker 旧目录 `exchange-rates/safe-midpoint-v1-YYYY.json` 只有在文件 HMAC、年度和快照结构校验通过后才导入 Official 数据；不通过的文件隔离保留，不参与计算。
3. 桌面旧缓存 `%LOCALAPPDATA%\CRS\exchange-rates\safe-midpoint-v1-YYYY.json` 逐年度导入当前 Windows SID 对应的 DesktopLegacy 数据。收到 Worker 数据库写入确认后，源文件才改名为 `.json.migrated`；导入失败时保留原文件，下一次可重试。
4. DesktopLegacy 快照按 Windows SID 隔离，不能被其他用户读取，也不能覆盖 Official 快照。对已结束年度，若迁入旧桌面快照，则优先沿用该用户原有快照并冻结数值，不因后续官方刷新而改变；当年快照仅在官方数据不可用时回退。旧快照保留旧程序原有的官方来源、确认状态和临时标记；数据库单独记录 DesktopLegacy 来源类型，防止其覆盖 Official 快照。
5. 旧桌面 JSON 配置文件及文件读取 Provider 已移除。此后新数据只写 SQLCipher；旧 Worker JSON 文件仅保留作迁移回滚证据，不再写入。

## 历史汇率不变规则

- 历史年度手工汇率按原始数值迁移：2021 USD 6.4515 / HKD 0.8291；2022 6.7261 / 0.8606；2023 7.0809 / 0.9056；2024 7.2200 / 0.9260；2025 7.1800 / 0.9210；2026 6.852873 / 0.875157。CNY 始终为 1。
- 已保存的历史测算结果、汇率底稿、汇率指纹和证据链不执行重算、不批量更新、不回写。
- 每个来源、年度、报价日采用首次写入原则：相同日期后续下载即使返回不同值也不覆盖已入库值；新报价日只追加。Official 与 DesktopLegacy 分开保存，旧缓存不能覆盖官方快照；对已结束年度，已迁入的 DesktopLegacy 快照作为该 Windows 用户的冻结历史版本。
- 旧年度汇率种子重复启动时，必须同时核对迁移回执 SHA-256、导入行数及每条记录的数值、来源、期间、临时标记和来源元数据；首次导入若遇到同主键记录，也只有完全一致才允许通过。任何冲突均回滚当前迁移并停止，不归档旧源文件。
- 导入操作幂等；重复启动不会重复增加旧年度记录。数据库迁移失败时，原数据库备份和旧 JSON 源文件均保留。

## 验收要求

- 从 v2 数据库升级时先产生 schema2 加密备份，升级后 `PRAGMA user_version=3`，原任务与执行历史行数、内容不变。
- 首次启动导入旧年度种子后，再次启动不重复导入；逐项比对 2021–2026 汇率值和 2026 来源元数据。
- 旧 Worker JSON 的 HMAC 正确才导入；篡改文件不进入 Official 表。
- 桌面旧缓存导入后按当前 Windows SID 可读，换 SID 不可见；导入成功才归档源文件。
- 对同一年度同一报价日再次写入不同 USD/HKD 值，数据库中的首次值保持不变。
- Worker 重启后仍可读取同一快照；无 Worker 数据时明确提示，不回退读取已删除的桌面配置 JSON。

### 验收工具汇率入口

- 真实 FUTU/IBKR 样本验收及 `--analyze` 入口通过 Worker IPC 读取 SQLCipher 汇率；不再接受 `exchange_rate.json` / `exchange_rate_sources.json` 目录。
- 旧验收清单中的 `ConfigDirectory` 字段仅为旧清单反序列化兼容保留，不读取该目录。自动化离线场景使用测试项目内的合成 Provider，与生产数据库隔离。
